# Создание наборов правил Game Mode

Набор правил объясняет Game Mode настольную систему: какие кости бросает проверка, что есть в листе персонажа, какие ресурсы тратятся и что возвращает отдых. Руководство предназначено тем, кто хочет написать собственный набор и поделиться им. Для игры с чужим набором начните с [Выбора правил](../game/getting-started.md#choosing-rules).

Набор правил – один JSON-файл. Это данные, не код. Ничего из него не выполняется, поэтому импорт не может ничего сделать с компьютером. Перед импортом чужого файла внимательно прочитайте текст Game Master: он передается модели в каждой игре с этим набором.

## Прочтите сначала: что набор правил может и чего не может

Набор может лишь заполнять параметры механики, уже известной Engine. Сейчас Engine знает два способа разрешения проверки; файл выбирает один через `resolution.kind`:

- **`dice-sum`**: бросить кости, прибавить числа листа и достигнуть либо превысить сложность. Подходит для d20, 2d6 плюс характеристика и многих других систем.
- **`dice-pool`**: бросить число костей персонажа и сосчитать достигшие цели. Подходит системам, где рейтинг означает горсть костей вместо бонуса.

Оба полностью описаны в разделе [Виды разрешения](#resolution-kinds).

Механику, не соответствующую ни одной форме, нельзя записать в файле набора. Примеры: выбор наибольшей кости пула, процентные проверки с броском ниже порога, символьные кости и встречные пулы. Каждому нужен новый вид разрешения внутри Engine, то есть изменение кода с тестами, а не JSON-файл. Если ваша система требует такого вида, откройте запрос функции в репозитории Engine и опишите механику несколькими полностью разобранными бросками. Они станут тестами.

Game Mode разрешает бой по собственным правилам Marinara или правилам вашего набора. Необязательный блок `battle` передает бою Marinara числа листов персонажей: см. [Сражения](#battles-lending-the-sheet-to-marinaras-combat). Необязательный `combat` вместо этого определяет разрешение боя самим набором: см. [Бой](#combat-a-fight-your-own-rules-resolve). Engine уже применяет эти правила. **Combat Preference** (предпочтительный вид боя) выбирает представление Classic или поле Tactical, если набор определяет расстояние.

## Быстрый старт

1. Скопируйте пример, подходящий броскам вашей системы. [`ember-roads.json`](https://github.com/Pasta-Devs/Marinara-Engine/blob/staging/docs/examples/rulesets/ember-roads.json) – небольшая система 2d6 с тремя характеристиками, показывающая, что формат не предполагает d20 или шесть характеристик. [`gravewatch.json`](https://github.com/Pasta-Devs/Marinara-Engine/blob/staging/docs/examples/rulesets/gravewatch.json) – небольшой пул десятигранных костей с тремя рейтингами и шестью профессиональными навыками. Полноразмерный пример 5e (SRD 5.1) находится в [`ruleset-5e-2014.example.json`](https://github.com/Pasta-Devs/Marinara-Engine/blob/staging/docs/development/ruleset-5e-2014.example.json).
2. Замените `id` своим. Идентификатор состоит из строчных букв, цифр и одиночных дефисов, например `ember-roads`.
3. Измените лист, отдых и текст Game Master.
4. Импортируйте файл (см. [Как опробовать набор правил](#trying-your-ruleset)). Импорт проверяет весь файл и построчно сообщает ошибки до любого сохранения.
5. Создайте игру, выберите набор в **Rules** (правила) и выполните несколько проверок.

Для подсказок при вводе укажите редактору JSON Schema, добавив следующую первую строку внутри внешних фигурных скобок файла:

```json
"$schema": "https://raw.githubusercontent.com/Pasta-Devs/Marinara-Engine/staging/docs/extending/ruleset.schema.json",
```

Схема при вводе находит ошибки в именах ключей и типах. Она не проверяет, ссылаются ли имена на существующие сущности, например называет ли навык существующую характеристику. Это делает импорт.

В любой объект файла можно добавить строку `"$comment": "..."` с заметкой. Engine ее игнорирует.

## Части файла

| Ключ | Содержимое |
| --- | --- |
| `schemaVersion` | Всегда `1`. |
| `id`, `version` | Имя набора для Engine и целое число, повышаемое при каждой публикации изменения. |
| `name` | То, что игроки видят в мастере настройки. |
| `edition` | Необязательно. Строка об издании или черновике. |
| `license` | Необязательно. Идентификатор SPDX и требуемый источником текст указания авторства. |
| `coverage` | Область действия набора и краткое описание в мастере настройки. |
| `resolution` | Как бросается проверка или спасбросок. |
| `sheet` | Все содержимое листа персонажа. |
| `rests` | Что восстанавливает и очищает каждый вид отдыха. |
| `gm` | Текст модели Game Master и значения листа, которые она видит для каждого персонажа. |
| `catalogs` | Необязательно. Готовые записи редактора листа вместо ручного ввода длинных списков. |
| `items` | Необязательно. Слова, которыми описаны ваши предметы: категории, редкости, параметры, слоты, деньги. |
| `battle` | Необязательно. Что бой читает из листа и записывает обратно после завершения. |
| `combat` | Необязательно. Разрешение боя по собственным правилам и то, что разыгрывает экран боя. |
| `layers` | Необязательно. Варианты набора, включаемые при создании игры. |

Размер файла – до 256 KB. Текст, попадающий в промпт (имена, подписи, текст Game Master), не может содержать переносов строк, квадратных или двойных фигурных скобок.

Идентификаторы листа (характеристики, навыки, поля, запасы и прочее) состоят из строчных букв, цифр и подчеркиваний, начиная с буквы, например `grit_max`.

### Виды разрешения

`resolution.kind` выбирает способ броска проверки. Оба вида читают один лист и имеют три общих ключа, поэтому части файла ниже `resolution` не меняются при переключении:

- `abilityModifier`: преобразование показателя листа в число. При `identity` показатель и есть число. `floorHalfMinusTen` – правило 5e. `stepTable` позволяет перечислить собственные пороги как `[[score, number], ...]`.
- `proficiencyTiers`: уровни подготовки навыка или спасброска. Неуказанный навык получает первый. Уровень добавляет `flat`, либо `multiplier`, умноженное на бонус мастерства, либо оба. Если в системе есть бонус мастерства, укажите его источник через `"proficiency": { "bonus": { "derived": "proficiency_bonus" } }`.
- `proficiency`: необязательно, нужно лишь уровню с умножением.

Значение полученного числа зависит от вида: `dice-sum` прибавляет его к броску, `dice-pool` бросает столько костей.

#### `dice-sum`: сложение костей

```json
"resolution": {
  "kind": "dice-sum",
  "dice": { "count": 2, "sides": 6 },
  "abilityModifier": { "op": "identity" },
  "proficiencyTiers": [
    { "id": "untrained", "label": "Untrained" },
    { "id": "trained", "label": "Trained", "flat": 1 }
  ],
  "advantage": false,
  "difficultyLadder": [
    { "label": "Easy", "dc": 6 },
    { "label": "Hard", "dc": 10 }
  ]
}
```

- `dice`: число костей и граней. Сумма сравнивается со сложностью.
- `advantage`: может ли Game Master попросить дважды бросить кости и оставить один бросок.
- `naturals`: влияние высшей и низшей грани одной кости на проверки и спасброски: `none`, `both`, `max-only` или `min-only`. Для чистой арифметики опустите. Требует одной кости, поэтому система 2d6 должна использовать `none`.
- `difficultyLadder`: сложности, из которых должен выбирать Game Master. `dc` – число, которого должна достичь сумма. Game Master может назвать ступень вместо ее числа, например `difficulty="Hard"`, и Engine возьмет число из ступени.

#### `dice-pool`: бросок костей и подсчет результатов

Число листа – **размер пула**, а не добавочный бонус. Рейтинг 3 и профессиональный навык стоимостью 2 дают пять костей. В этом вся идея: без нового словаря листа и нового редактора; система с рейтингами в виде горстей костей использует те же `abilities`, `skills` и `proficiencyTiers`, что и любая другая.

```json
"resolution": {
  "kind": "dice-pool",
  "die": { "sides": 10 },
  "abilityModifier": { "op": "identity" },
  "proficiencyTiers": [
    { "id": "rating_0", "label": "Untried" },
    { "id": "rating_1", "label": "Shown once", "flat": 1 }
  ],
  "pool": { "min": 1, "max": 15, "abilityPlusAbility": true },
  "target": { "default": 7, "min": 5, "max": 9 },
  "explode": { "from": 10, "min": 8 },
  "cancel": { "upTo": 1 },
  "botch": { "upTo": 1 },
  "exceptional": { "successes": 5 },
  "situationalDice": { "min": -3, "max": 3 },
  "reroll": [{ "id": "careful", "upTo": 6, "mode": "once" }],
  "difficultyLadder": [
    { "label": "Plain work", "successes": 1, "target": 6 },
    { "label": "Grim", "successes": 3, "target": 8 }
  ]
}
```

- `die`: число граней одной кости пула, от 2 до 100.
- `pool`: пределы числа листа до любых взрывов. `min` 0 позволяет пустому пулу провалиться вообще без броска; `max` – не более 100. `abilityPlusAbility: true` позволяет проверке характеристики назвать вторую характеристику через `with=` и бросить обе – для систем, где бросают два атрибута вместе; без него `with=` в проверке характеристики ничего не значит.
- `target`: грань, которой должна достичь кость для зачета. Задайте `min` ниже `max`, чтобы Game Master мог менять порог проверки через `threshold=`; равенство всех трех значений фиксирует порог.
- `double`: необязательно. Грань не ниже `from` считается дважды.
- `explode`: необязательно. Грань не ниже `from` бросает еще одну кость, которая тоже может взорваться. Дополнительных костей не больше `pool.max` сверх самого пула, поэтому проверка бросает максимум удвоенное `pool.max`, и низкое `from` не создает бесконечного броска.
- Оба правила могут иметь `min`: наименьшую грань, до которой проверка может опустить правило через `explode="N"` или `double="N"` в теге либо через использованную персонажем запись. С `min` можно опустить `from`, и тогда правило срабатывает только в проверке, которая его запрашивает: специализация, при которой десятки одного навыка бросаются снова, – это `"explode": { "min": 10 }`. `from` не может быть ниже `min`.
- `cancel`: необязательно. Грань не выше `upTo` отнимает один успех. Число не опускается ниже нуля.
- `botch`: необязательно. Если **ни одна** кость не успешна и выпала грань не выше `upTo`, проверка критически провалена. Пул с единственным отмененным успехом дает обычный, не критический провал. `"rule": "halfOrMore"` читает правило иначе: грани не выше `upTo` хотя бы на половине изначально брошенных костей (без учета взрывов) дают критический провал, если ни одна кость не успешна, а иначе оставляют результат в силе и помечают его `complication="true"`: одновременно с ним что-то идет не так. По умолчанию действует `"noSuccesses"`.
- `exceptional`: необязательно. Такое или большее число чистых успехов в успешной проверке дает критический успех.
- `situationalDice`: необязательно. Диапазон костей, добавляемых или убираемых Game Master для одной проверки через `bonus=` за трюки, раны или плохое освещение.
- `reroll`: необязательно. Перебросы, которые система дает бесплатно, до шести, каждый с `id`, который Game Master называет в проверке через `reroll=`. Грани не выше `upTo` бросаются снова: при `"once"` новая грань остается, какой бы ни была, а при `"until"` – пока не выпадет грань выше. `upTo` – от 1 до числа граней кости минус один, поскольку переброс всех граней никогда бы не закончился, а `until` в любом случае останавливается после сотни перебросов за проверку. Переброс не делается, если проверка его не называет. Одна проверка делает один переброс: если его купили также расход или использованная персонажем запись, бросается тот, что охватывает больше граней, а при равном охвате `until` побеждает `once`.
- `difficultyLadder`: `successes` задает необходимое число успехов. Ступень может назвать `target`, но только если порог регулируется и в его пределах. С этим порогом считается проверка на этой ступени: когда Game Master называет ступень через `difficulty=` или пишет `dc=`, нужное ровно одной ступени. Если нескольким ступеням нужно одинаковое число успехов, один `dc=` не скажет, какая имелась в виду, поэтому порог остается по умолчанию; назовите ступень.

Грани `cancel` и `botch` должны быть ниже минимального порога, а все грани этих правил должны существовать на кости. Невыполнимое правило отклоняется при импорте, а не обнаруживается в игре.

Набор с пулом в составе пакета требует Capability API 1.24; `min` у `explode` или `double`, `pool.abilityPlusAbility` и `botch.rule` требуют 1.37, `reroll` – 1.38. Импортируемый набор сообщества проверяет читающий его Engine, поэтому дополнительное требование не нужно.

#### Что Game Master может писать в проверке пула

```
[skill_check: skill="Ward" dc="2" who="Bram the Quiet" threshold="8" bonus="-2" with="Sinew"]
[skill_check: skill="Ward" difficulty="Grim" explode="9"]
[skill_check: skill="Nerve" dc="1" with="Warmth"]
[skill_check: skill="Ward" dc="2" reroll="careful"]
```

- `dc` – число необходимых **успехов**, не порог кости. Допустимо от 1 до максимума, который можно насчитать за бросок: максимум пула, удвоенный при взрывах и еще раз удвоенный при двойном зачете граней.
- `threshold=` меняет порог кости и предлагается только при `target.min` ниже `target.max`.
- `bonus=` добавляет или убирает кости и предлагается только при объявленном `situationalDice`.
- `with=` использует для навыка или спасброска другую характеристику. Работает в обоих видах, так что набор 5e получает "Strength (Intimidation)" через тот же атрибут. В проверке характеристики он вместо этого добавляет вторую характеристику, если включено `pool.abilityPlusAbility`.
- `difficulty=` называет ступень лестницы вместо `dc=` в обоих видах: ее число успехов (или ее сложность при сумме) и, для пула, ее порог. Записанный рядом `dc=` по-прежнему главнее для числа, а `threshold=` – для порога. Имя, которому не соответствует ни одна ступень или которое носят две ступени, игнорируется.
- `explode=` и `double=` сдвигают грани этих правил для данной проверки и предлагаются, только если у правила есть `min`.
- `reroll=` называет один из ваших перебросов `reroll` для данной проверки и предлагается, только если вы их объявили. Имя, которому не соответствует ни один из них, игнорируется.

Все ограничено декларацией файла: выходящее за диапазон значение прижимается к ближайшей границе, а отсутствующая в наборе характеристика игнорируется вместо отказа проверки. Запись показывает фактически использованные значения: сложность и порог числами, бонусные кости после ограничений, `with=` – только если характеристику действительно заменили или добавили, грань – только если проверка ее сдвинула, `reroll=` – только если брошен именно названный переброс и он что-то перебросил, и `complication="true"`, если по правилу `halfOrMore` что-то пошло не так одновременно с результатом. Engine всегда сам бросает кости. Результат пула от модели заменяется, `mode="advantage"` игнорируется, потому что вид не имеет преимущества, а брошенная игроком до хода кость не применяется.

#### Что вне области действия и почему

Каждой из этих механик нужен собственный вид разрешения, потому что ни одна не выражается подсчетом костей относительно порога:

- **Наибольшая кость** (как в Blades in the Dark) требует ступени частичного успеха, которой у результата проверки нет.
- **Пулы позиции против характеристики** (как в Lasers and Feelings) выбирают "выше или ниже" для каждой проверки: это другое сравнение.
- **Символьные кости** (как в Genesys) вообще не дают чисел.
- **Встречные пулы** разрешают двух персонажей одновременно; проверка имеет одного бросающего.
- **Броски ниже порога и открытые процентные броски** сравнивают в другую сторону.
- **Суммируемые пулы с дикой костью** (как в OpenD6) складывают кости и отдельно обрабатывают одну из них.

Обе ранее исключенные возможности теперь моделируются; раздел Расходы для изменения броска ниже объясняет как. Собственное правило системы, "потратить очко за успех" или "потратить очко, чтобы перебросить неудачи", – это `resolution.spend`. Переброс, который система дает бесплатно, когда этого требует ситуация, – это `resolution.reroll` выше. Переброс, принадлежащий выбранной персонажем вещи, – это `mechanics.check` записи каталога, оплачиваемый собственной стоимостью записи.

### Расходы для изменения броска

Некоторые системы позволяют платить за предстоящий бросок: очко воли за автоматический успех. `resolution.spend` описывает это как постоянное правило системы, а не купленную персонажем вещь:

```json
"spend": [{ "pool": "resolve", "amount": 1, "successes": 1, "perCheck": 2 }]
```

- `pool` – один из `live.pools`. Он не может начинаться пустым, иначе в начале игры тратить нечего.
- `amount` – стоимость ОДНОЙ покупки. `successes`, `dice` и `reroll` задают приобретаемое; покупка должна давать хотя бы одно из них. Успехи добавляются после подсчета костей и отмен, поскольку их никто не выбрасывал. Кости бросаются вместе с пулом в его собственных пределах. `reroll` имеет вид `{ "upTo": 6, "mode": "once" }`, читается так же, как `resolution.reroll`, и покупается один раз, сколько бы покупок ни сделала проверка: кость, переброшенная дважды, – все равно один переброс.
- `perCheck` – число покупок за проверку; максимум – на `amount * perCheck` очков. Ограничение не дает полному запасу купить беспроигрышный бросок. Это число от 1 до 10, значение из листа в той же форме, в какой его читает производное значение (`{ "abilityScore": "nerve" }`, `{ "derived": "focus" }`), или `"pool"`: столько, сколько у проверки костей, то есть число листа для нее до ран, бонусных костей и модификаторов. Значение из листа читается для бросающего, округляется вниз и удерживается между 0 и 100, а персонаж с пределом 0 ничего не покупает и ничего не платит.
- Только `dice-pool` может иметь это правило: у суммируемого броска нет успехов или пула для добавления костей, поэтому `dice-sum` с `spend` отклоняется при импорте.
- До четырех записей, и две не могут назвать один запас, иначе проверка не укажет, какая из них нужна.
- Расход, покупающий `reroll`, `perCheck`, не являющийся числом, и более двух записей требуют Capability API 1.38 для набора в составе пакета.

**Это указывается в самой проверке.** Game Master пишет `[skill_check: skill="Nerve" dc="2" spend="resolve:1"]`, а не отдельную команду `[sheet:]`: кости бросаются до применения команд листа, и позже менять было бы нечего. Одно разрешение бросает кости и оплачивает изменивший их эффект.

### Талисман, меняющий бросок

`resolution.spend` – правило системы. Фактически ВЫБРАННАЯ персонажем запись тоже может изменить проверку через `mechanics.check` записи каталога:

```json
"mechanics": {
  "kind": "utility",
  "cost": [{ "pool": "blood", "amount": 1 }],
  "perCostStep": { "flat": 1 },
  "check": { "reroll": { "upTo": 1, "mode": "once" }, "successes": 1 }
}
```

- `reroll` перебрасывает кости с гранью не выше `upTo`. `once` заменяет каждую один раз и оставляет новую грань; `until` продолжает. `upTo` должно быть ниже высшей грани, иначе весь пул перебрасывался бы бесконечно; Engine ограничивает число перебросов проверки независимо от файла.
- `dice` добавляет кости до броска, `successes` – успехи после подсчета, а `threshold` задает порог кости для этого броска в диапазоне `target`.
- `explode` и `double` сдвигают грани этих правил для одного броска, и только если у вашего правила есть `min`, в его пределах: `"check": { "explode": 8 }` – запись, при которой восьмерки бросаются снова. Они главнее написанного Game Master в теге, как и `threshold`. Capability API 1.37.
- Нужно хотя бы одно из этих полей; иначе запись ничего не определяет и отклоняется.
- Все это поддерживает только `dice-pool`, поэтому `dice-sum` с `mechanics.check` отклоняется при импорте.

**Стоимость – собственное `cost` записи**, оплачиваемое тем же механизмом, что использование любой другой вещи: запас и одно использование каждого счетчика этой записи. `perCostStep` задает МАСШТАБИРОВАНИЕ: запись с ним покупается столько раз, сколько оплачена цена, а без него – один раз независимо от предложенной суммы.

**Game Master называет запись в проверке:** `[skill_check: skill="Brawl" dc="3" use="Potence" spend="blood:3"]`. Не отдельной командой листа, по той же причине: бросок предшествует любому учету.

**Все или ничего.** Если запаса не хватает, покупки нет и ничего не списывается: бросок остается ровно таким, каким был бы без покупки. Очки, не составляющие целое число покупок, тоже ничего не дают. Превышение `perCheck` ограничивается, а не отклоняется, и оплачивается только предел. Все вычисляет Engine; Game Master называет объявленный игроком расход и не касается костей. Запись показывает фактическую оплату, примененную запись, число успехов без броска и переброшенных костей. Невыбранный талисман или талисман с недоступным Engine каталогом ничего не делает вместо применения на доверии.

### Лист

- `sections` группирует содержимое редактора. Поля, производные значения и списки указывают свою секцию через `section`; так же могут делать характеристики, навыки и спасброски: тогда редактор, лист в игре и блок листа Game Master показывают их под этим заголовком (лист, где у них секция не указана, показывает их точно как раньше). Секция также может нести правило `untrained` (ниже).
- `abilities` – основные показатели. `skills` и `saves` могут называть используемую характеристику, `cap` и правило `untrained` (ниже).
- `fields` – одиночные значения. Типы: `number`, `text`, `longtext`, `boolean`, `enum` (фиксированные варианты) и `dice` (текст вроде `1d8`).
- Значения `derived` вычисляются из других и не перезаписываются вводом. Операции: `sum`, `min`, `max`, `scale` (умножить и округлить), `stepTable` (найти по порогам, как уровень дает бонус мастерства) и `enumTable` (число для каждого значения поля-перечисления или текущего режима; см. Текущие режимы ниже).
- `lists` – таблицы со своими столбцами: снаряжение, заклинания, особенности. Список с `pools` превращает каждую строку в ресурс с собственным максимумом для классовых особенностей с ограниченными использованиями.
- `live` меняется в игре: `pools` (хиты, ячейки заклинаний, Grit), `tracks` (число на шкале, например истощение, или шкала ран с отметками), `text` (короткие заметки, например предмет концентрации), `conditions` и `states` (одно значение из закрытого набора, например облик или стойка).

Любой читатель числа указывает ссылку на значение – объект ровно с одним ключом: `const`, `field`, `derived`, `abilityScore`, `abilityMod`, `abilityModFromField`, `skillMod`, `saveMod`, `listSum`, `livePool`, `liveTrack` или `itemStat`. Пример запаса с производным максимумом: `"max": { "derived": "grit_max" }`.

- `listSum` складывает один числовой столбец списка: `{ "listSum": { "list": "gear", "column": "bulk", "onlyWhen": "packed" } }`. `onlyWhen` необязательно и называет логический столбец; учитываются только строки, где он включен. Пустое значение считается значением столбца по умолчанию, а список, скрытый через `hideWhen`, ничего не добавляет. Так Ember Roads вычисляет Burden по снаряжению, которое персонаж упаковал, поэтому значение никогда не расходится со списком, как могло бы введенное вручную число. Масштабируемый столбец каталога не может читать сумму списка даже через производное значение: список может содержать масштабируемые значения, свои или читающие его обратно, и пересчет никогда бы не завершился.
- `livePool` читает остаток одного из ваших `live.pools` (запас строки списка к ним не относится). `liveTrack` читает одну из ваших `live.tracks` с необязательным `read`: `"value"` – текущее положение (по умолчанию); `"filled"` – насколько шкала выше своего `min`; `"remaining"` – насколько ниже своего `max`; или, только для шкалы ран, `"penalty"` – действующий штраф. Скрытый запас или шкала читается как 0. "Harm still to take" в Gravewatch – это `{ "liveTrack": "harm", "read": "remaining" }`.
- Чтение текущего состояния берет его таким, каким оно является в момент броска проверки, начала боя или составления блока листа Game Master. Где текущего состояния еще нет (редактор листа, обзор импорта), читается состояние на начало игры: запас полный или пустой согласно своему `start`, шкала на своем `default`, шкала ран без отметок.
- Ничто, вычисляемое до появления текущего состояния, не может его читать: `max` запаса или шкалы, бонус мастерства, масштабируемый столбец или масштабирование каталога. Это действует и через читающее его производное значение, и через навык, ограниченный текущим значением, а импорт называет значение, которое так делает.
- Эти три ссылки требуют Capability API 1.39 для набора в составе пакета.
- `itemStat` читает предметы персонажа, например защиту надетого доспеха, и подчиняется тому же правилу, что чтение текущего состояния. См. [Предметы в листе](#items-on-the-sheet). Capability API 1.52.

**Проверка без подготовки.** Навык или спасбросок, в котором у персонажа нет подготовки (его уровень – первый), бросается как обычно, если набор не говорит иначе через `untrained` у навыка, спасброска или секции, в которой он находится (собственное правило навыка или спасброска главнее):

```json
"sections": [{ "id": "labour", "label": "Labour", "untrained": { "by": -1 } }],
"skills": [
  { "id": "dig", "label": "Dig", "ability": "sinew", "section": "labour", "untrained": "refuse" },
  { "id": "listen", "label": "Listen", "ability": "nerve", "untrained": "harder" }
]
```

- `"normal"`: как обычно (по умолчанию).
- `{ "by": -3 }`: прибавляется к числу проверки, от -20 до 20: кости для пула, постоянная величина для суммы. Входит в число, которое показывает лист и с которым бросается каждая проверка, до любого `cap`.
- `"harder"`: на одну ступень сложнее. Для пула порог кости повышается на один (оставаясь в пределах диапазона порога), поэтому нужен набор с пулом, чей порог может меняться; в любом другом случае правило отклоняется при импорте, потому что никогда не изменило бы бросок.
- `"refuse"`: проверка вообще не бросается. Engine записывает запрос Game Master обратно с `reason="untrained"`, и это окончательно: позже ее никто не бросает, Game Master сообщают, что персонаж не мог попытаться, и повествование это отражает. Конечная точка проверки навыка отвечает на такую проверку кодом 400 (`skill_check_untrained`), а блок ветвления, зависящий от нее, не сохраняет ни одного из двух исходов. Редактор листа не показывает для нее числа.
- Для персонажа без листа нет подготовки, которую можно прочитать, поэтому правила без подготовки к нему не применяются.
- Напоминание Game Master перечисляет правила без подготовки по секциям или по навыкам, чтобы он запрашивал проверки, которые персонаж может сделать.

Секции у характеристик, навыков и спасбросков, а также `untrained` в любом месте требуют Capability API 1.41 для набора в составе пакета.

Навык или спасбросок может иметь `cap` – ссылку на значение, выше которого его проверка никогда не поднимается: рейтинг, который нельзя перерасти, или шкала, которая его сдерживает. Gravewatch ограничивает Soothe оставшимся у стража Resolve: `"cap": { "livePool": "resolve" }`. Ограниченное число – то, которое показывает лист и с которым бросается каждая проверка, а замена через `with=` вычисляется по числу до ограничения и затем снова ограничивается. Предел не может читать модификатор навыка или спасброска, как и читаемое им производное значение и любое производное значение, объявленное выше него, поэтому лист по-прежнему вычисляется один раз, сверху вниз. Capability API 1.39.

`hideWhen` скрывает поле, производное значение, список, запас или обычную шкалу по значению другого поля ровно одним из трех способов: `equals` одно значение, `notEquals` одно значение (скрыто всякий раз, когда в поле что-то другое; так говорится "только для персонажей такого типа") или `in` список значений. Каждое названное значение должно быть допустимым для поля, иначе правило никогда не сработает, и проверяется это по одному значению; для `notEquals` и `in` это включает диапазон числового поля и длину текстового. Правило читает значение, которое показывает редактор листа: незаданное поле имеет значение, с которого начинается пустой лист, а значение перечисления, которое набор больше не предлагает, читается как значение поля по умолчанию. Файл 5e использует `equals`, чтобы скрыть ячейки заклинаний у персонажа, не владеющего магией; Gravewatch убирает масло для фонаря из листа каждого стража не из ночной смены через `"hideWhen": { "field": "watch", "notEquals": "night" }`. Слой не может удалить значение, с которым сравнивает любое из этих правил. Шкалу ран скрыть нельзя, потому что броски и бой читают ее независимо от того, что показывает лист. `notEquals` и `in` требуют Capability API 1.39.

`max` обычной шкалы может быть ссылкой на значение вместо числа, и тогда длину шкалы задает рейтинг персонажа: `"max": { "field": "willpower_rating" }`. Ее `min` и `default` остаются числами. У шкалы ран с именованными уровнями `max` равен числу уровней; шкала из нумерованных ячеек длиной равна собственному `max` (см. Нумерованные ячейки ниже). `alwaysShow: true` выводит шкалу в блок листа Game Master даже на значении по умолчанию – для рейтинга, важного на каждом ходу; без него шкала на значении по умолчанию опускается, потому что три спасброска от смерти на нуле ничего не говорят. Эти три возможности требуют Capability API 1.37 для набора в составе пакета.

### Текущие режимы: облик, стойка, свет

Поле-перечисление выбирается при создании персонажа и остается выбранным, а состояние лишь включено или выключено. **Текущий режим** – одно значение из закрытого набора, меняющееся в игре: облик оборотня, боевая стойка, насколько ярко горит фонарь.

```json
"live": {
  "states": [
    {
      "id": "stance",
      "label": "Stance",
      "values": ["guarded", "steady", "reckless"],
      "valueLabels": { "guarded": "Guarded", "steady": "Steady", "reckless": "Reckless" },
      "default": "steady"
    }
  ]
}
```

- `values` – от двух до сорока значений, каждое показывается как его запись в `valueLabels` или как есть. Они подчиняются правилу любой подписи (одна строка, без квадратных скобок и фигурных скобок макросов) и никогда не содержат двойных кавычек, потому что команда листа заключает их в кавычки. До двенадцати режимов.
- `default` – значение, с которого начинается каждый лист; если его опустить – первое значение. Хранится только режим, отличный от значения по умолчанию, а сохраненное значение, которого режим больше не предлагает, читается как значение по умолчанию.
- `hideWhen` убирает режим из листа по значению поля, как и запас: он не показывается, не задается командой и читается таблицей (ниже) как отсутствие значения.
- Game Master задает режим командой `[sheet: who="Name" op="state" state="Stance" value="Reckless"]`, называя режим по id или подписи, а значение – как есть или по подписи. Режим или значение, которых нет в листе, отклоняются (`unknown-state`, `unknown-value`). Engine обучает модель этой команде и перечисляет все значения, только если в наборе есть режим, а каждый блок листа называет значение каждого режима, включая значение по умолчанию, потому что "в человеческом облике" – факт, нужный повествованию на каждом ходу.
- Экран листа в игре показывает выбор для каждого режима.
- Отдых возвращает режим шагом восстановления, который его называет: `{ "state": "stance", "to": "default" }` или `"to"` с одним из его значений.

**Числа, которые следуют за режимом.** Производное значение с `"op": "enumTable"` дает число для каждого значения поля-перечисления или текущего режима:

```json
{
  "id": "stance_brawn",
  "label": "Stance on Brawn",
  "op": "enumTable",
  "from": { "liveState": "stance" },
  "table": { "guarded": -1, "reckless": 2 },
  "default": 0
}
```

- `from` называет ровно одно из двух: `field` (поле-перечисление) или `liveState`. Каждая строка `table` – значение, которое тот может принимать, от одной до сорока строк. Значение, пропущенное таблицей, и режим, скрытый листом, читаются как `default` (0, если его опустить).
- Поле фиксируется при создании персонажа, поэтому таблица по нему может питать максимум: Gravewatch дает стражу рассветной смены на одно очко Resolve больше. Текущий режим меняется в игре, поэтому таблица по нему – чтение текущего состояния, как `liveTrack`: ничто, вычисляемое до появления текущего состояния, не может ее читать ни напрямую, ни через другое производное значение. Поэтому ключ называется `liveState`, а не `state`: каждое чтение текущего состояния названо через `live`, и так вы и импорт отличаете то, чего максимум использовать не может.
- Чтобы число попало на кости, укажите на него в `resolution.adjust` (см. Модификаторы из листа). Ember Roads добавляет свою Stance к каждому броску Brawn; в Gravewatch закрытый или погасший фонарь отнимает от каждого броска Nerve.
- Слой может убрать значение из поля, для которого в таблице есть строка. Пока слой включен, эта строка просто никогда не читается.

Текущие режимы, `enumTable` и шаг отдыха, называющий `state`, требуют Capability API 1.42 для набора в составе пакета.

### Шкалы ран: здоровье как шкала вместо числа

Многие системы вообще не считают хиты. Вместо них – столбец ячеек, каждая хуже предыдущей, и при ранении ставится отметка. Добавьте записи `live.tracks` `kinds` и либо именованные `levels`, либо нумерованные `boxes` (ниже), и число на шкале станет такой шкалой ран:

**Какая форма нужна вашей системе?** Запас хранит СКОЛЬКО вреда получено; шкала – сколько И какого вида была каждая часть. Если рана бывает ударной, летальной или усугубленной, и вид важен после удара – усугубленная медленнее лечится, не поглощается или окончательно убивает, – он должен где-то сохраниться после броска. Вид несет только отметка. Запас очков этого не умеет: вычтенный урон оставляет меньшее число, а лист не помнит вид отдельных очков. Поэтому `combat.damageKinds` отклоняется при здоровье-запасе, а не игнорируется. Запас все еще может иметь `damageTypes`, а противник – сопротивление или иммунитет к ним: это определяет дошедшую часть удара, а не последующий вид раны.

```json
{
  "id": "harm",
  "label": "Harm",
  "min": 0,
  "max": 4,
  "levels": [
    { "label": "Scuffed", "penalty": 0 },
    { "label": "Winded", "penalty": -1 },
    { "label": "Bleeding", "penalty": -3 },
    { "label": "Down", "penalty": -99 }
  ],
  "kinds": [
    { "id": "knock", "label": "K", "severity": 0 },
    { "id": "tear", "label": "T", "severity": 1 }
  ]
}
```

- `levels` – 1–16 ступеней от лучшей к худшей. У каждой `label` и целый `penalty`, не превышающий 0. Большое отрицательное число означает выбывание, поэтому `-99` допустимо.
- `kinds` – 1–6 видов вреда с `id`, коротким `label` для ячейки и `severity`. Тяжести должны различаться; числа задают лишь порядок, интервалы произвольны.
- Оба нужны вместе. `kinds` без `levels` или `boxes` отклоняется: нечего отмечать. `levels` или `boxes` без `kinds` тоже отклоняется: отметка должна иметь вид. У шкалы есть `levels` или `boxes`, но никогда оба.
- **Различайте два слова.** `kinds` – то, чем отметка МОЖЕТ БЫТЬ по правилам. ОТМЕТКА – один из этих видов на шкале во время игры. Определение хранит виды, лист персонажа – отметки.
- Шкала ран начинается без отметок, поэтому ее `min` – 0. Шкала с именованными уровнями длиной равна числу уровней, поэтому ее `max` – `levels.length`; другое значение отклоняется, а не исправляется молча, поэтому противоречащих длин в файле быть не может. Шкала из ячеек длиной равна собственному `max`, который может быть вычисляемым листом значением (см. Нумерованные ячейки ниже).

**Точные правила**, потому что расплывчатое прочтение дает неправильную шкалу:

- Отметки отсортированы, **самые тяжелые первыми**. Семь уровней вмещают максимум семь отметок.
- Отметка **вставляется по тяжести** среди имеющихся, не добавляется в конец. Она занимает высший положенный тяжести уровень и сдвигает легкие вниз.
- Действует штраф **самого нижнего отмеченного уровня**, не сумма. Три отметки на шкале выше дают `-3`, не `0 + -1 + -3`.
- `amount` – число отметок одного вида, **применяемых по одной**: шкала, заполненная в процессе, обрабатывается так же, как изначально полная.
- Отметка на **полной** шкале **повышает самый легкий вид на одну ступень** вместо добавления. На одну ступень собственной лестницы видов независимо от вида новой отметки.
- Повышение выше максимальной тяжести оставляет максимум, а невместившаяся отметка учитывается как **переполнение**. Оно сохраняется, поэтому перезагрузка не забывает уже полученный вред.
- **Лечение – та же команда с отрицательным количеством.** Переполнение снимается раньше любой отметки. Лечение, называющее один из видов шкалы, снимает только отметки этого вида, поэтому "ударные раны заживают, летальные остаются" – это `kind="bashing"` с отрицательным количеством; лечение, не называющее ни одного вида шкалы, сначала снимает самые легкие отметки.

**Отметки в игре.** Game Master пишет `[sheet: op="damage" track="harm" kind="knock" amount="1"]` и лечит отрицательным `amount`. На шкале, заполняемой по ячейкам, он добавляет `box="3"` – ячейку, в которую приходится удар. Форма `damage` с `pool=` не меняется. Простая команда `track` для шкалы ран отклоняется: одно число не называет виды новых отметок. Игрок также может вручную отмечать и очищать ячейки листа, как предполагают такие системы.

**Бой тоже ставит отметки.** Направьте `combat.health` на шкалу вместо запаса. Попадание отмечает столько ячеек, сколько говорит `combat.damageKinds.marks`, видом, сопоставленным этим блоком типу урона. Персонаж с полной шкалой падает, что и читает правило умирания. На шкале, заполняемой по ячейкам, урон `per-point` называет ячейку, в которую приходится, а `per-blow` целится в первую; удар, который не может принять ни одна ячейка, валит персонажа с ног – в системах с такой шкалой это и означает выбыть. Лечение очищает одну отметку, самую легкую, любого вида. Временные очки отклоняются: у шкалы нет буфера для них. Engine читает шкалу как число ОСТАВШИХСЯ уровней, поэтому остальной бой, падение, возвращение, журнал и пересказ не меняются.

**Отдых может лечить шкалу ран.** Шаг восстановления с `"to"` очищает ее до указанного числа отметок, вместе с переполнением; шаг с ОТРИЦАТЕЛЬНЫМ `"by"` убирает столько отметок, начиная с переполнения, так что `"by": { "const": -2 }` убирает две. Шаг, который также называет `kind`, снимает только отметки этого вида: "Catch your breath" в Gravewatch – это `{ "track": "harm", "kind": "knock", "to": "min" }`, он залечивает ушибы и оставляет разрывы. Шаг, ДОБАВЛЯЮЩИЙ отметки, ничего не делает, потому что отдых не наносит вреда, и это касается и положительного `"by"`: такой шаг молча пропускается, поэтому пишите знак минус.

#### Нумерованные ячейки вместо именованных уровней

Если длина шкалы зависит от выносливости персонажа, задайте ей `boxes` вместо `levels`. У нее столько ячеек, сколько составляет ее собственный `max`, который может быть вычисляемым листом значением (но никогда не читающим текущее состояние), до 64:

```json
{
  "id": "strain",
  "label": "Strain",
  "min": 0,
  "max": { "derived": "strain_boxes" },
  "boxes": {
    "penalty": {
      "by": "remaining",
      "table": [
        [0, -1],
        [1, 0]
      ]
    }
  },
  "kinds": [{ "id": "strain", "label": "S", "severity": 0 }],
  "fill": "indexed",
  "onFull": "refuse"
}
```

- Действующий штраф берется из `table` (таблица ступеней, как у производного значения, со штрафами не выше 0) по числу ячеек `filled` или `remaining`, каким бы оно ни было, поэтому таблица может назначать цену даже без отметок. Он не зависит от того, какие именно ячейки отмечены.
- Ячейки нумеруются: лист показывает "Box 3", а блок листа Game Master сообщает, сколько отмечено из скольких, вместо названия уровня.

#### Заполнение по ячейкам и шкалы, которые отказывают

- `"fill": "indexed"` ставит отметку в ячейку, названную командой через `box=` (в первую ячейку, если ничего не названо), или в следующую свободную ячейку выше нее и никогда не сдвигает уже поставленную отметку. Лечение снимает самую верхнюю из самых легких отметок. Экран листа позволяет игроку нажать любую свободную ячейку.
- `"onFull": "refuse"` отклоняет отметку, для которой нет свободной ячейки, вместо повышения самой легкой отметки. Отклоняется вся команда, поэтому три отметки при двух свободных ячейках не ставятся вовсе. Шкала с индексацией всегда отказывает; укажите это рядом через `"onFull": "refuse"`.

#### Уровни, добавляемые списком

`"extra": { "list": "scars", "countColumn": "levels", "penaltyColumn": "penalty" }` у шкалы с именованными уровнями позволяет списку в листе удлинять ее для каждого персонажа. Каждая строка по порядку добавляет свое число уровней (не больше 16) со своим штрафом после последнего уровня, штраф которого не хуже; уровни называются по этому уровню, если штрафы совпадают, и по штрафу в остальных случаях. Так устроены шрамы в Gravewatch. Скрытый листом список ничего не добавляет, а если удалить строку, пока ее уровни отмечены, непоместившиеся отметки сохраняются как переполнение: правка листа не отменяет вред.

`boxes`, `fill`, `onFull`, `extra` и `kind` в шаге отдыха требуют Capability API 1.40 для набора в составе пакета.

### Штраф к броскам

`resolution.penaltyFrom` указывает шкалу ран, штраф которой действует на каждую проверку набора. Это декларация, не предположение: без нее броски работают точно как до появления шкал ран.

ДЕЙСТВИЕ штрафа определяет вид разрешения, как и значение числа листа:

- При `dice-pool` **убираются кости из пула**, не ниже собственного `pool.min`. При `pool.min` 1 даже на последней ступени бросается одна кость; при `pool.min` 0 не бросается ни одной и наступает провал без броска.
- При `dice-sum` это **фиксированный модификатор броска**, включенный в то же число, куда добавляются характеристика и подготовка.

Ссылка должна указывать шкалу ран. Обычная шкала не имеет штрафа и отклоняется при импорте. Результат называет примененный штраф, чтобы игрок понимал меньшее число костей, а блок листа для Game Master показывает ступень и ее цену.

### Модификаторы из листа

Некоторые числа листа сопровождают каждый бросок, которого касаются: тяжелый мешок при каждом подъеме, штраф доспеха при каждой попытке подкрасться, благословение на все. `resolution.adjust` описывает это для любого вида:

```json
"adjust": [{ "value": { "derived": "burdened" }, "abilities": ["brawn"] }]
```

- `value` – значение из листа в той же форме, в какой его читает производное значение, включая текущее состояние. Отрицательное число отнимает. Ember Roads складывает объем снаряжения, упакованного персонажем, в Burden, а таблица ступеней превращает каждые три единицы в минус один к каждому броску Brawn. Таблица по текущему режиму – способ довести облик или стойку до костей (см. Текущие режимы).
- `abilities` необязательно. С ним модификатор применяется только к проверке, бросаемой с одной из этих характеристик: самой характеристикой, навыком или спасброском, который ее использует, навыком, брошенным с ней через `with=`, или парой характеристик, которая ее включает. Без него – к каждой проверке.
- Он применяется там же, где штраф ран: кости для пула с тем же нижним пределом `pool.min` и постоянное число для суммы внутри модификатора, который складывает запись броска. До восьми записей, они складываются для каждой проверки.
- Бой по набору правил добавляет его к каждому броску, который строит из листа, в начале боя: атака, бросаемая с характеристикой или навыком, спасбросок, проверка состязания и инициатива, читаемые из характеристики, навыка или спасброска, получают записи этой характеристики, а все остальное – только записи для каждого броска.
- Персонаж без листа ничего от него не получает, как не получает и модификатора.

Результат сообщает, что добавил лист (`adjust="-2"` в записи броска и строка на карточке броска), чтобы игрок видел, почему бросок вышел таким. Это Capability API 1.38 для набора в составе пакета.

### Отдых

Отдых – список шагов восстановления и очищаемых вещей. Каждый шаг называет одну цель (`pool`, `poolGroup`, `listPools`, `track` или `state`) и задает значение (`"to": "max"`, `"to": "min"` либо число) или меняет его (`"by": { "const": 1 }` либо `"by": { "fractionOfMax": 0.5 }`). Шаг шкалы ран может только лечить, поэтому его `by` отрицателен; см. выше. Шаг текущего режима только задает его – `"default"` или одно из его значений.

### Текст Game Master

- `checkGuidance` заменяет встроенный абзац о запросе проверки. Назовите систему и случаи бросков. Game Master указывает лишь навык и сложность; Engine бросает и считает по листу, поэтому не просите модель вычислять.
- `sheetGuidance` представляет листы в промпте. Объясните важные ресурсы и когда их тратить.
- `worldGuidance` необязательно и читается один раз при генерации мира, чтобы придуманные условия подходили правилам: нет пороха, редкая магия, ходячие мертвецы. На ход оно не попадает.
- `sheetSummary` выбирает поля, производные значения и строки списков, видимые Game Master для персонажа. Engine всегда показывает модификаторы характеристик, освоенные навыки и спасброски, а также текущие значения. Остальное держите коротким: оно отправляется каждый ход. `nameColumn` списка в сводке может быть текстовым столбцом или столбцом-перечислением (перечисление показывает подпись значения), а `columns` называет до трех других столбцов строки, выводимых после имени, поэтому блок читается как `Gear: Crowbar 1d6`, а не одни имена. Логический столбец выводит свою подпись, когда включен. Оба требуют Capability API 1.37 для набора в составе пакета.
- Объяснять команду листа в `sheetGuidance` не нужно. Engine сам обучает модель каждой команде с именами, объявленными в файле, а если в наборе есть шкала ран, добавляет команду `op="damage"` для ее отметки и перечисляет ее уровни и виды вреда. Если есть текущие режимы, он добавляет команду `op="state"` и перечисляет значения каждого.

## Каталоги: готовые записи для списков листа

Построчно вводить заклинания, снаряжение или страницу классовых особенностей утомительно. Каталог – именованная коллекция готовых записей в наборе. Редактор предлагает их в выборе каждой питаемой каталогом таблицы; выбор заполняет строку.

Каталоги необязательны. Набор может иметь до двенадцати; Engine не знает их назначения: все ID, столбцы, фильтры и слова поступают из файла.

### Заголовок

Заголовок находится в `catalogs` верхнего уровня рядом с `gm`.

```json
"catalogs": [
  {
    "id": "knacks",
    "label": "Knacks",
    "feeds": ["knacks", "tricks"],
    "filters": [
      { "id": "grit", "label": "Grit cost", "type": "number" },
      { "id": "road", "label": "Road", "type": "text" },
      { "id": "callings", "label": "Calling", "type": "tags", "startFrom": { "field": "calling" } }
    ],
    "units": { "distance": { "label": "paces", "perCell": 2 } },
    "entries": []
  }
]
```

- `id` и `label`: ID соответствует правилам идентификаторов листа; подпись называет окно выбора.
- `holds`: `"rows"` (по умолчанию и во всех каталогах до этого выпуска), `"creatures"` или `"items"`. Каталог существ – читаемый боем бестиарий, а каталог предметов перечисляет то, что несет отряд. Ни один из них ничего не пишет в лист, не объявляет `feeds` и не предлагается в окне выбора. См. [Существа](#creatures-a-bestiary-a-fight-reads) и [Предметы](#items-what-a-party-carries) ниже.
- `feeds`: от одного до восьми списков листа, куда могут писать записи. Обязательно для каталога строк и запрещено для каталогов существ и предметов. Запись не пишет в неуказанный список или значение, недопустимое для его столбцов.
- `filters`: необязательно, до восьми фильтров выбора. Фильтр – `number`, значение `text` или `tags` (несколько слов). `startFrom` называет поле листа, с которым открывается выбор: персонаж с Calling Tinker сначала видит записи Tinker.
- `units`: необязательно. Значение дальности или размера области в `mechanics` записи для вашей системы.

### Запись

```json
{
  "id": "road-sense",
  "label": "Road Sense",
  "summary": "You read a road the way other people read a face.",
  "filters": { "grit": 0, "road": "Ash Flats", "callings": ["Scout", "Courier"] },
  "rows": [
    {
      "list": "knacks",
      "values": { "name": "Road Sense", "notes": "Sneak to notice where a road turns bad." }
    }
  ]
}
```

- `id`: строчные буквы, цифры и одиночные дефисы; уникально внутри каталога.
- `label` и `summary`: отображаемое в выборе. Сводка необязательна, одна строка до 300 символов.
- `filters`: значения объявленных заголовком фильтров. `number` принимает число, `text` одну строку, `tags` список строк.
- `rows`: записываемое при выборе, от одной до шести строк. `list` – один из `feeds`, а ключи `values` – ID столбцов списка.
- `creature`: противник вместо строк в каталоге, чей `holds` содержит существ. У записи ровно одно из `rows` и `creature`; у существа нет `mechanics`, оно описывает поведение собственными действиями.

Каждое значение проверяется по столбцам целевого списка, поэтому неверное имя столбца или число вне диапазона сообщается вместе с исходной записью. Записи внутри файла набора проверяются при загрузке, для импортируемого файла – при импорте. Отдельный каталог пакета проверяется при первом запросе окна выбора; ошибочный файл показывает там причины вместо записей.

### Одна запись, несколько списков

Особенность с ограниченными использованиями – две строки: сама особенность и счетчик. Выбирается она по-прежнему один раз.

```json
{
  "id": "last-ember",
  "label": "Last Ember",
  "rows": [
    {
      "list": "knacks",
      "values": { "name": "Last Ember", "notes": "Spend 1 Grit to give a downed friend 3 Grit back." }
    },
    { "list": "tricks", "values": { "name": "Last Ember", "uses": 1, "recharge": "camp" } }
  ]
}
```

### Значения, обновляемые набором

После выбора числа строки принадлежат игроку. Полезное исключение – следующий за персонажем максимум: использования по значению характеристики или ресурс класса, растущий с уровнем. Строка может назвать до четырех числовых столбцов в карте `scaled`, и редактор поддерживает их значения.

```json
{
  "list": "tricks",
  "values": { "name": "Last Ember", "uses": 1, "recharge": "camp" },
  "scaled": { "uses": { "from": { "abilityScore": "heart" } } }
}
```

- Ключ – один из столбцов `number` списка.
- `from` – обычная ссылка на значение из того же закрытого словаря. Сложное вычисление становится объявленной листом величиной `derived`, на которую указывает `from` (`"from": { "derived": "lay_on_hands_max" }`). Новая арифметика не добавляется.
- `table` необязательно. Ищет значение ссылки в таблице ступеней, например число по уровню: `"scaled": { "max": { "from": { "field": "level" }, "table": [[1, 2], [3, 3], [6, 4]] } }`.
- `values` по-прежнему должно иметь обычное число столбца; строка без него отклоняется. Оно используется до появления листа и сохраняется в листе без указанной ссылки.
- Строка с `scaled` должна быть единственной строкой записи для этого списка, чтобы отмеченная строка листа соответствовала одной спецификации.

Значение вычисляется при редактировании, никогда при чтении: сохраненная строка всегда содержит показанное число. Оно ограничивается `min` и `max` столбца и округляется вниз для целых значений. В примере Heart 3 дает три использования, Heart 0 и ниже – ни одного. Строка остается с 0 использований; счетчик с максимумом 0 не является запасом, поэтому тратить в игре нечего.

Масштабируемые столбцы пакета требуют Capability API 1.23. Импортируемый набор сообщества проверяет читающий Engine, поэтому ничего дополнительного не нужно.

### Выбранные строки являются копиями

Выбранная строка копируется в лист с дополнительным ключом `_catalog`, содержащим `<catalog id>/<entry id>`. ID столбцов начинаются буквой, поэтому ключ не может совпасть с вашим.

Копия принадлежит персонажу. Игрок может менять ее содержимое, лист работает без установленного набора, а публикация новой версии никогда не переписывает чужого персонажа. Метка позволяет окну выбора показать уже имеющееся и используется обновлением ниже.

### Обновление из набора правил

Выбранная строка сохраняет метку, поэтому редактор листа может сообщить игроку, что ваш новый текст отличается от содержимого строки. Короткая строка под списком показывает число строк с обновленным текстом, а кнопка **Review** (просмотреть) сопоставляет для каждой содержимое листа и набора правил, с флажком выбора. До нажатия **Update selected** (обновить выбранное) ничего не записывается; затем меняются только различающиеся столбцы отмеченных строк. Все остальное, включая метку, сохраняется.

Область сравнения намеренно узкая:

- Существующие значения сравниваются только в столбцах `text`, `longtext`, `dice` и `enum`. Значения `number` и `boolean` принадлежат игроку и сохраняются, включая 0 и false. Еще отсутствующий в строке столбец можно предложить с типизированным значением, в том числе числом или переключателем. Масштабируемый столбец исключен: он уже следует за листом.
- Только столбцы, заданные вашей записью. Пропущенный в ней столбец никогда не меняется, что бы ни хранилось в листе.
- Значение, которое сам столбец не примет, например больше не предлагаемый вариант `enum` или текст длиннее `maxLength`, пропускается, а не записывается.
- Строка сопоставляется с породившей ее строкой записи по позиции среди строк с той же меткой в данном списке, пока их на листе столько же, сколько пишет запись. Иначе это работает только для записи, которая пишет одну строку в этот список. Если игрок удалил одну из двух строк записи, ее оставляют без изменений, не пытаясь угадать.
- Строка, чьей записи больше нет в каталоге, остается без изменений и без уведомления.

Таким образом, новый текст или название записи могут попасть к уже выбравшим ее персонажам, если те примут обновление. Изменить таким способом смысл числа нельзя и не получится: как только строка принадлежит игроку, этот столбец тоже его.

### `mechanics`: действие записи в числах

Запись может содержать необязательный блок `mechanics`, описывающий ее действие в числах: `kind` (`attack`, `heal`, `buff`, `debuff`, `utility`, `rider`), `range`, `area`, `targets`, `targetCount`, `friendlyFire`, `amount` (кости, например `2d6`, или постоянное число), `damageType`, `attackRoll`, `autoHit`, `save` (один из спасбросков листа и эффект успеха), `applies` (накладываемые состояния), `temporary` (временные очки в запасе здоровья), `scales` (величина, растущая вместе с листом), `cost` (расходуемый при использовании запас), `perCostStep`, `budget` (расходуемая часть экономики действий), `concentration`, `reaction`, `plus`, `free`, `gives`, `standard`, `rider` и `check`.

Окно выбора показывает этот блок одной строкой. Кто читает остальное, зависит от блока, который включен в наборе правил:

- С [блоком `combat`](#combat-a-fight-your-own-rules-resolve) бой читает боевые эффекты. `range`, `area` и `friendlyFire` применяются на поле боя с позициями; `reaction` обозначает запись, которая отвечает на событие, а не используется в свой ход, и называет ожидаемый ею момент (см. [Окна](#windows-holding-the-fight-open)); запись с простым `true` не называет момента и не появляется ни в одном меню. `check` применяется к проверкам навыков, как описано выше.
- Только с [блоком `battle`](#battles-lending-the-sheet-to-marinaras-combat) бой читает `kind`, `range`, `area`, `friendlyFire`, `amount`, `damageType` и `cost`: для этих частей есть место в собственной боевой системе Marinara.

Словарь закрытый: ключ или значение, которых нет в списке выше, отклоняются, а не молча игнорируются.

`cost` также задает цену, которую вне боя платит команда `use` Game Master; ей посвящен следующий раздел.

### Команда `use`: Game Master платит заданную вами цену

В ходе повествования Game Master обновляет каждый лист командами `[sheet: ...]`: `spend`, `restore` (`heal` означает то же самое), `damage`, `temp`, `track`, `condition`, `note` и `rest`. Набор правил с каталогами получает еще одну:

```
[sheet: who="Mira" op="use" name="Fireball"]
[sheet: who="Mira" op="use" name="Fireball" pool="3rd-level slots"]
```

`op="cast"` означает то же, что `op="use"`, а `spell=` – то же, что `name=`. Поэтому привычная Game Master формулировка работает, хотя формату не нужно знать слово "заклинание".

Имя сопоставляется без учета регистра со строками листа этого персонажа, полученными из одного из ваших каталогов. Строка отзывается на имя, показанное Game Master (столбец имени `sheetSummary` для списка, затем `pools.nameColumn` списка, затем его первый текстовый столбец), и на `label` исходной записи, поэтому переименование строки игроком не лишает ее доступа. Отклоняется как имя без совпадений, так и имя, соответствующее двум разным записям.

Что расходуется:

- Каждое слагаемое `mechanics.cost` записи. Слагаемое с именем текущего запаса оплачивается из него; с именем ГРУППЫ запасов – из первого запаса этой группы в порядке объявления, способного покрыть цену. Автоматического перехода к более высокому запасу нет: группа не всегда представляет лестницу.
- Плюс единица из каждого запаса в строке списка, записанного той же записью, например счетчика использований способности. Это вторая строка записи `Last Ember` выше. Счетчик с максимумом 0 не имеет доступных использований, поэтому команда отклоняется, а не проходит бесплатно.

`pool=` – применение на более высоком уровне: та же единственная цена оплачивается из другого запаса той же группы. Оно допускается, только если в цене ровно одно слагаемое, а указанный запас входит в его группу. Все остальное отклоняется без переосмысления.

Все или ничего. Если любую часть оплатить нельзя, вся команда отклоняется, ничего не меняется, а игрок получает сообщение. Запись вообще без цены, например заговор или пассивная способность, принимается и ничего не меняет.

### Встроенный каталог или отдельный файл

Небольшой каталог размещается прямо в `ruleset.json`, в `entries` заголовка. Большой живет в собственном файле, который заголовок указывает через `asset`. У каталога ровно один из этих вариантов.

```json
{ "id": "knacks", "label": "Knacks", "feeds": ["knacks"], "asset": "catalogs/knacks.json" }
```

Путь всегда имеет вид `catalogs/<the catalog's id>.json`. Сам файл выглядит так:

```json
{ "schemaVersion": 1, "catalog": "knacks", "entries": [] }
```

Отдельные файлы каталогов предназначены для пакетов из официального каталога: пакет перечисляет файл в `contributions.assets.paths` рядом с `ruleset.json` и требует Capability API 1.21. Каталог существ, встроенный или отдельный, требует Capability API 1.27, а каталог предметов – 1.49. **Набор правил, импортируемый одним файлом или публикуемый через репозиторий GitHub, хранит каталоги внутри**, поэтому они должны уместиться в ограничение 256 KB на весь файл набора правил. Этого хватит на несколько сотен коротких записей.

Ограничения: 12 каталогов на набор правил, 2000 записей на каталог в обоих вариантах и 1 MB на отдельный файл каталога.

## Предметы: что несет отряд

Доспехи, оружие, зелья, снаряжение, боеприпасы и деньги – это предметы. Необязательный блок `items` объявляет слова, которыми описан каждый предмет вашего набора, а каталог с `holds: "items"` перечисляет сами предметы. Оба требуют Capability API 1.49; `rarityCaps` и `propose` блока, управляющие предметами, которые придумывает Game Master, требуют 1.51, значение, читающее предметы персонажа (`itemStat`), – 1.52, действие предмета на проверки, пока он надет или при себе, вместе с ограничениями `bonus` блока – 1.53, требования предмета к носителю и изменяемые им характеристики – 1.54, `attack` оружия – 1.55, действие предмета в бою – 1.56, то, чем стреляет оружие и сколько в нем заряжено, – 1.57, режимы оружия, атака второй рукой, нижний предел и состояния при попадании – 1.58, действие использования предмета в бою вместе с его зарядами – 1.59, использование, восстанавливающее запас, – 1.60, заряды, восстанавливаемые отдыхом, или предмет, ломающийся при опустошении, – 1.61, использование, требующее сначала проверки (`gate`), – 1.62, таблицы добычи и добыча существа – 1.63, строка добычи с монетами или слой, убирающий монеты, – 1.64, рынок, место `sold` предмета и `service` – 1.65, рыночный день (кошелек, `buyBack`, `stock` продавца, количество `limited` или `sold` без места) – 1.69, а дополнительный эффект, срабатывающий от удерживаемого оружия (`weapons`), – 1.70.

### Блок предметов

Блок находится в `items` верхнего уровня файла. Вот блок Ember Roads, немного сокращенный:

```json
"items": {
  "categories": [
    { "id": "weapon", "label": "Weapon" },
    { "id": "armor", "label": "Armor" },
    { "id": "ammunition", "label": "Ammunition" }
  ],
  "rarities": [
    { "id": "common", "label": "Common" },
    { "id": "storied", "label": "Storied" }
  ],
  "tags": [
    { "id": "thrown", "label": "Thrown" },
    { "id": "ranged", "label": "Ranged" },
    { "id": "two_handed", "label": "Two-handed" },
    { "id": "arrow", "label": "Arrow" }
  ],
  "stats": [
    { "id": "bulk", "label": "Bulk", "type": "number", "min": 0, "max": 10, "default": 0 },
    { "id": "guard", "label": "Guard", "type": "number", "min": 0, "max": 4, "default": 0 },
    { "id": "damage", "label": "Damage", "type": "dice", "example": "1d6" },
    { "id": "swing", "label": "Rolls with", "type": "enum", "values": ["brawn", "wits", "heart"], "default": "brawn" },
    { "id": "reach", "label": "Reach", "type": "enum", "values": ["close", "near", "far"], "default": "close" }
  ],
  "slots": [
    { "id": "body", "label": "Body", "count": 1 },
    { "id": "hands", "label": "Hands", "count": 2 }
  ],
  "carry": { "stat": "bulk", "encumberedAbove": { "derived": "load" }, "limit": { "const": 12 } },
  "rarityCaps": [
    { "rarity": "common", "stats": { "guard": 1 }, "bonus": 1 },
    { "rarity": "storied", "stats": { "guard": 3 }, "bonus": 2 }
  ],
  "currencies": [
    {
      "id": "coin",
      "label": "Coin",
      "perWeight": 100,
      "units": [
        { "id": "bit", "label": "bits", "value": 1 },
        { "id": "mark", "label": "marks", "value": 10 },
        { "id": "sovereign", "label": "sovereigns", "value": 100 }
      ]
    },
    {
      "id": "salt",
      "label": "Salt",
      "perWeight": 10,
      "units": [
        { "id": "pinch", "label": "pinches", "value": 1 },
        { "id": "cake", "label": "cakes", "value": 20 }
      ]
    }
  ]
}
```

- `categories`: от одной до 24. У каждого предмета ровно одна категория, например доспех, оружие или зелье.
- `rarities`: необязательно, до 12. Перечисляйте их от самой частой к самой редкой.
- `tags`: необязательно, до 48. Свойства, которые может иметь предмет, например метательный или посеребренный.
- `stats`: необязательно, до 24. Числа и слова, которые несет предмет, объявленные точно как столбец списка: `number`, `text`, `boolean`, `enum` или `dice`, с диапазоном, значениями и значением по умолчанию, где они есть у типа. `promptVisible` (по умолчанию `true`) определяет, показывается ли параметр Game Master рядом с предметом. Задайте `false` для того, что должен видеть только игрок, например где спрятан предмет.
- `slots`: необязательно, до 12. Где предмет носят или держат и сколько таких слотов у персонажа, от 1 до 20.
- `binding`: необязательно. Настройка, посвящение или что угодно еще, ограничивающее, сколько предметов один персонаж может одновременно держать привязанными. `label` – его название, а `max` – значение из листа персонажа, например `{ "abilityScore": "nerve" }` или производное значение. Оно не может читать текущее состояние, потому что число привязываемых предметов не меняется с каждым ударом.
- `carry`: необязательно. `stat` называет числовой параметр, который служит весом предмета, с `min` 0 или больше. `encumberedAbove` – сколько персонаж несет до перегрузки, а `limit` (необязательно) – сколько он вообще может нести. Оба читаются из листа, как `binding.max`. Без `carry` вес ничего не значит и никто не бывает перегружен.
- `currencies`: необязательно, до шести семейств по одной–десять монет.
  - Монеты одного семейства обмениваются друг на друга по `value`, которое считается в самой мелкой монете семейства. Поэтому самая мелкая монета стоит 1, и никакие две монеты семейства не стоят одинаково.
  - Два семейства никогда не обмениваются друг на друга. Монета другого государства или ходящие в мире одолжения – отдельное семейство.
  - Id монеты уникален среди всех семейств, потому что стоимость предмета называет только монету.
  - `perWeight` (необязательно и только рядом с `carry`) – сколько монет семейства весят одну единицу параметра переноски.
  - Монеты – деньги отряда, их носят в сумках, как любой предмет (см. Деньги ниже).
- `rarityCaps`: необязательно, не больше одного на редкость. Максимум, который может дать придуманный Game Master предмет этой редкости: наибольшее значение каждого числового параметра, названного в `stats`, в пределах собственного диапазона параметра и целое для параметра, принимающего целые числа, а также `bonus` (Capability API 1.53) – наибольший постоянный бонус, который может добавить один из его модификаторов при ношении. При редкости с `bonus` бонус в костях опускается, поскольку кости нельзя ограничить числом; штраф никогда не ограничивается. Придуманный предмет подчиняется этим ограничениям; предметы из ваших каталогов принадлежат вам и никогда не ограничиваются.
- `propose`: по умолчанию `true`. `false` запрещает Game Master придумывать предметы вашего набора.
- `native`: по умолчанию `true`. `false` отключает собственные нетипизированные предметы Game Mode в играх вашего набора (см. **Что читает предметы**). Game Master по-прежнему может придумывать предметы, описанные словами вашего набора.
- `freeform`: чем становится предмет, введенный игроком. `"plain"` (по умолчанию) оставляет его предметом без правил, как сейчас. `"refuse"` разрешает только предметы вашего набора.
- `lootTables` (Capability API 1.63): необязательно, до 24. Что выпадает из существ выигранного боя и по команде Game Master `[loot:]` (см. Добыча ниже).

### Предмет

Каталог предметов не объявляет `feeds`:

```json
{ "id": "outfitter", "label": "Outfitter", "holds": "items", "entries": [] }
```

Каждая запись несет `item` вместо `rows` или `creature`:

```json
{
  "id": "hunting-bow",
  "label": "Hunting bow",
  "summary": "Yew, waxed string, and a grip worn smooth by someone else's hand.",
  "item": {
    "category": "weapon",
    "rarity": "common",
    "tags": ["ranged", "two_handed"],
    "stats": { "bulk": 2, "damage": "1d8", "swing": "wits", "reach": "far" },
    "slots": { "hands": 2 },
    "cost": { "amount": 3, "unit": "sovereign" }
  }
}
```

- `id`, `label`, `summary` и `filters` работают как у любой записи. Подпись – название предмета.
- `category` обязательна. `rarity` и `tags` необязательны, и все три называют собственные id блока. Редкость у предмета может быть, только если блок объявляет редкости.
- `stats`: значения параметров блока. Каждое – допустимое для своего параметра значение.
- `slots`: сколько слотов каждого вида занимает предмет, никогда не больше, чем есть у персонажа.
- `stack`: сколько максимум вмещает одна стопка, от 1 до 999 999. Без него стопка вмещает столько же, сколько любая стопка Game Mode. Предмет с `charges` – один в стопке.
- `cost`: целое `amount` одной монеты, названной id в `unit`. Окно выбора показывает стоимость, и Game Master видит ее рядом с предметом (см. Деньги ниже).
- `sold` (Capability API 1.65): `{ "place": "city" }` – наименьшее из мест вашего рынка, где продается предмет, поверх любого правила, которое сказало бы иначе; с 1.69 он может вместо этого или вместе с этим сообщать, сколько таких предметов место держит в наличии за день (`"limited": 2` или `"limited": "1d3"`) (см. Рынки ниже).
- `service` (Capability API 1.65): `true` для ночлега, проезда, благословения: покупается как предмет и никогда не носится. Покупка только оплачивает услугу; ничто другое не кладет ее в сумку (добавление услуги отклоняется как `service`), а окно выбора не показывает услуги. У услуги есть `cost` и нет ничего связанного с ношением или использованием (`slots`, `stack`, `binds`, `worn`, `carried`, `requires`, `attack`, `use`, `charges`).
- `binds`: предмет нужно привязать, прежде чем он начнет действовать при ношении. `restriction` (необязательно) словами описывает, кто может его привязать, а `cursed: true` помечает предмет, который не отпускает. Привязываемые предметы бывают только в наборе с `binding`.
- `worn` и `carried` (необязательно, Capability API 1.53): действие предмета на проверки и спасброски владельца, пока предмет надет и пока его просто несут с собой, (1.54) характеристики, которые он задает или повышает, и (1.56) его действие в бою. См. [Проверки вне боя](#checks-outside-a-fight) и [Доспехи и эффекты надетого в бою](#armor-and-worn-effects-in-a-fight).
- `requires` (необязательно, Capability API 1.54): что предмет требует от носителя и что действует, пока тот не соответствует требованиям. См. [Проверки вне боя](#checks-outside-a-fight).
- `attack` (необязательно, Capability API 1.55): действие предмета как оружия в бою, пока он надет, (1.57) чем он стреляет и сколько в нем заряжено и (1.58) его другие режимы, атака второй рукой, нижний предел вреда и состояния, которые он накладывает при попадании. См. [Оружие в бою](#weapons-in-a-fight), [Боеприпасы и перезарядка](#ammunition-and-reloading) и [Режимы, второе оружие, нижний предел и состояния при попадании](#modes-a-second-weapon-a-floor-and-conditions-on-a-hit).
- `use` и `charges` (необязательно, Capability API 1.59): что делает использование предмета в бою и вне его, заряды, которые это использование тратит, и (1.60) запас, который оно восстанавливает. См. [Использование предметов в бою](#using-items-in-a-fight) и [Использование предметов вне боя](#using-items-outside-a-fight).

У предмета нет `mechanics`: его действие записано в блоке `item`.

### Что читает предметы

Все перечисленное проверяется при импорте набора, а ваши каталоги предметов поставляются вместе с ним. В игре их читает инвентарь Game Mode:

- **Ваши предметы лежат в сумке.** Стопка может быть одним из ваших предметов и остается им, как бы ее ни назвал игрок. Кнопка **From the ruleset** (из набора правил) в инвентаре открывает окно выбора всех предметов из ваших каталогов, с поиском и фильтрами каталога, а слой, скрывающий запись, скрывает ее и там.
- **Имена находят ваши предметы.** Имя, которое вводит игрок или пишет Game Master в `[inventory: action="add"]`, совпадающее в любом регистре с `label` одного из ваших предметов, добавляет этот предмет. Если у двух предметов одинаковая подпись, имя находит тот, который ваши каталоги перечисляют первым.
- **`stack`** соблюдается: добавление, установка количества, объединение или передача сверх него заполняет стопку и начинает новую.
- **`freeform: "refuse"`** оставляет игроку только ваши предметы: окно выбора и имена, совпадающие с вашими предметами.
- **`native: false`** оставляет Game Master только ваши предметы и придуманные им самим: имя, не являющееся ни тем, ни другим, отклоняется (`not-ruleset-item`), но добавить еще того, что уже есть, по-прежнему можно, и его инструкции это сообщают. Бой больше не спрашивает модель, что делают предметы инвентаря, поэтому сражаются только ваши предметы: в бою по набору правил – удерживаемое оружие и использования ваших предметов (см. Оружие в бою ниже), а в боях Classic и Tactical – ваши предметы с `use` (см. Предметы в боях Classic и Tactical ниже). Введенное игроком по-прежнему подчиняется `freeform`, а то, что нес отряд, в любом случае возвращается в новой сессии.
- **Что представляет собой предмет**, показывается на выбранной стопке: категория, редкость и метки по их подписям, параметры, сводка и сколько вмещает одна стопка. Окно выбора также показывает его `cost`. Game Master видит каждый имеющийся у отряда предмет вашего набора с категорией, редкостью, метками и параметрами, оставленными `promptVisible`, например `Hand axe [Weapon, Common, Thrown; Damage 1d6, Reach close]`.

- **`slots`**: предмет, занимающий слоты, может надеть тот, кто его несет, пока у него свободны эти слоты, а один предмет из большей стопки при надевании переносится в отдельную стопку. Инвентарь показывает занятые слоты каждого персонажа.
- **`binding`**: предмет с `binds` можно привязать, не больше `binding.max` из собственного листа носителя (персонаж без листа читает пустой). Проклятый (`cursed`) предмет после привязки остается привязанным: игрок не может отвязать его, снять, отдать или выбросить, и только Game Master может снять проклятие.
- **`carry`**: предмет весит свое значение `carry.stat` (предмет без него ничего не весит), а нагрузка персонажа – вес его сумки, сравниваемый с `encumberedAbove` и `limit` из его собственного листа. Предмет, добавленный в общий вид инвентаря игроком или Game Master без `who=`, достается тому, кто может его нести без перегрузки (сначала игроку, затем отряду по порядку), а если никто не может взять все, распределяется по оставшемуся у каждого месту. Ничто не превышает чей-либо `limit`: то, что никто не может нести, остается на месте, и Game Master об этом сообщают. Задайте параметру веса `"integer": false` для весов вроде четверти фунта.
- **Game Master придумывает предметы вашими словами.** Если вы не задали `propose: false`, его `[inventory: action="add"]` может описать новый предмет: `like=` – один из ваших предметов как основа, затем любые из `category=`, `rarity=`, `tags=`, `stats=` (пары `id=value`), `slots=` (`id=count`), `binds=` (`yes`, `cursed` или `no`), `worn=` и `carried=` (изменения через `;`, каждое `+N`, `-N`, `advantage`, `disadvantage` или `fails` для спасбросков, для навыков или спасбросков по имени либо для `checks` или `saves` для всех сразу, `+N` или `-N` к имени характеристики, чтобы повысить или понизить ее, а если у вас есть бои – `+N`, `-N`, преимущество или помеха к атакам и `+N` или `-N` к защите или вашему слову для нее: `worn="+1 Sneak; disadvantage on Sway checks"`, `carried="+1 Brawn"`, `worn="+1 Guard"` или `none`) и `summary=`, каждая часть по id или подписи. Параметр предмета, который уже учитывает ваша защита (Guard в Ember Roads складывает `guard` надетого), – это способ, которым доспех ее повышает, поэтому изменение защиты при ношении рядом с таким параметром опускается, и ответ это сообщает: небольшая модель пишет `guard=1` и `+1 Guard` для одного +1. Также читается то, что небольшая модель склонна писать вместо этого: число после имени (`Brawn +1`), "bonus" после атак или защиты (`+1 attack roll bonus`), `none` для пустого списка меток, параметров или слотов и `worn=`, `carried=` или `summary=` внутри `stats=`, если у вас нет параметра с таким именем. Engine сохраняет только то, что есть в вашем блоке: неизвестные категория, метка, параметр, слот, навык или спасбросок опускаются, отсутствующая у вас редкость становится самой низкой, число удерживается в диапазоне параметра, а затем в `rarityCaps` своей редкости, бонус при ношении – в `bonus` своей редкости (включая часть, взятую из `like`), а имя, совпадающее с одним из ваших предметов, просто становится этим предметом. Ответ сообщает Game Master, что было изменено (никогда о параметре, который вы ему не показываете), а сведения о предмете показывают игроку каждое изменение. Игра сохраняет предмет, поэтому то же имя означает этот предмет до конца игры, а новая сессия сохраняет его, пока он у кого-то есть.
- Game Master может выполнять `equip` и `unequip` для ваших предметов своей командой инвентаря, если у вас есть `slots`, а также `bind` и `unbind`, если у вас есть `binding`: ему сообщают только о тех, что есть в вашем наборе. Он видит нагрузку каждого персонажа, привязанные предметы и слоты, а также что надето или привязано.

- **Действие предмета, пока он надет или при себе**, показывается на выбранной стопке и в окне выбора ("While worn: -1 on checks (Sneak)"), и Game Master видит его рядом с предметом (`worn: -1 on checks (Sneak)`). Проверки вне боя его применяют (см. Проверки вне боя ниже).
- **Действие оружия** показывается так же ("Attack (Action): Brawn to hit, 1d6 + Brawn cut damage"), и бой предлагает его, пока оружие в руках (см. Оружие в бою ниже).
- **Действие использования предмета** показывается так же ("Use (Action): heals 1d4 + 1, range 0 paces, used up") вместе с оставшимися зарядами. Его предлагает бой, а также кнопка **Use** (использовать) в инвентаре и команда Game Master `[inventory: action="use"]` (см. Использование предметов в бою и Использование предметов вне боя ниже).

В боях Classic и Tactical каждый ваш предмет с `use` делает там то, что в нем сказано, а предмет без него не предлагается (см. Предметы в боях Classic и Tactical ниже). Что бы ни говорил `native`, лист может читать ваши предметы (ниже), удерживаемое оружие является атакой в бою по набору правил и стреляет тем, что берет из сумки, действие надетого или носимого предмета учитывается в таком бою (см. Доспехи и эффекты надетого в бою ниже), предмет с `use` используется по собственным правилам в бою и вне его (см. Использование предметов в бою и Использование предметов вне боя ниже), а ваши `currencies` – деньги отряда (см. Деньги ниже).

<a id="items-on-the-sheet"></a>

### Предметы в листе

Ссылка на значение может читать предметы персонажа через `itemStat` (Capability API 1.52). Ember Roads прибавляет защиту доспеха, надетого путником, к его Guard – числу, которое должен превзойти удар:

```json
{
  "id": "guard",
  "label": "Guard",
  "op": "sum",
  "of": [{ "const": 6 }, { "abilityMod": "wits" }, { "itemStat": { "stat": "guard", "from": "worn", "pick": "sum" } }]
}
```

- `from`: `"worn"` – предметы на персонаже: предмет, занимающий слоты, пока он надет, предмет с `binds`, пока он привязан, и предмет с обоими свойствами, пока выполнены оба условия. Предмет без этих свойств никогда не считается надетым. `"carried"` – остальное, что у него есть, а `"all"` – и то и другое.
- `pick`: `"sum"` складывает значение каждого предмета, умноженное на их количество, `"max"` и `"min"` читают наибольшее или наименьшее отдельное значение, а `"count"` считает предметы по их количеству.
- `stat` называет один из ваших параметров предметов. `sum`, `max` и `min` требуют параметра `number`. `count` может не указывать его, чтобы считать все предметы, или назвать любой параметр, чтобы считать только предметы, которые его дают.
- `slot`, `category` и `tag` (каждый необязателен) оставляют только предметы, которые занимают этот слот, относятся к этой категории или несут эту метку.
- `default` (необязательно, по умолчанию 0) – значение, если не выбран ни один предмет или ни один из них не дает параметр.

Предметы меняются в игре, поэтому `itemStat` подчиняется тому же правилу, что чтение текущего состояния: `max` запаса или шкалы, бонус мастерства, `binding.max`, числа `carry` и масштабируемый столбец или масштабирование каталога не могут его читать даже через производное значение. Везде, где читается число, он доступен: производное значение, `adjust` проверки, `cap` навыка, защита, поглощение или инициатива в бою.

Предметы персонажа – те, что в его собственной сумке. Карточка игрока (та, что соответствует персонажу, за которого играют в чате, иначе первая) читает сумку игрока, а каждая другая карточка – свою. Учитываются только предметы вашего набора, поскольку у простого предмета нет параметров для чтения. Лист на экране, проверка, блок листа Game Master и бой в момент начала читают то, что есть у каждого персонажа в этот момент. Вне игры, в редакторе листа или при обзоре импорта, ни у кого ничего нет, и `itemStat` читает свой `default`.

<a id="checks-outside-a-fight"></a>

### Проверки вне боя

Проверка или спасбросок, которые Game Master запрашивает вне боя, читают не только лист: собственные активные состояния персонажа, достигнутые им уровни, действие его предметов, пока они надеты или при себе, и цену требований надетого предмета, пока персонаж им не соответствует. Это тот же словарь, что у состояний в бою (Capability API 1.53 для ключей предметов и сужения).

Предмет описывает свое действие через `worn`, которое действует, пока он надет (и привязан, если привязывается), и `carried`, которое действует, пока его просто несут с собой. Кожаный плащ из Ember Roads скрипит, когда его владелец крадется, а путевой камень внушает доверие караванщикам:

```json
"worn": { "modifiers": [{ "to": "checks", "skills": ["sneak"], "flat": -1 }] }
```

```json
"carried": { "modifiers": [{ "to": "checks", "skills": ["sway"], "flat": 1 }] }
```

Каждый из них принимает те части состояния, которые читает проверка:

- `effects`: `own-checks-advantage`, `own-checks-disadvantage`, `own-saves-advantage` и `own-saves-disadvantage`.
- `modifiers`: изменения `to` проверок или спасбросков с `flat`, `dice` (и `minus`), `mode` и собственными `skills` или `saves`, точно как у состояния.
- `failsSaves`: спасброски, которые носитель проваливает без броска.
- `skills` и `saves`: к каким навыкам или спасброскам относятся эффекты и модификаторы, не называющие собственных.
- `abilities` (Capability API 1.54): изменяемые характеристики по id, каждая `{ "set": N }` (не меньше N: более высокий показатель сохраняется) или `{ "add": N }` (отрицательное число понижает). Они применяются до вычисления листа, поэтому все, что читает характеристику, читает измененную: лист на экране, производные значения, проверки, блок листа Game Master и бой в момент начала. Сначала применяются прибавки, затем наибольшее `set`, а собственные `min` и `max` характеристики соблюдаются. Максимум запаса или шкалы и бонус мастерства вычисляются только по листу, поэтому предмет их не сдвигает.

Рукавицы из бычьей кожи в Ember Roads дают слабой хватке силу погонщика:

```json
"worn": { "abilities": { "brawn": { "set": 2 } } }
```

Действие предмета в бою (защита, атаки, скорость, другие эффекты боя, а также вред и состояния, от которых он защищает) описано в разделе [Доспехи и эффекты надетого в бою](#armor-and-worn-effects-in-a-fight); проверка вне боя читает только перечисленные выше части. Один предмет действует один раз, сколько бы его стопок ни было у персонажа.

Предмет может также предъявлять требование к носителю через `requires`: значение из его листа (`value`, любая ссылка на значение, читаемая так же, как все в игре), наименьшее допустимое значение (`atLeast`) и то, что действует, пока носитель не соответствует (`otherwise`, в том же словаре, но без изменения характеристик, поскольку требование может их читать). До четырех. Могильная лопата из Gravewatch – тяжелая работа для слабого стража:

```json
"requires": [
  {
    "value": { "abilityScore": "sinew" },
    "atLeast": 3,
    "otherwise": { "modifiers": [{ "to": "checks", "skills": ["dig"], "flat": -1 }] }
  }
]
```

Требование читает характеристику такой, какой ее оставляют предметы носителя, поэтому рукавицы, задающие Sinew 3, удовлетворяют требованию лопаты.

В проверке:

- Каждый относящийся к ней модификатор добавляет свое число, а его кости бросаются: постоянное число для суммируемой проверки, кости для пула. Проверка характеристики и проверка, которую набор не может назвать, читают только то, что не сужено ни до чего, а спасбросок читает только относящееся к спасброскам.
- Преимущество и помеха из всех источников, включая `mode=` от Game Master, взаимно отменяются: при наличии и того и другого проверка бросается один раз. Преимущество или помеха действуют только в наборе, который вообще бросает дважды (`resolution.advantage`).
- Спасбросок, проваливаемый состоянием или предметом, проваливается без броска, и на него ничего не тратится.
- Запись броска сообщает, что ее изменило: `effects="-1"` для числа, `from="Leather coat"` для того, что изменило, и `automatic="true"` для спасброска, проваленного без броска. Карточка броска показывает то же, и Game Master читает это на следующем ходу. Ему сообщают, что Engine применяет это сам, поэтому он не добавляет это повторно.

Gravewatch показывает то же на пуле: привязанный Dawn bell добавляет кость к Ward, а Rattled отнимает одну от Soothe и Barter.

<a id="weapons-in-a-fight"></a>

### Оружие в бою

Предмет может быть оружием (Capability API 1.55). Его `attack` имеет форму [строк атак](#combat-a-fight-your-own-rules-resolve) боевого блока, со значениями вместо столбцов, и [бой по набору правил](#combat-a-fight-your-own-rules-resolve) предлагает его как атаку, пока предмет надет: удерживается в руках, которые он занимает, и привязан, если привязывается. Убранный или просто носимый с собой предмет ничего не предлагает, а строки атак и собственные действия существа работают точно как раньше. Ручной топор из Ember Roads:

```json
"attack": {
  "budget": "act",
  "toHit": { "abilities": { "stat": "swing" } },
  "damage": { "dice": { "stat": "damage" }, "abilities": { "stat": "swing" }, "type": "cut" },
  "reach": 2,
  "range": { "normal": 10, "long": 20 }
}
```

- `budget`: расходуемый бюджет, один из `combat.economy.budgets`.
- `toHit`: что добавляется к попаданию. `abilities` – один или несколько id характеристик, и учитывается лучшая из них (у фехтовального оружия их две). `skill` добавляет то же, что проверка этого навыка, с характеристикой атаки вместо собственной характеристики навыка, как у строки атаки. `proficiency` – значение из листа владельца: если оно больше 0, добавляется бонус мастерства набора (`{ "const": 1 }` – всегда). `bonus` – число. `target` – собственный порог кости для атаки этим оружием в бою пулами (лопата из Gravewatch засчитывает каждую кость от 6, а не от 7, как пул), и задать его может только набор `dice-pool`, чей `target` может меняться; в бою на суммах то же выражает его `bonus`.
- `damage`: наносимые кости `dice`, лучшая из характеристик урона `abilities`, `bonus` и `type`. Бою на суммах нужно `dice`; в бою пулами попадание наносит свои успехи, а `dice` добавляет еще столько костей пула.
- `reach` и `range` (`normal` и `long` – насколько оно еще бьет дальше) задаются в единице `combat.distance` и требуют ее. Оружие с обоими значениями – метательное, как строка атаки: вблизи взмах, дальше бросок. Без обоих оно достает на одну клетку.
- `versatile`: кости `dice`, которые оно наносит вместо обычных, пока в каждом занимаемом им слоте есть место еще для такого же среди надетого владельцем: копье в одной руке при свободной другой.
- `strikes`: сколько ударов покупает один расход, из листа владельца, как `strikes` строки атаки. Оружие без него дает один удар за расход, сколько бы атак ни было у владельца.

Любое из этих чисел или слов может вместо этого читать собственный параметр предмета: `{ "stat": "damage" }` – это `damage` предмета, а параметр, который предмет не дает, равнозначен незаписанному значению. `abilities` и `skill` читают параметр-перечисление, чьи слова – id характеристик или навыков, а `type` – текстовый параметр или перечисление. Поэтому предмет, который Game Master придумывает `like=` оружию, тоже оружие и сражается собственными параметрами, ограниченными `rarityCaps`, как любой параметр (записанное вами значение копируется как есть). Придуманный предмет без слота и без привязки никогда не надет, поэтому создается без атаки. Небольшая модель склонна описывать оружие, не указывая `like=`, поэтому придуманный в категории вашего оружия предмет без основы сражается как ваше оружие этой категории, наиболее похожее по названию (общее слово в любую сторону, так что crossbow похож на bow), или как первое из них, беря любой читаемый этой атакой параметр, пропущенный в предложении, и ответ это сообщает ("It fights as Hand axe does."). Форма предложения Game Master также сообщает ему, что оружие, сделанное по образцу, сражается как образец.

Метки оружия – то, что несут его удары. Запись `resist` или `immune` существа может сообщать, что проходит сквозь нее: `{ "type": "tearing", "except": ["silver"] }` полностью принимается от оружия с меткой `silver` и уменьшается сопротивлением от всего остального. Так записан могильный упырь из Gravewatch, и серебряный гробовой гвоздь из того же набора его пробивает.

Сведения об оружии и строка Game Master сообщают, что оно делает: `attack (Action): Brawn to hit, 1d6 + Brawn cut, reach 2 paces, range 10 to 20 paces`, с `1d8 with a hand free` для кабаньего копья из Ember Roads и `at 6` рядом с лопатой из Gravewatch.

<a id="ammunition-and-reloading"></a>

#### Боеприпасы и перезарядка

Оружие может чем-то стрелять и может иметь собственный магазин (Capability API 1.57). Охотничий лук из Ember Roads стреляет стрелами, а караульный пистолет из Gravewatch вмещает одну пулю и заряжается порохом и пулями из сумки стража:

```json
"ammo": { "tag": "arrow", "recover": 0.5 }
```

```json
"ammo": { "tag": "shot" },
"clip": { "max": 1, "reload": "act" }
```

- `ammo`: чем стреляет оружие, по одной из ваших меток предметов (`tags`). Каждая атака забирает `perAttack` (1, если не указано) предметов с этой меткой, которые есть у владельца, надетых или нет, из первой такой стопки в его сумке, затем из следующей. Оружие предлагается, только пока их хватает, а меню боя показывает, сколько осталось. После победы отряда в бою `recover` (от 0 до 1) выпущенного каждым возвращается в ту стопку, откуда взято: доля суммируется за весь бой и округляется вниз один раз для каждой стопки, так что половина от пяти стрел из одного колчана – две. Проигранный бой или бегство ничего не возвращает.
- `clip`: магазин, который оружие держит при себе. `max` – сколько он вмещает, записанное числом или прочитанное из числового параметра предмета, а `reload` – бюджет, который тратит перезарядка. Атака тратит заряженное вместо того, чтобы брать из сумки, и оружие предлагается, только пока заряжено достаточно для одной атаки. Вариант **Reload** (перезарядить) в меню боя тратит `reload` и заполняет магазин: из сумки, если у оружия есть `ammo` (столько, сколько осталось в сумке, если этого меньше), и полностью, если боеприпасов у него нет. Число хранится в стопке оружия в инвентаре, поэтому пистолет, опустошенный в одном бою, остается пустым в следующем. Оружие, из которого еще никто не стрелял, заряжено, как и то, которое игрок объединяет в стопку из нескольких таких же, поскольку заряженное число принадлежит одному оружию. Выпущенное из магазина не подбирается после боя, поэтому `recover` – для оружия без магазина.

Все, что бой выпускает, заряжает и подбирает, записывается в инвентарь на каждом шаге, как здоровье отряда, а журнал приключений сообщает, что было использовано. Шаг, чья стопка исчезла или содержит меньше, чем рассчитывал бой, отклоняется, как и потраченный предмет, который бой не может найти. Журнал боя сообщает о каждом выстреле, перезарядке и подборе ("Hunting bow: 2 left to shoot.", "Ada loads 1 into Watch pistol: 1 of 1 loaded."), а сведения о предмете и строка Game Master сообщают, чем стреляет оружие и что вмещает: `ammunition Arrow (1 an attack, 50% picked up after a won fight)` и `holds 1, reload (Act)`.

<a id="modes-a-second-weapon-a-floor-and-conditions-on-a-hit"></a>

#### Режимы, второе оружие, нижний предел и состояния при попадании

Оружие может иметь другие способы атаки, напарника во второй руке, наименьший наносимый вред и состояния, которые оно накладывает на пораженного (Capability API 1.58). Охотничий лук из Ember Roads может дать залп, а серебряный гробовой гвоздь из Gravewatch можно держать в каждой руке, и он метит тех, кого глубоко ранит:

```json
"modes": [{ "id": "volley", "label": "Volley", "ammo": 2, "toHit": -2, "targets": 2 }]
```

```json
"offHand": true,
"onHit": [{ "condition": "marked", "atLeast": 2, "rounds": 2 }]
```

- `modes`: до шести других способов атаки, каждый с `id`, `label` и тем, что он меняет. `ammo` – сколько выпускает одна атака в этом режиме, поэтому у оружия должны быть `ammo` или `clip`, из которых стрелять. `toHit` – что добавляется к попаданию: кости в бою пулами и число в бою на суммах. `target` сдвигает порог кости в бою пулами на эту величину (от собственного порога оружия, иначе от порога пула; `+1` – сложнее), если порог пула может меняться. `targets` – на сколько целей его можно направить, каждая со своим броском атаки. Меню боя спрашивает о способе после выбора атаки (после ее стиля инициативы, если стили есть), показывая для каждого ожидаемый результат, и предлагает только режимы, на которые у владельца хватает выстрелов. Участник отряда под управлением Engine оценивает каждый режим, направленный на одну цель, а режим на несколько целей оставляет игроку. В окне атака совершается как есть.
- `offHand`: оружие для второй руки. Боевой блок называет бюджет, который тратит вторая атака, и сохраняет ли ее урон положительную характеристику:

  ```json
  "offHand": { "budget": "quick", "ability": "full" }
  ```

  Как только владелец атаковал в этом ходу одним оружием с отметкой `offHand`, каждое другое такое оружие на нем предлагает вторую атаку за этот бюджет, названную в меню "Silver coffin nail, off hand". `ability` – `full` (по умолчанию) или `penalty-only`, при котором характеристика урона добавляется, только если она что-то отнимает, как правило боя двумя оружиями в 5e. Атака второй рукой – один удар, сколько бы ударов ни покупала основная атака, и никогда не удар по уходящему. Оружию с отметкой `offHand` нужен `offHand` боевого блока.
- `floor`: наименьший вред при попадании, записанный числом или прочитанный из числового параметра предмета. Вред после поглощения в бою пулами или урон в бою на суммах поднимается до него до того, как сопротивление его уполовинит, и журнал это сообщает. Тратящий удар бросает число атакующего и никогда не поднимается.
- `onHit`: до четырех ваших состояний, которые получает цель, когда вред удара достиг `atLeast`, на `rounds` ее собственных ходов или, без этого, пока что-то их не снимет. Учитывается вред, дошедший после поглощения и сопротивлений цели; забирающий удар отнимает инициативу, а не наносит вред, поэтому состояний не накладывает.

Сведения об оружии и строка Game Master сообщают все это: `modes Volley (2 shots, -2 to hit, up to 2 targets)`, `off hand (Quick)`, `at least 1 on a hit before resistance` и `Marked for 2 rounds when a hit deals 2 or more`.

<a id="armor-and-worn-effects-in-a-fight"></a>

### Доспехи и эффекты надетого в бою

Действие предмета, пока он надет или при себе, может менять и бой (Capability API 1.56) для его владельца, наряду с его состояниями и уровнями. Каждый из блоков принимает те части состояния, которые читает бой:

- `effects`: любые эффекты состояния, кроме четырех, которых не может быть у уровня (`half-move-to-stand`, `ends-on-damage`, `cannot-target-source`, `cannot-approach-source`), поскольку предмет на владельца никто не накладывал и сам он не заканчивается: `own-attacks-advantage`, `attacks-against-disadvantage`, `resist-all`, `speed-zero` и остальные.
- `modifiers`: изменения `to` защиты, атак и скорости, а также проверок и спасбросков, точно как у состояния; в бою `dice-pool` изменение атак – постоянное число костей, как у состояния.
- `resist`, `vulnerable` и `immune`: виды вреда, которые владелец получает наполовину, вдвое или не получает вовсе, как у существа (и проверяемые по `combat.damageTypes`, если вы их объявили). `conditionImmunities`: ваши состояния, которые никогда не накладываются на владельца.

Проклятое вдовье кольцо из Gravewatch стоит кости при каждой атаке, привязанный Dawn bell из того же набора не дает носителю стать Rattled, а путевой камень из Ember Roads, носимый с собой, защищает от жара:

```json
"worn": { "modifiers": [{ "to": "attacks", "flat": -1 }] }
```

```json
"worn": { "modifiers": [{ "to": "checks", "skills": ["ward"], "flat": 1 }], "conditionImmunities": ["rattled"] }
```

```json
"carried": { "modifiers": [{ "to": "checks", "skills": ["sway"], "flat": 1 }], "resist": ["burn"] }
```

Бой читает каждый предмет один раз, называя его по стопке ("Widow's ring" рядом с броском в журнале и у защиты), как и проверка; `otherwise` невыполненного требования тоже учитывается в бою, поэтому слишком тяжелый для носителя доспех может стоить скорости. Сведения о предмете и строка Game Master сообщают все это ("While worn: -1 on attacks", "worn: +1 on checks (Ward), immune to Rattled"). Доспех, который просто прибавляет к защите или поглощению, – это параметр предмета, читаемый через `itemStat` (см. Предметы в листе), так же как Guard в Ember Roads читает надетый плащ.

**Твердость.** Если инициатива – число, которое сдвигают атаки, `combat.pool.hardness` – твердость бойца, читаемая из его листа в начале боя (у доспеха – через `itemStat`), а существо задает собственную `hardness`. Тратящий удар, чьих костей меньше этого значения, попадает и ничего не делает: число атакующего все равно возвращается к базе, журнал это сообщает ("Ada's Grave spade lands on the warden with 5 dice, below a hardness of 6, and does nothing."), а меню не прогнозирует для него вреда. Твердость может быть только у набора со стилем, который тратит, а существо, записанное листом, берет ее из листа.

<a id="using-items-in-a-fight"></a>

### Использование предметов в бою

Предмет можно использовать в бою (Capability API 1.59): прижать припарку к ране, выпить настойку, позвонить в колокол. Его `use` описывает действие использования словами `mechanics` записи каталога (см. [Что бой читает из `mechanics`](#what-a-fight-reads-from-mechanics)): `kind` (`heal`, `attack`, `buff` или `debuff`), `amount`, `damageType`, `plus`, `attackRoll`, `save`, `applies`, `temporary`, `range`, `area`, `targets`, `targetCount` и `friendlyFire`, с расходуемым `budget` или `free`. Припарка из Ember Roads, а также согревающая настойка и колокол Dawn bell из Gravewatch:

```json
"use": { "kind": "heal", "budget": "act", "range": 0, "targets": "ally", "amount": { "dice": "1d4", "flat": 1 }, "consumes": true }
```

```json
"use": { "kind": "heal", "budget": "quick", "targets": "self", "amount": { "flat": 1 }, "consumes": true }
```

```json
"stack": 1,
"use": {
  "kind": "debuff",
  "budget": "act",
  "targets": "enemy",
  "save": { "save": "steel", "onSuccess": "negates" },
  "saveDifficulty": 7,
  "applies": [{ "condition": "rattled", "duration": { "rounds": 2 } }],
  "charges": 1
},
"charges": { "max": 3 }
```

- Использование находится в меню боя в разделе **Items** (предметы) и называется по предмету ("Poultice"), как бы ни называлась стопка. Предмет, занимающий слоты или привязываемый, используется, пока надет (и привязан, если привязывается), как колокол; любой другой – пока его несут с собой.
- Оно тратит бюджет или является `free` и оплачивается самим предметом: `cost`, `perCostStep`, `check`, `concentration`, `reaction`, `scales`, `gives`, `standard` и `rider` предназначены для записи каталога в листе и в использовании отклоняются.
- `toHit` в использовании с `attackRoll` – что добавляется к попаданию, так же как в `toHit` оружия (см. Оружие в бою): характеристики, навык, бонус и, в бою пулами, порог кости. Без него бросок ничего не добавляет.
- `saveDifficulty`: число, против которого бросается запрашиваемый спасбросок (собственный, снимающий наложенное состояние или спасбросок составляющей без `difficulty`), записанное или прочитанное из числового параметра предмета. Запись в листе читает это число из источника своего каталога; у предмета его нет, поэтому он задает свое.
- `consumes: true` при каждом использовании убирает один предмет из стопки, а меню показывает, сколько осталось. Последний использованный забирает стопку с собой.
- `restore` (Capability API 1.60) возвращает часть запаса каждого листа, на который приходится использование, как пакет крови возвращает кровь: `{ "pool": "resolve", "amount": { "flat": 1 } }`, с `dice` и `flat`, как у `amount`. Он называет один из ваших текущих запасов, но никогда не запас здоровья (здоровье возвращает лечение), и бывает у полезного использования – `heal` или `buff`. У существа нет запасов, поэтому оно ничего не получает. Журнал это сообщает ("Ada gets back 1 Resolve, and is on 3 of 4."), а участник отряда под управлением Engine не трогает полный запас. Согревающая настойка из Gravewatch вместе с лечением восстанавливает очко Resolve.
- `charges` тратит столько собственных зарядов (`charges`) предмета, `max` которых – сколько он вмещает, от 1 до 100, записанное или прочитанное из числового параметра предмета (предмет, дающий этот параметр меньше 1, отклоняется, а больше 100 – вмещает 100). Число хранится в стопке предмета в инвентаре, поэтому колокол, в который дважды позвонили в одном бою, в следующем имеет один заряд, а колокол, в который никто не звонил, полон. Заряды принадлежат одному предмету, поэтому у предмета с ними `stack` равен 1. Использование либо расходует предмет, либо тратит заряды, но никогда не то и другое, а заряды предмета всегда тратятся его использованием. У `charges` есть еще два ключа (Capability API 1.61), как у колокола Dawn bell из Gravewatch:

  ```json
  "charges": { "max": 3, "recharge": { "rests": ["vigil"], "amount": "max" }, "breaksOn": { "die": 20, "atMost": 1 } }
  ```

  - `recharge`: какие из ваших `rests` возвращают заряды и сколько: `"max"` заполняет предмет, а количество (`{ "dice": "1d6", "flat": 1 }`) возвращает столько, но не больше `max`. Отдых возвращает заряды каждого предмета своего персонажа, который его называет, будь то кнопка Rest листа или команда Game Master `[sheet: op="rest"]`; лист и сумка записываются вместе, а перегенерированный ответ восполняет заряды только один раз. Лист сообщает, что вернулось после отдыха ("Dawn bell 3/3 charges"), а Game Master видит оставшиеся заряды каждого предмета рядом с ним в инвентаре ("2 of 3 charges left").
  - `breaksOn`: когда использование тратит последний заряд, Engine бросает d`die`, и при результате не выше `atMost` предмет ломается и исчезает из сумки, в бою и вне его. Журнал боя это сообщает ("Dawn bell breaks (a 1 on its die)."), отчет кнопки Use – тоже ("Its last charge spent, it breaks."), а журнал приключений учитывает предмет как потерянный.
- `gate` (Capability API 1.62) – проверка, которую пользователь проходит, прежде чем предмет сработает, как свиток заклинания выше уровня читающего требует проверки. `check` называет бросок: `{ "skill": "ward" }`, `{ "ability": "wits" }` или значение из листа (`{ "value": { "derived": "spell_mod" } }`) – для числа, которое отличается у разных персонажей, как модификатор заклинаний заклинателя 5e. `difficulty` – от 1 до 100, записанное или прочитанное из числового параметра предмета (предмет, который его не дает, не попадает в меню, а его кнопка Use прямо об этом говорит). `unless` пропускает проверку, если значение в листе пользователя не меньше `atLeast`. Проваленная проверка расходует предмет (или тратит его заряды) впустую. В бою проверка бросается в момент траты предмета костями самого боя (пулом в бою пулами, где `difficulty` – нужное число успехов) с числом листа, прочитанным в начале боя, и учитывается то, что добавляют к этой проверке состояния и надетые предметы пользователя, включая то, что относится именно к этому навыку. Журнал это сообщает ("Ada rolls Ward to use Page of the vigil litany: 2 successes from 2 dice at 7 or more (8, 9), needing 2 successes, a success."). Такая проверка есть у Page of the vigil litany из Gravewatch:

  ```json
  "gate": { "check": { "skill": "ward" }, "difficulty": 2, "unless": { "value": { "abilityScore": "nerve" }, "atLeast": 3 } }
  ```

Расходуемое в бою и оставшиеся заряды записываются в инвентарь на каждом шаге, как выстрелы оружия, а журнал приключений сообщает, что было использовано. Журнал боя сообщает о каждом использовании ("Poultice: 1 of 2 left.", "Dawn bell: 2 of 3 left."). Участник отряда под управлением Engine применяет лечение только к раненому, и никто не использует предмет для удара по уходящему. Сведения о предмете и строка Game Master сообщают, что делает использование: "Use (Action): heals 1d4 + 1, range 0 paces, used up" и `use (Act): Steel 7 save negates it, Rattled, 1 of 3 charges`, а сведения показывают оставшиеся заряды. Предмет, который Game Master придумывает `like=` вашему, используется как образец, со всеми зарядами.

### Предметы в боях Classic и Tactical

Набор, который не разрешает собственные бои, оставляет их встроенным боям Classic и Tactical режима Game Mode, где в начале боя модель спрашивают, что делают предметы инвентаря. Ваши предметы не угадываются: каждый с `use` делает то, что в нем сказано, на собственных числах Engine, а предположение Game Master запрашивается только для предметов не из вашего набора (и ни для каких при `native: false`).

- `heal` лечит, а `attack` наносит вред долей максимального здоровья цели, исходя из среднего значения `amount`: среднее 7, как у базового оружия `1d8+3`, – чуть больше пятой части, никогда не меньше двадцатой и не больше всего здоровья. В такой шкале мост к бою читает числа записи каталога. `damageType` становится стихией.
- Первое состояние в `applies` накладывается как статус под собственным именем на свои `rounds` (2 без них), а `buff` или `debuff` – это только этот статус, который повышает или понижает защиту, как собственные статусы Engine.
- `targets` сообщает, на кого применяется предмет. Без него лечение или усиление достается другу, а атака или ослабление – врагу.
- `consumes: true` убирает один предмет из стопки, а использование без него оставляет предмет на месте.
- Броску попадания, спасброску, области, временным очкам и восстановленному запасу в этих боях нет места, как и `mechanics` записи каталога там: описание предмета в меню все равно их упоминает.
- Предмет, занимающий слоты, используется, только пока надет, а привязываемый – только пока привязан, как в бою по набору правил. Расходуемый предмет берется из надетого, никогда из запасного в сумке.
- Предмет, чье использование тратит `charges`, предлагается, пока остается использование, а меню Items считает его использования. Каждое использование тратит их из стопки предмета, сначала собственной стопки игрока, а последнее потраченное бросает его `breaksOn`: сломанный предмет исчезает из сумки, а журнал приключений учитывает его как потерянный.
- Для предмета, требующего сначала проверки (`gate`), проверка бросается на сервере, когда его использует участник отряда, по листу этого участника и тому, что на нем надето (спутник без собственной карточки бросает по пустому листу, и только собственный юнит игрока использует карточку игрока), как ее бросает кнопка Use, и пропускается, если выполнено `unless`. При провале предмет тратится (или тратятся его заряды) и ничего не делает, и журнал это сообщает: "Ada rolls Ward to use Page of the vigil litany: 0 against 2, failed, and it is used up for nothing."
- Предмет без `use` в этих боях не предлагается, как и лечение без `amount`.

Engine сам вычисляет действие каждого предмета, поэтому присланное экраном никогда не решает, что делает ваш предмет.

### Добыча

Выигранный бой в любой игре Game Mode один раз оставляет добычу, которая попадает в сумки отряда. Без набора правил она берется из собственных таблиц Game Mode (больше и реже на более сложной игре), как и в наборе, который не объявляет таблиц добычи и оставляет `native` включенным. Набор, объявляющий таблицы добычи, вместо этого выдает собственные предметы, а набор с `native: false` и без таблиц ничего не выдает.

`lootTables` в блоке `items` (Capability API 1.63) перечисляет их, как погребальные дары в Gravewatch:

```json
"lootTables": [
  {
    "id": "grave_goods",
    "label": "Grave goods",
    "rolls": "1d2",
    "entries": [
      { "item": "kit/shot-and-powder", "weight": 4, "count": "1d4" },
      { "item": "kit/warming-tonic", "weight": 3 },
      { "item": "kit/litany-page", "weight": 2 },
      { "filter": { "category": "arm" }, "weight": 1 },
      { "coins": "shilling", "weight": 2, "count": "1d6" }
    ]
  }
]
```

- `rolls` – сколько выборов делает таблица: число от 0 до 20 или кости (`"1d2"`), по умолчанию 1.
- Каждый выбор вытягивает одну строку по `weight` (по умолчанию 1) относительно остальных. Строка называет один из ваших предметов как `<catalog>/<entry>`, `filter` по `rarity`, `category` и `tag`, равновероятно выбирающий среди всех подходящих предметов, или (Capability API 1.64) `coins` – одну из ваших монет по id. `count` – сколько выпадает, число или кости, по умолчанию 1. Предмет или монета, которые убирает слой, ничего не дают, как и фильтр, не нашедший ни одного предмета.
- Существо бестиария называет свою таблицу через `loot` (см. Существа ниже). Выигранный бой по набору правил бросает таблицу каждого побежденного существа, а в бою, который Engine не разрешает по вашим правилам, существ бестиария нет, поэтому ничего не выпадает.
- Выпавшее попадает в общий вид как добавление, сначала спрашивается сумка игрока, а то, что никто не может нести, остается на месте. Сводка, которую получает Game Master, сообщает, что выпало и что это уже в сумках, журнал приключений это отмечает, и появляется уведомление.
- Game Master бросает таблицу в истории командой `[loot: table="grave_goods" who="Ada"]` (`who=` – в сумку одного персонажа), отсчитываемой от начала хода, как его теги инвентаря, поэтому перегенерированный ответ выдает добычу один раз. На каждый выпавший предмет дается ответ как на добавление, а инструкции этой команды перечисляют ваши таблицы.

### Деньги

Ваши `currencies` – деньги отряда. Монета – предмет в сумках, стопка каждой монеты как любая другая, названная по `label`:

- Она весит одну единицу параметра переноски на каждые `perWeight` монет своего семейства, учитывается в нагрузке носителя и при поступлении распределяется по правилу переноски. Семейство без `perWeight` ничего не весит.
- Игрок добавляет монеты из списка **Coins** (монеты) окна выбора, а разделяет, отдает и объединяет их, как любую стопку.
- Строка над стопками инвентаря показывает монеты каждого семейства в текущем виде и их стоимость в самой мелкой монете семейства. Game Master видит эту стоимость рядом с каждой сумкой (`Coin worth 432 pennies` или `no coins` для пустого кошелька, причем сумка игрока перечисляется, даже если пуста), а `cost` предмета – рядом с предметом (`costs 3 shillings`).
- Game Master платит командой `[inventory: action="pay" amount="3 shillings" who="Ada"]` и получает плату через `action="earn"`. `amount` – количество и монета по id или подписи, в единственном или множественном числе, в любом регистре (`1 penny`, `12 pennies`). Платеж берется из одной сумки (игрока без `who=`) и только в семействе самой монеты: сначала уходят самые крупные подходящие монеты, затем разменивается самая мелкая оставшаяся монета, покрывающая остаток долга, и сдача возвращается более мелкими монетами семейства, начиная с крупнейших. Ответ сообщает, что заплачено и что вернулось: 3 shillings из кошелька с одной crown – это `Paid with crowns ×1; shillings ×2 back.` Платеж, который сумка не может покрыть, отклоняется (`cannot-afford`), как и монета, которой у вас нет (`unknown-coin`), и любой платеж в наборе без валют (`no-currencies`). Заработок – добавление этой монеты в сумку `who` или распределение по правилу переноски. Журнал приключений перечисляет потраченное и заработанное, и появляется уведомление. Инструкции перечисляют ваши монеты, и есть они только у набора с валютами.
- Покупка – это платеж и затем добавление, а в наборе с рынком – `buy` (ниже). Экрана магазина нет.

### Рынки

`market` в блоке `items` (Capability API 1.65) сообщает, что продает место и по какой цене, вместо того чтобы каждая лавка продавала все по прейскуранту. Рынок Gravewatch, немного сокращенный:

```json
"market": {
  "prices": [
    { "id": "cheap", "label": "cheap", "times": 0.75 },
    { "id": "fair", "label": "fair", "times": 1, "default": true },
    { "id": "dear", "label": "dear", "times": 1.5 }
  ],
  "places": [
    { "id": "hamlet", "label": "hamlet" },
    { "id": "village", "label": "village" },
    { "id": "town", "label": "market town" },
    { "id": "city", "label": "city" }
  ],
  "sold": [
    { "filter": { "rarity": "rare" }, "place": "town" },
    { "filter": { "category": "arm" }, "place": "village" }
  ],
  "sellers": [
    { "id": "chandler", "label": "chandler", "sells": [{ "category": "coat" }, { "category": "tonic" }] },
    { "id": "smith", "label": "smith", "sells": [{ "category": "arm" }], "place": "village" },
    {
      "id": "chapel",
      "label": "chapel of the Vigil",
      "sells": [{ "category": "page" }],
      "place": "town",
      "only": { "value": { "abilityScore": "nerve" }, "atLeast": 3, "label": "wardens of Nerve 3 or more" }
    }
  ]
}
```

- `prices`: от одного до восьми уровней цен, каждый – множитель (`times`, больше 0) к `cost` предмета, и один из них – `default`. Цена – стоимость в самой мелкой монете семейства, умноженная на уровень и округленная в этой монете (никогда не меньше одной монеты для того, что что-то стоит), и называется в монете, в которой записана стоимость, если эта монета покрывает ее ровно, иначе в самой крупной оставленной вашими слоями монете, которая это делает: на уровне `dear` плащ стоимостью 8 shillings стоит 12 shillings, а зелье 5e стоимостью 50 gp – 50 gold pieces, но никогда не 5 platinum. Торг или настроение продавца сдвигают уровень, но никогда не число.
- `places`: от одного до двенадцати размеров мест, от наименьшего, вашими словами.
- `sold`: правила для наименьшего места, где продается то, что выбирает фильтр. Фильтр называет `rarity`, `category` и `tag`, любые из них, и подходит предмету, у которого есть все названные; решает первое подходящее предмету правило. Собственный `sold` предмета главнее правил, а предмет, которого ничто не называет, продается везде.
- `sellers`: виды продавцов, каждый с тем, что он продает (`sells` – фильтры, любой из которых выбирает предмет), наименьшим местом `place`, где он есть (везде, если не указано), и при необходимости тем, кому он продает (`only`): значение из листа покупателя, с его текущим состоянием и тем, что он несет, не меньше `atLeast`, сообщаемое Game Master как `label`. Без `sellers` любой в месте продает все, что продается в этом месте.
- Предмет без `cost` не продается, как и предмет, который скрывает слой, или предмет, чьи монеты убрал слой.

**Где находится отряд.** Game Master сообщает, в каком месте сцена и какого оно размера, командой `[place: name="Millbrook" size="market town"]`, размер – по id или подписи, и опускает размер для места без рынка (дорога, глушь). Engine отвечает на каждый тег на месте, отклоняя размер, которого у вас нет, а последнее место, на которое он ответил в собственных видимых игроку ответах с последнего начала разговора, остается текущим, пока не названо другое. Тег места, введенный игроком, никогда не учитывается. Перегенерированный ответ читает только то, что было до замещаемого им сообщения.

**Покупка.** Game Master покупает командой `[inventory: action="buy" item="Hand axe" count="1" level="dear" seller="smith" who="Ada"]`; `level` (без него – по умолчанию) и `seller` (без него – любой здешний продавец этого предмета) необязательны. Engine назначает цену по месту, текущему на момент окончания ответа, берет ее из кошелька покупателя (игрока без `who=`), как платеж, со сдачей, и кладет предмет в его сумку или только оплачивает услугу. Происходит либо и то и другое, либо ничего. Ответ сообщает цену (`price="12 shillings"`), что заплачено и что вернулось, и появляется уведомление. Покупка отклоняется и ничего не меняет, если место не названо (`no-place`), уровня, предмета или продавца у вас нет (`unknown-level`, `unknown-item`), нет цены (`not-for-sale`), место слишком мало для предмета (`not-here`), здесь нет продавца этого предмета (`no-seller`), покупатель не соответствует `only` продавца (`not-to-you`), кошелек не может покрыть цену (`cannot-afford`) или сумка не может вместить предмет.

**Что видит Game Master.** Пока сцена находится в месте с рынком, блок MARKET называет место и его размер, уровни цен и каждого здешнего продавца с дюжиной его товаров по уровню по умолчанию, от самых дешевых; все, что он продает, можно купить по имени. Его инструкции обучают `[place:]` и `buy`, и есть они только у набора с рынком.

#### Рыночный день

Рыночный день (Capability API 1.69) заставляет полки места меняться и пустеть и позволяет отряду продавать обратно. Пример Gravewatch, немного сокращенный:

```json
"places": [
  { "id": "hamlet", "label": "hamlet", "purse": { "amount": 10, "unit": "shilling" } },
  { "id": "town", "label": "market town", "purse": { "amount": 100, "unit": "shilling" } }
],
"buyBack": 0.5,
"sold": [{ "filter": { "rarity": "rare" }, "place": "town", "limited": "1d2" }],
"sellers": [
  { "id": "smith", "label": "smith", "sells": [{ "category": "arm" }], "stock": { "table": "smiths_odd_lot" } }
]
```

- **День.** День в месте длится, пока Game Master не назовет другое место; новый день в том же месте он начинает, назвав его снова с `day="new"` (`[place: name="Millbrook" size="market town" day="new"]`). Все ниже вычисляется для каждого дня по видимым игроку ответам Game Master, поэтому свайп, перегенерированный ответ или ветка не требуют ничего хранить, а день всегда дает одни и те же полки.
- **`limited`** в правиле `sold` или собственном `sold` предмета: сколько место держит в наличии за день – число или кости, бросаемые на день. Правило может назвать предел без места (продается везде, понемногу); место предмета берется из первого правила, называющего место, а предел – из первого, называющего предел. Когда они раскуплены, покупка отклоняется (`sold-out`) до нового дня.
- **`stock`** у продавца: одна из ваших таблиц добычи, бросаемая раз в день, – что есть у продавца в наличии сверх того, что он продает. Выпавшее (только предметы, никогда монеты) продает только этот продавец, столько, сколько выпало, что бы ни говорили `sells` и `sold`; `only` продавца по-прежнему действует.
- **`buyBack`**: доля (больше 0, не больше 1) цены предмета по умолчанию, которую платит за него продавец. Покупает его здешний продавец, продающий такие вещи (любой, если продавцов нет). Без `buyBack` никто ничего не выкупает.
- **`purse`** у размера места: сколько максимум его продавцы выплачивают за день, все вместе, в одной из ваших монет. Продажи, оплачиваемые в семействе этой монеты, учитываются в нем; без кошелька продавцы покупают без ограничений.
- **Продажа.** Game Master продает командой `[inventory: action="sell" item="Silver coffin nail" count="1" seller="smith" who="Ada"]`. Engine назначает цену, забирает предмет из сумки продающего (игрока без `who=`; никогда привязанный проклятый предмет) и кладет туда монеты, начиная с крупнейших, или отказывает и ничего не меняет: место не названо, никто здесь это не покупает (`not-bought`), нет цены (`not-for-sale`), сегодняшний кошелек исчерпан (`purse-spent`), такого предмета нет или сумка не может вместить монеты. Ответ сообщает, сколько выручено (`price="4 shillings"`), журнал приключений отмечает продажу, и появляется уведомление.
- Блок MARKET добавляет, что у каждого продавца есть в наличии сегодня, сколько осталось ограниченного предмета, сколько платят здешние продавцы и сколько осталось в сегодняшнем кошельке; его инструкции обучают `sell` и `day="new"`.

### Использование предметов вне боя

То же `use` работает вне боя (Capability API 1.60 для `restore`; остальному ничего нового не нужно). Кнопка **Use** в инвентаре для вашего предмета с `use` и команда Game Master `[inventory: action="use" item="Poultice" who="Juno"]` делают с тем, кто несет предмет, то, что делает предмет, костями Engine:

- Лечение возвращает здоровье: количество – в запас здоровья или одна снятая отметка на шкале ран, как лечение в бою. Очки `temporary` идут в запас здоровья, `restore` возвращает свой запас, а каждое состояние из `applies` накладывается, пока что-то его не снимет.
- Использование, наносящее вред или направленное на другую сторону (`kind` `attack` или `debuff` либо `targets` `enemy`), ни на кого не приходится: вне боя на поле некого бить. Предмет все равно используется, а Game Master сообщают, что он делает, чтобы это описать.
- Оно убирает один предмет из стопки или тратит заряды точно как в бою, а предмет без оставшихся использований, а также занимающий слот или привязываемый и не надетый, отклоняется и ничего не меняет. Лист и сумка записываются вместе.
- `gate` бросается первым, как проверка: собственными костями набора с числом листа, штрафом ран пользователя и тем, что его состояния и надетые или носимые предметы делают с этой проверкой. Проваленная проверка расходует предмет впустую, и строка это сообщает ("Ada uses Page of the vigil litany: Ward check 1 against 2, failed; it is used up for nothing. 1 left.").

Произошедшее сообщается одной строкой: "Juno uses Poultice: heals 4 (Grit 6/11). 1 left." Кнопка Use отправляет это Game Master в блоке `[item_used]` после "I use my Poultice.", который чат показывает значком; на собственный тег Game Master отвечают тем же, отсчитывая от начала хода, как его другие теги, поэтому перегенерированный ответ никогда не использует предмет дважды. Предмет без `use` или в игре без набора правил по-прежнему просто называется: "I use my rope."

<a id="battles-lending-the-sheet-to-marinaras-combat"></a>

## Сражения: передача листа боевой системе Marinara

По умолчанию сражение ничего не знает о листе. Оно создает бойцов как прежде, и персонаж может выйти из боя с неизменившимися очками здоровья в листе.

Необязательный блок `battle` меняет это только в одном направлении: передает бою числа листа и записывает результат обратно. **Он не заставляет бой следовать вашим правилам.** Математика костей остается за Marinara, как и определение того, кто кого поразил и на сколько. Поэтому здоровье переносится как доля максимума, а не ваше собственное число: персонаж с половиной здоровья в листе начинает бой с половиной полосы здоровья, которую построила для него Marinara. Ваш запас здоровья в 9 очков никогда не попадает напрямую в бой, где один удар наносит 12.

```json
"battle": {
  "health": { "pool": "grit" },
  "energy": { "pool": "luck" },
  "skills": [{ "list": "knacks" }]
}
```

- `health`: обязательно. Текущий запас, задающий очки здоровья персонажа в бою. Это должен быть один из запасов в `sheet.live.pools`, а не список, чьи строки служат запасами.
- `energy`: необязательно. Текущий запас, расходуемый в бою и становящийся полосой MP. Он должен отличаться от `health`, поскольку бой не может расходовать здоровье как топливо.
- `slots`: необязательно. Текущие запасы, которые бой расходует по одному, каждый с `level` от 1 до 9: `[{ "pool": "slots_1", "level": 1 }]`. Каждый уровень и каждый запас используются однократно.
- `skills`: необязательно, до восьми. Списки листа, чьи строки становятся боевыми навыками персонажа. Учитываются только строки из ваших каталогов и лишь когда исходная запись имеет блок `mechanics`: вручную набранная строка ничего не описывает в числах. `onlyWhen` указывает логический столбец, который должен быть включен в строке, например подготовленное заклинание. `alwaysWhen` указывает столбец и значение, пропускающие строку независимо от этого условия, например заклинания, не требующие подготовки. Это исключение из `onlyWhen`, поэтому без него оно отклоняется.

### Что передается в бой и что возвращается

**В бой**, для каждого участника отряда, чей лист есть у игры: доля текущего запаса здоровья от максимума задает начальную точку на собственной полосе здоровья Marinara, запас энергии становится MP, каждый запас ячеек становится ячейками своего уровня, а отмеченные строки – навыками. Максимум здоровья, атака, защита, скорость и уровень остаются собственными числами Marinara. Персонаж с нулем здоровья в листе начинает бой поверженным, как указано в листе; персонаж со здоровьем выше нуля никогда не начинает с менее чем одним очком, поэтому округление малой доли не может вывести его из строя.

**Из боя**, после его окончания: оставшаяся бойцу доля полосы здоровья переводится обратно в шкалу его запаса, а разница с началом боя применяется как урон или лечение. Энергия и ячейки – количества, а не доли, поэтому записываются как есть. Все проходит по тем же правилам, что используют кнопки листа; изменение, отвергнутое листом, пропускается с сообщением, а не навязывается. Бой, не изменивший здоровье бойца, вообще не записывает изменения здоровья, поэтому две конвертации сами по себе никогда не меняют лист.

**Ни в одну сторону**: броски атаки, спасброски, концентрация и прибавка от более высокой цены. Они хранятся в `mechanics`, чтобы однажды их прочла полноценная боевая система; этот мост их не применяет, и набор правил не должен заявлять обратное.

Брошенное сражение ничего не записывает обратно. Если удалить сообщение, в котором бой начался, или бой так и не закончится, лист останется прежним: боя не было.

### Как запись становится навыком

Блок `mechanics` записи каталога читается следующим образом:

- `kind` становится типом навыка. Записи `utility` и все с отметкой `reaction` исключаются: в боевой системе Marinara для них нет места.
- `amount` задает силу эффекта как множитель собственной атаки бойца, а не число урона. Более крупные кости никогда не дают более слабый удар, а множитель остается в диапазоне, уже используемом генерируемыми навыками.
- `range` и `area.size` делятся на `units.distance.perCell` каталога для получения клеток сетки и никогда не округляются до нуля. Взрыв становится своим радиусом, конус – половиной этого значения, линия – одной клеткой. Эффект с областью выбирает всех покрытых ею врагов; `friendlyFire` соблюдается.
- `damageType` становится стихией навыка. `targets` не переносится: боевая система Marinara определяет допустимые цели лечения, усиления или атаки по типу навыка.
- `cost` запаса энергии становится ценой MP, несколько затрат энергии суммируются. `cost` ровно одной ячейки расходует одну ячейку этого уровня. Боевая система Marinara берет одно количество энергии или одну ячейку, но не оба ресурса, поэтому запись ценой в две ячейки, ячейки двух уровней либо ячейку плюс энергию исключается из боя. То же касается затрат любого другого запаса, например здоровья или классового ресурса: иначе Engine выдавал бы эффект бесплатно.
- `buff` или `debuff` становится собственным усилением или ослаблением Marinara. Другие обещания текста записи, например снятие состояния в листе, в бою не выполняются. Не добавляйте `mechanics` записи, чей эффект имеет смысл лишь вне сражения.

`coverage.combat` остается отдельным и сохраняет прежний смысл: включайте его, только если сражения действительно следуют правилам вашей системы.

<a id="combat-a-fight-your-own-rules-resolve"></a>

## Бой: сражение, которое разрешают ваши правила

Блок `battle` выше передает бою числа листа, оставляя арифметику Marinara. Необязательный `combat` делает другое: задает, как ваши правила РАЗРЕШАЮТ бой. Он параметризует принадлежащий Engine вид боя, как `resolution` параметризует вид проверки; каждое имя внутри принадлежит вам. Видов два: `attack-vs-defense`, где кости складываются и сравниваются с числом, и `dice-pool`, где бой бросает собственные пулы вашего набора `dice-pool` и считает успехи (см. Бой пулами ниже).

**Игра, чей набор правил объявляет `combat`, сражается по вашему блоку.** Числа отряда читаются из собственных листов, противники берутся из вашего бестиария или шкалы угрозы, каждый ход разрешается вашими костями, а все расходы и потери персонажа сразу записываются в его лист: закрытие вкладки посреди боя ничего не теряет. Экран сражения использует ваши слова: ваши атаки и способности в меню, ваши бюджеты, состояния и журнал с реальной арифметикой. Пока отсутствующие возможности перечислены в разделе Пока нет.

```json
"combat": {
  "kind": "attack-vs-defense",
  "health": { "pool": "grit" },
  "defense": { "derived": "guard" },
  "initiative": { "dice": { "count": 2, "sides": 6 }, "modifier": { "abilityMod": "wits" } },
  "attackRoll": { "dice": { "count": 2, "sides": 6 } },
  "economy": { "budgets": [{ "id": "act", "label": "Action", "per": "turn", "count": 1 }] },
  "attacks": [
    {
      "list": "gear",
      "budget": "act",
      "name": "name",
      "toHit": { "ability": { "column": "swing" } },
      "damage": { "dice": { "column": "damage" }, "ability": { "column": "swing" }, "type": { "column": "harm" } }
    }
  ],
  "abilities": [{ "list": "knacks", "budget": "act" }],
  "standard": ["dodge", "help"],
  "conditions": [
    { "condition": "shaken", "effects": ["own-attacks-disadvantage", "ends-on-damage"] },
    { "condition": "pinned", "effects": ["cannot-act", "speed-zero"] }
  ]
}
```

Это весь блок Ember Roads, по которому сражается игра на Ember Roads. Черновик 5e использует те же ключи для системы d20:

```json
"combat": {
  "kind": "attack-vs-defense",
  "health": { "pool": "hp" },
  "defense": { "field": "ac" },
  "initiative": { "dice": { "count": 1, "sides": 20 }, "modifier": { "derived": "initiative" } },
  "attackRoll": {
    "dice": { "count": 1, "sides": 20 },
    "advantage": true,
    "naturals": { "max": "critical", "min": "miss" },
    "critical": "double-dice"
  },
  "economy": {
    "budgets": [
      { "id": "action", "label": "Action", "per": "turn", "count": 1 },
      { "id": "bonus", "label": "Bonus action", "per": "turn", "count": 1 },
      { "id": "reaction", "label": "Reaction", "per": "turn", "count": 1 }
    ],
    "movement": { "field": "speed" }
  },
  "abilities": [
    {
      "list": "spells",
      "onlyWhen": "prepared",
      "alwaysWhen": { "column": "level", "equals": 0 },
      "budget": "action",
      "toHit": { "derived": "spell_attack" },
      "saveDifficulty": { "derived": "spell_save_dc" }
    }
  ],
  "concentration": { "text": "concentration", "save": "con_save", "floor": 10, "fromDamage": 0.5 }
}
```

### Все ключи

- `kind`: `"attack-vs-defense"` (одна сторона бросает кости против защиты другой; попадание наносит урон) или `"dice-pool"` (см. Бой пулами). Каждый ключ ниже значит одно и то же в обоих видах и читается так, как этот вид читает числа.
- `health`: обязательно. То, что отнимает бой. Либо `{ "pool": "grit" }`, уменьшаемый текущий запас, чей временный буфер при наличии поглощает урон первым; либо `{ "track": "harm" }`, шкала ран, на которой ставятся ОТМЕТКИ. Шкала требует рядом `damageKinds` и не дает временных очков.
- `defense`: обязательно, ссылка на значение. Поле, вводимое игроком, или вычисляемое вами производное значение.
- `initiative`: обязательно. Кости, бросаемые один раз в начале, и необязательная ссылка на модификатор. При равенстве выигрывает больший модификатор, затем порядок создания участников боя. `"each": "round"` заново бросает инициативу всех в начале каждого нового раунда с модификатором на тот момент (поэтому модификатор, читающий шкалу ран, делает раненого медленнее), и раунд начинается с первого в новом порядке. Capability API 1.47. Бой `dice-pool` может вместо этого бросать ее пулом: `pool` (ссылка на значение) – сколько костей, а их успехи плюс `plus` – число, без `dice` или `modifier` рядом. `resource`, которому нужен `pool`, сохраняет это число и позволяет атакам его сдвигать (см. "Инициатива, которую сдвигают атаки" ниже). Capability API 1.48.
- `attackRoll`: обязательно при `attack-vs-defense` и отклоняется при `dice-pool`, который бросает собственные пулы вашего разрешения. Кости, бросает ли система дважды с выбором одного результата (`advantage`), действие крайних граней единственной кости (`naturals.max`: `critical`, `hit` или `none`; `naturals.min`: `miss` или `none`) и влияние критического попадания на урон (`critical`: `double-dice` бросает кости урона еще раз, `max-dice` один раз добавляет их максимальные грани, `none` означает обычное попадание). Особые натуральные результаты требуют одной кости, как и в проверках. Спасброски внутри боя используют эти же кости.
- `economy`: обязательно. `budgets` задает, что вмещает ход: id, подпись, `per` (`turn` восполняет в начале собственного хода владельца, `round` – в начале нового раунда) и `count`. ПЕРВЫЙ объявленный бюджет – основной; его расходует стандартное действие. `movement` – необязательная ссылка на значение: дальность перемещения за ход в вашей единице расстояния. Читается боем на поле (см. Позиции).
- `attacks`: необязательно. Списки листа, чьи строки являются оружием. `name` – текстовый столбец имени строки, `damage.dice` – столбец костей, а каждый из `toHit.ability`, `toHit.proficiency`, `toHit.bonus`, `damage.ability`, `damage.bonus` и `damage.type` именует столбец того же списка. Столбец `ability` – `enum` с одним из id ваших характеристик; другое значение ничего не добавляет. Столбец `proficiency` – `boolean`; если он включен, добавляется бонус мастерства. Строка без читаемых костей не является атакой, поэтому веревка в том же списке остается веревкой. `toHit.skill` называет столбец `enum` с одним из id ваших навыков: строка добавляет то же, что проверка этого навыка, с собственной `ability` строки вместо характеристики навыка, если строка ее называет, точно как `with=` проверки ее заменяет (Capability API 1.47). `strikes` – необязательная ссылка на значение, показывающее, сколько ударов покупает ОДИН расход бюджета списка: выбор строки без ударов в запасе тратит бюджет и оставляет остальные удары в запасе; пока запас есть, любая строка с `strikes` вообще не расходует бюджет. Поэтому меню естественно позволяет сменить оружие, цель и пройти между ударами. `strikesCappedBy` именует логический столбец, ограничивающий ЕГО СОБСТВЕННУЮ строку одним ударом независимо от числа, купленного списком, для оружия, стреляющего раз в ход независимо от числа атак владельца: он создан для свойства Loading из SRD 5.1. Для списка, и так покупающего один удар за расход, он бессмыслен и отклоняется. Запас ударов принадлежит БОЙЦУ, а не списку: персонаж с двумя списками оружия, объявляющими `strikes`, тратит один и тот же запас любой из строк. Он очищается в конце хода, на котором куплен. Список без этого объявления покупает один удар за расход, как любой бой до появления этой возможности.

  ```json
  {
    "list": "attacks",
    "budget": "action",
    "name": "name",
    "strikes": { "field": "attacks_per_action" },
    "damage": { "dice": { "column": "damage" } }
  }
  ```

- `abilities`: необязательно. Списки листа, чьи отмеченные каталогом строки являются способностями, фильтруемыми через `onlyWhen` и `alwaysWhen` точно как `battle.skills`. Действие каждой определяет собственный `mechanics` записи; блок задает расходуемый по умолчанию `budget`, добавляемый `toHit` для записи с броском попадания и `saveDifficulty`, против которого делается спасбросок записи. Запись, требующая спасброска, собственного или снимающего наложенное ею состояние, отклоняется, если у целевого списка нет `saveDifficulty`: спасбросок против ничего всегда был бы успешен.
- `standard`: необязательно, из закрытого списка `dash`, `disengage`, `dodge`, `help`, `hide`, `ready`. `dodge` (атаки по уклоняющемуся бросаются дважды с худшим результатом) и `help` (следующая атака поддержанного союзника бросается дважды с лучшим результатом) разрешаются всегда. `dash` (еще такой же запас перемещения) и `disengage` (никто не ударяет за отход в этом ходу) разрешаются на поле и фиксируются вне поля. `hide` и `ready` принимаются, но пока ничего не делают.
- `standardEffects`: необязательно, для части стандартного действия, не выраженной его флагом. Сейчас такая часть есть только у `dodge`: `{ "dodge": { "saves": ["dex_save"] } }` задает, какие ваши спасброски уклоняющийся бросает дважды с лучшим результатом, пока длится уклонение. Указывайте только объявленные листом спасброски и только если в `standard` есть `dodge`. Без этого уклонение остается прежним: в персонажа труднее попасть, и больше ничего.
- `conditions`: необязательно. Сопоставляет ВАШИ id состояний с их действием, поэтому состояния листа и боя – одна запись, а отравленный персонаж остается отравленным после боя. Эффекты образуют закрытый список: `own-attacks-advantage`, `own-attacks-disadvantage`, `attacks-against-advantage`, `attacks-against-disadvantage`, `attacks-against-adjacent-advantage`, `attacks-against-far-disadvantage`, `attacks-from-adjacent-critical`, `cannot-act`, `cannot-react`, `speed-zero`, `half-move-to-stand`, `ends-on-damage`, `own-saves-advantage`, `own-saves-disadvantage`, `own-checks-advantage`, `own-checks-disadvantage`, `resist-all`, `cannot-target-source` и `cannot-approach-source`. `failsSaves` именует спасброски, проваливаемые состоянием без броска. Шесть эффектов, требующих расстояния или перемещения (`attacks-against-adjacent-advantage`, `attacks-against-far-disadvantage`, `attacks-from-adjacent-critical`, `speed-zero`, `half-move-to-stand`, `cannot-approach-source`), читаются боем на поле и ничего не значат без него (см. Позиции). `cannot-react` исключает владельца из окна, открываемого перемещением, поэтому его никогда не спрашивают. Рядом с эффектами есть еще четыре ключа:
  - `modifiers`: числа, которые состояние меняет, пока действует. См. Числа, которые меняет состояние, ниже.
  - `saves`: каких спасбросков касаются два эффекта спасбросков и любой модификатор спасбросков. При отсутствии – всех; указание без того или другого рядом отклоняется.
  - `skills`: каких навыков касаются два эффекта проверок и любой модификатор проверок, не называющий собственных навыков. При отсутствии – всех; указание без того или другого рядом отклоняется. Состязания в бою бросают собственные проверки боя, а не навыки, поэтому суженное до навыков до них никогда не доходит; проверка вне боя по одному из этих навыков его читает (см. Проверки вне боя ниже). Capability API 1.53.
  - `whileSourceInSight`: что действует лишь пока наложивший состояние находится в поле зрения владельца. `true` ограничивает все состояние; список его собственных эффектов ограничивает только их, оставляя остальные действовать. Это нужно для страха, запрещающего приближаться независимо от видимости источника. Указание отсутствующего в состоянии эффекта отклоняется. Без поля нет линии видимости, которую можно прервать, поэтому в обоих случаях действует все.
  - `endsWhenSourceDown`: состояние снимается сразу, как наложивший его падает.

  `own-saves-advantage` и противоположный эффект бросают спасбросок дважды с выбором одного результата, точно как атаку, и взаимно отменяются. `own-checks-advantage` и противоположный эффект делают то же со стороной владельца в состязании, где бой проводит свои проверки характеристик, и с его проверками вне боя. `resist-all` делит пополам любой вид урона в дополнение к собственной защите цели и аналогично отменяется уязвимостью. `cannot-target-source` запрещает владельцу направлять что-либо на наложившего состояние, а `cannot-approach-source` запрещает приближаться к нему ближе текущей клетки, включая весь маршрут: обход к равноудаленной клетке остается доступным, но маршрут, проходящий ближе и выходящий с другой стороны, – нет.

  ```json
  { "condition": "restrained", "effects": ["own-saves-disadvantage"], "saves": ["dex_save"] }
  ```

  **Числа, которые меняет состояние.** Каждая запись в `modifiers` называет, что она меняет (`to`), и на сколько:
  - `defense`: число, которого должна достичь атака против владельца. Только постоянное число.
  - `attacks`, `saves`, `checks`: собственные броски атаки, спасброски и проверки состязаний владельца. Постоянное число или `dice`, бросаемые при каждом броске (`"1d4"`); `minus: true` отнимает кости вместо прибавления.
  - `speed`: дальность перемещения владельца в вашей единице расстояния (`flat`) или `times` 0.5 либо 2 для половины или удвоения, применяемое после всех постоянных изменений. Читается только на поле, как `speed-zero`.

  Модификатор `checks` может называть собственные `skills`, а модификатор `saves` – собственные `saves`, которые сужают его вместо сужения состояния. Любой из них может бросать дважды с `mode: "advantage"` или `"disadvantage"`, учитываясь вместе с одноименными эффектами и взаимно отменяясь, как они, с числом рядом или без; так одно состояние может одновременно затруднить Sneak и облегчить Climb. Эти три ключа требуют Capability API 1.53.

  ```json
  { "condition": "muddy", "modifiers": [{ "to": "checks", "skills": ["sneak"], "mode": "disadvantage" }] }
  ```

  Постоянное число несет собственный знак, а 0 отклоняется. Каждый модификатор показывается в журнале рядом с измененным броском вместе с именем состояния ("12 + 5 + 3 (Blessed) = 20"), а шанс попадания и шанс победы в меню его учитывают. Состояния складываются друг с другом; одно и то же состояние дважды – все равно одно состояние.

  ```json
  "conditions": [
    { "condition": "blessed", "modifiers": [{ "to": "attacks", "dice": "1d4" }, { "to": "saves", "dice": "1d4" }] },
    { "condition": "shielded", "modifiers": [{ "to": "defense", "flat": 5 }] },
    { "condition": "slowed", "modifiers": [{ "to": "speed", "times": 0.5 }, { "to": "defense", "flat": -2 }] }
  ]
  ```

- `levels`: необязательно. Уровни текущей шкалы, которые считаются состояниями, пока шкала достаточно высока; так выражается состояние, ухудшающееся ступенями, например истощение. Каждая запись называет обычную шкалу `track` (не шкалу ран), уровень `at`, с которого она начинается, и ее действие с теми же `effects`, `modifiers`, `failsSaves`, `saves` и `skills`, что у состояния. Учитывается каждый достигнутый шкалой уровень, поэтому они складываются по мере роста. У уровня нет источника, и он заканчивается, только когда читаемое им значение снижается, поэтому `half-move-to-stand`, `ends-on-damage`, `cannot-target-source` и `cannot-approach-source` для него отклоняются. Шкалы есть только у участника боя с листом. Журнал называет уровень по шкале и номеру ("- 1 (Heat 3)").

  Вместо `track` уровень может читать значение `derived` (Capability API 1.54), вычисляемое с текущим состоянием и предметами персонажа, поэтому никому не нужно ничего отмечать: Ember Roads замедляет каждого, кто несет 10 единиц объема или больше.

  ```json
  { "derived": "bulk_carried", "at": 10, "modifiers": [{ "to": "speed", "flat": -2 }, { "to": "checks", "skills": ["sneak"], "flat": -1 }] }
  ```

  Порог, который отличается у разных персонажей ("больше пятикратной Strength"), – это производное значение, которое его вычитает: `scale` на -1 дает вычитаемую часть, а `sum` двух – то, что читает уровень.

  ```json
  "levels": [
    { "track": "exhaustion", "at": 1, "effects": ["own-checks-disadvantage"] },
    { "track": "exhaustion", "at": 2, "modifiers": [{ "to": "speed", "times": 0.5 }] },
    { "track": "exhaustion", "at": 3, "effects": ["own-attacks-disadvantage", "own-saves-disadvantage"] }
  ]
  ```

  Модификаторы, уровни и эффекты проверок требуют Capability API 1.45.

- `checks` и `contests`: необязательно. Что читает состязание и какие состязания может начать любой в бою: захват, толчок, освобождение. См. Состязания ниже. Capability API 1.43.
- `concentration`: необязательно. Текущее поле `text`, записывающее удерживаемый эффект, `save`, вызываемый уроном, нижний порог сложности `floor` и `fromDamage` – доля полученного урона, задающая сложность, если она выше. Запуск второй способности с концентрацией завершает первую; провал спасброска завершает ее и снимает поддерживаемые ею состояния.
- `dying`: необязательно, `kind: "saves"`. Две шкалы, считающие броски (нужное количество задается максимумом каждой), `dice`, `succeedAt`, действие крайних граней (`naturals.max`: `revive-1` или `success`; `naturals.min`: `one-failure` или `two-failures`), цена урона в поверженном состоянии (`damageWhileDown`, `criticalWhileDown`) и `condition` поверженного персонажа. Без блока персонаж на нуле просто повержен, а лечение возвращает его.
- `damageTypes`: необязательно. Типы вашей системы, сопоставляемые без учета регистра.
- `damageKinds`: обязательно, когда `health` именует шкалу ран, и отклоняется при запасе, потому что только отметка хранит вид, а запасу очков хранить его негде (см. Шкалы ран выше). Задает, какой из `kinds` шкалы отмечает удар и сколько ячеек заполняет. `default` – вид для всего без сопоставления, включая удар вообще без типа; `byType` сопоставляет ваши `damageTypes` видам, а его ключи, как сами типы, сравниваются без регистра: `"Fire"` и `"fire"` – один ключ, и указание обоих отклоняется. У `marks` нет значения по умолчанию, поскольку ответы противоположны: `"per-point"`, когда бросок урона считает уровни здоровья, так что удар на три отмечает три ячейки и смягчить его на единицу полезно; и `"per-blow"`, когда удар либо попадает, либо нет, и отмечает одну ячейку независимо от силы. Удар с несколькими составляющими урона все равно отмечает одну ячейку самым тяжелым попавшим видом. Укажите вариант вашей системы. `{ "default": "bashing", "byType": { "fire": "aggravated" }, "marks": "per-point" }`.
- `pool`: обязательно при `dice-pool`, отклоняется при `attack-vs-defense`. См. Бой пулами.
- `spendLimits`: необязательно. Сколько из текущего запаса один участник боя может потратить за `turn` или за `round` в бою любого вида: `[{ "pool": "blood", "max": { "derived": "blood_per_turn" }, "per": "turn" }]`. `max` читается один раз в начале боя. Цена сверх оставшегося предела недоступна и потому отсутствует в меню, сколько бы ни было в запасе. Предел на ход возобновляется в начале собственного хода владельца, предел на раунд – в начале раунда. Противник, записанный обычными числами, ничего не платит из листа, поэтому предел на него не действует; противник, записанный листом, платит из собственных запасов и подчиняется пределу, как любой другой. Capability API 1.47.
- `threat`: необязательно; требуется бестиарию. `tiers` – шкала выбора противника: id, подпись, диапазон `health`, `defense`, `toHit`, диапазон `damagePerRound` и `saveDifficulty`. Каждое поставляемое существо именует одну из этих ступеней, а не написанный заранее противник приводится к ступени, запрошенной Game Master, чтобы никто не вышел за шкалу. Диапазон `damagePerRound` означает действие существа на ОДНУ цель за раунд, включая всю последовательность.

### Бой пулами: `dice-pool`

Набор `dice-pool` считает успехи, а не складывает кости, и его бои могут делать то же. `"kind": "dice-pool"` требует, чтобы `resolution.kind` был `"dice-pool"`, и читает лист так же, как ваши проверки пулом: **каждое число, которое прибавляет бросок, – число костей, а каждое число, с которым он сравнивается, – число успехов.** Поэтому ничего не переименовывается:

- Число попадания (у строки атаки, `toHit` списка способностей, действия существа) – пул, который бросает атака. Кость, порог, которого должна достичь кость, и грани, на которых срабатывают удвоение, взрыв, отмена и критический провал, берутся из вашего `resolution`. Шкала ран, названная в `resolution.penaltyFrom`, снимает свой штраф с пула, как и с проверки.
- `defense` – сколько успехов нужно атаке, и никогда не меньше одного. Модификатор состояния к `defense` и `cover.bonus` прибавляются к нему.
- Каждый успех сверх нужных добавляет одну кость урона. Критический провал – промах, что бы ни насчиталось. Критических попаданий нет: сильный удар стоит своих дополнительных костей.
- Число спасброска – его пул, а сложность – нужные ему успехи. Состязание бросает проверку каждой стороны пулом, и побеждает сторона с большим числом успехов.
- Модификатор состояния к атакам, спасброскам или проверкам – добавленные или убранные кости, поэтому это постоянное число `flat`: бросаемый модификатор (`dice`) отклоняется.
- Урон – кости вашего типа: `dice` величины (у существа, у записи) говорит, сколько, и должен быть вашей костью, а его часть `flat` – автоматические успехи, которые никогда не бросаются. Столбец костей урона строки атаки читается ради их количества, `damage.ability` добавляет рейтинг этой характеристики костями, а `damage.bonus` – автоматические успехи. `perCostStep` и `scales` добавляют кости, как всегда. Лечение и временные очки – величины и складываются, как раньше.
- Инициатива – сумма (`initiative.dice` и `modifier`) или пул, если вы его запросите (`initiative.pool`, ниже), а правило умирания сохраняет собственные кости.

Сверх этого бой пулами бросает то, что задает его блок `pool`:

```json
"pool": {
  "advantage": true,
  "damageTarget": 6,
  "soak": { "roll": true, "byKind": { "knock": { "abilityMod": "sinew" } } }
}
```

- `advantage`: бросается ли бросок с преимуществом или помехой дважды с выбором того, где больше успехов (критический провал считается меньше любого броска без него). Без этого бой бросает один раз, что бы ни говорило состояние.
- `damageTarget`: порог кости, против которого бросаются кости урона и поглощения. Если не указан – порог разрешения по умолчанию. Эти кости засчитывают каждую грань не ниже него один раз и больше ничего: на них ничего не удваивается, не взрывается, не отменяется и не дает критического провала.
- `soak`: что цель снимает с вреда попадания по виду вреда. `all` – ссылка на значение для любого вида, а `byKind` – по одной на вид вашей шкалы здоровья, которая главнее `all` для своего вида; вид, не названный ни тем ни другим, не поглощается. С `"roll": true` цель бросает столько костей против порога урона, и каждый успех снимает единицу. С `"roll": false` число снимается с костей урона до броска, поэтому никогда не затрагивает автоматические успехи, которые бросаемое поглощение снимает, как любые другие. Ничто не опускается ниже нуля, и ничего не бросается для поглощения удара, который ничего не насчитал. Существо задает собственные числа как `soak: { "all": 1, "byKind": { "knock": 3 } }`, и для этого `soak` блока должен сообщать, как снимается поглощение. Сопротивление, уязвимость, иммунитет и `resist-all` применяются после поглощения к остатку.
- `hardness`: ссылка на значение для твердости бойца, если инициатива – число, которое сдвигают атаки. См. [Доспехи и эффекты надетого в бою](#armor-and-worn-effects-in-a-fight).

Урон каждой цели бросается для нее, потому что заработанное попаданием сверх нужных успехов и поглощаемое ею принадлежит ей. Вторая составляющая удара и дополнительный эффект – каждый свой пул урона своего вида, без дополнительных костей от попадания. Меню точно прогнозирует пул: шанс набрать нужные успехи и чего стоят кости урона после поглощения первой цели.

Так написан Gravewatch: его стражи бросают рейтинг и профессиональный навык, поглощают ушибы через Sinew и вообще не поглощают разрывы, могут тратить одно очко Resolve за ход и заново бросают инициативу каждый раунд.

**Объявление в обратном порядке не реализовано.** В некоторых системах все объявляют действие до того, как кто-либо действует, начиная с самого медленного. В бою, где каждый участник выбирает одно действие в свой ход, предварительное объявление не меняет ничего, что читает какое-либо правило, поэтому ключу нечего сказать.

### Инициатива, которую сдвигают атаки

Некоторые системы с пулами хранят инициативу как число на весь бой и позволяют атакам его сдвигать: один способ атаки забирает его у цели, другой тратит собственное число атакующего как урон, а тот, кто опускается до заданной черты, срывается. Бой `dice-pool` может это выразить (Capability API 1.48):

```json
"initiative": {
  "pool": { "abilityMod": "nerve" },
  "plus": 3,
  "resource": {
    "base": 3,
    "styles": [
      { "id": "press", "label": "Press", "takes": { "gain": 1 } },
      { "id": "telling", "label": "Telling blow", "spends": { "onMiss": [[0, 1], [6, 2], [11, 3]] } }
    ],
    "crash": { "at": 0, "condition": "reeling", "bonus": 5, "recoverAfter": 3 }
  }
}
```

- **Начало.** В начале боя каждый бросает `pool` костей, и успехи плюс `plus` – его число, поэтому `resource` требует `pool`: суммированные кости задают порядок, а не число костей. `initiativeModifier` существа – его пул, поскольку каждое число, которое прибавляет бой пулами, – это кости. Число сохраняется: его никогда не бросают заново (`each` рядом с `resource` отклоняется), а в начале каждого раунда порядок сортируется по текущим числам.
- **Стили.** Каждая атака (строка атаки, способность или запись каталога, которые бросают попадание и наносят вред, такое же действие существа и действие, составленное из других действий) предлагается один раз на каждый стиль, и игрок выбирает стиль до цели. До четырех стилей, каждый либо забирает, либо тратит, и хотя бы один забирает. Выбор без стиля совершается в первом; выбор в стиле, в котором атака не предлагается, отклоняется. Атака сохраняет стиль, в котором совершена, до конца, даже если ответ изменит число атакующего до попадания.
- **Забирающий стиль.** При попадании урон бросается как обычно (дополнительные кости от попадания, кости оружия, поглощение по виду, автоматические успехи), а насчитанное снимается с числа цели вместо ее здоровья. Атакующий получает все это плюс `gain`.
- **Тратящий стиль.** Предлагается, только пока число атакующего выше черты срыва (0, если `crash` не задан), и никогда для действия, составленного из других действий, поскольку число тратится на один удар. При попадании урон – число атакующего на момент атаки в костях против порога урона, и больше ничего: ни костей оружия, ни дополнительных костей от попадания, ни автоматических успехов, ни поглощения. Он отмечает здоровье собственным видом вреда атаки. Когда атака завершена, число, которое куда-то попало, возвращается к `base`, а число, не попавшее никуда, теряет то, что говорит `onMiss` для числа, с которым атака была совершена (таблица ступеней: пары `[at least, lose]` по возрастанию; ниже первой ступени ничего).
- **Срыв.** Число, опустившееся до `crash.at` или ниже, означает срыв: на участника накладывается `condition` (одно из ваших состояний, необязательно), а тот, кто его туда довел, получает `bonus`. Промах, вызвавший срыв собственного автора, никому не дает бонуса. Сорвавшийся участник не может тратить. Срыв снимается вместе с состоянием, когда число снова поднимается выше черты, после `recoverAfter` собственных ходов участника (в начале этого хода его число возвращается к `base`) и когда бой заканчивается, как бы он ни закончился. Тот, чей начальный бросок на черте или ниже, начинает бой в срыве. `base` должен быть выше `crash.at`, иначе возвращение к нему снова вызвало бы срыв.

Меню показывает собственный прогноз каждого стиля: шанс попадания и сколько забрал бы забирающий стиль или какой вред нанес бы тратящий. Панель состояния показывает число каждого, а журнал сообщает о каждом изменении и его причине: "Ada gains 5 initiative for crashing Rats, and is on 14." Механизм выбора Engine оценивает забирающий удар на ход вперед: забрать, а затем потратить, против того, чтобы потратить сейчас и снова с базы.

<a id="what-a-fight-reads-from-mechanics"></a>

### Что бой читает из `mechanics`

`kind` определяет, является ли `amount` уроном или лечением; все с отметкой `reaction` исключается из меню, как и запись `utility`, если она не меняет возможности самого хода (см. ниже). `attackRoll` выполняет бросок против защиты цели с `toHit` списка; `autoHit` полностью его пропускает. `save` бросает собственный спасбросок цели против `saveDifficulty` списка, а `onSuccess` определяет, остается при успехе половина или ничего. `targetCount` – допустимое число целей. Способность без броска атаки (область, против которой все спасаются, или автоматическое попадание) бросает кости ОДИН раз для всех; способность с броском попадания по каждой цели бросает урон заново при каждом попадании. `applies` накладывает состояния на затронутых, каждое с `duration`: `instant` (без собственного таймера: остается, пока что-то не снимет), `until-save` (требует рядом `saveEnds`) или `{ "rounds": n }`, и необязательным `saveEnds`, именующим спасбросок и повторение в `turn-end` или `turn-start`. Раунды отсчитывают собственные ходы владельца по мере окончания каждого; `{ "rounds": 1, "at": "turn-start" }` отсчитывает их по мере начала – так выражается "до начала вашего следующего хода". `endsAfter` снимает состояние после первого `own-attack` (следующего броска атаки владельца), `attacked` (следующего броска атаки против владельца) или `own-save` (следующего спасброска владельца), что бы ни говорил его таймер, поэтому `{ "duration": { "rounds": 1 }, "endsAfter": "own-attack" }` – это "на следующую атаку до конца следующего хода". Состояние, длящееся одну атаку, длится всю ее, включая урон, а новое такое же состояние, наложенное тем же ударом, остается. Оба требуют Capability API 1.45. `temporary` дает временные очки запаса здоровья; они не складываются – остается больший буфер. `scales` увеличивает величину дополнительными КОСТЯМИ, которые его таблица дает для прочитанного значения. `cost` оплачивается собственной командой листа `use`, а `budget` переопределяет расходуемую часть экономики действий.

`plus` – до трех ДОПОЛНИТЕЛЬНЫХ величин того же удара рядом с `amount`, каждая бросается и получает тип отдельно ("and 2d6 fire"). Составляющая имеет вид `{ "dice": "2d6", "flat": 1, "type": "fire" }` и может иметь собственный `save`, `{ "save": "con_save", "difficulty": 13, "onSuccess": "none" | "half" }`, который ЦЕЛЬ бросает независимо от уже потребованного действием: `none` при успехе полностью убирает эту составляющую, `half` оставляет половину; остальной удар не меняется. Без `difficulty` берется число собственного спасброска действия, затем `saveDifficulty` списка. Критическое попадание удваивает кости каждой составляющей по тому же правилу, что кости первой величины; составляющая без `type` имеет собственный вид урона удара, а весь удар по-прежнему вызывает ОДНУ проверку концентрации по суммарному урону и одну проверку падения. Составляющей нужен базовый `amount`; у `heal` их не бывает.

```json
{
  "kind": "attack",
  "attackRoll": true,
  "amount": { "dice": "1d8" },
  "damageType": "piercing",
  "plus": [{ "dice": "2d6", "type": "fire" }]
}
```

Три ключа задают действие записи на экономику самого хода; запись `utility`, объявляющая любой из них, предлагается, а не исключается:

- `free`: вообще не расходует бюджет. Указанный `cost` все равно оплачивается; одновременно указывать `budget` нельзя.
- `gives`: `[{ "budget": "action", "count": 1 }]`, до четырех. В момент использования увеличивает эти бюджеты, ограничивая результат вместимостью хода плюс подарок, поэтому ничего нельзя накопить для будущего хода.
- `standard`: `{ "actions": ["dash", "disengage", "hide"], "budget": "bonus" }`. Владелец может выполнять эти стандартные действия за ЭТОТ бюджет. Они предлагаются рядом с обычными как `standard:<id>@<budget>`; сама запись не появляется в меню, если она только дает разрешение, поскольку разрешение не выполняют.

Запись нового вида `kind: "rider"` ПАССИВНА: никто ее не выполняет, ее никогда нет в меню, и она автоматически добавляет еще одну составляющую урона к первому подходящему попаданию периода. Она содержит `rider` и ничего другого, что можно выполнять:

```json
{
  "kind": "rider",
  "rider": {
    "on": "hit",
    "sources": ["attacks"],
    "requires": { "column": "finesse" },
    "when": ["advantage", "ally-adjacent"],
    "oncePer": "turn",
    "amount": { "dice": "1d6" }
  },
  "scales": {
    "from": { "field": "level" },
    "table": [
      [1, 0],
      [3, 1]
    ]
  }
}
```

`sources` именует списки атак, от которых он срабатывает, а `requires` – один истинный столбец их строк, поэтому дополнительный эффект для определенного оружия указывает его без знания Engine о том, что такое оружие; отсутствие обоих означает любое попадание владельца. Удерживаемое оружие из сумки – не строка, поэтому `weapons` (Capability API 1.70) также называет метки предметов, от которых он срабатывает: `"weapons": { "tags": ["finesse",
"ranged"] }` срабатывает при попадании удерживаемым оружием с любой из этих меток, включая удар второй рукой. Если назван только `weapons`, эффект не срабатывает ни от какой строки, а если названы только строки – ни от какого удерживаемого оружия. `when` означает ЛЮБОЕ условие: `advantage` – окончательное преимущество броска атаки, а `ally-adjacent` – стоящий союзник атакующего, способный действовать, в пределах одной клетки от цели на поле или где угодно без поля. `oncePer` – `turn` (обновляется в начале каждого хода, поэтому удар во время чужого действия тоже может его нести) либо `round`. `amount` растет с собственным `scales` записи, а `type` задает вид урона, по умолчанию вид самого удара.

<a id="creatures-a-bestiary-a-fight-reads"></a>

### Существа: бестиарий, который читает бой

Каталог с `"holds": "creatures"` содержит противников вместо строк листа. Он не наполняет списки, окно выбора редактора листа никогда его не предлагает, а все числа записаны в ключах, уже объявленных вашим `combat`. Ему нужны блок `combat` и шкала `threat`, поскольку существо относится к одной из ваших ступеней.

```json
{
  "id": "road_trouble",
  "label": "Road trouble",
  "holds": "creatures",
  "filters": [{ "id": "tier", "label": "How bad", "type": "text" }],
  "entries": [
    {
      "id": "rust-jackal",
      "label": "Rust Jackal",
      "summary": "A lean thing that lives on the metal roads.",
      "filters": { "tier": "Pack trouble" },
      "creature": {
        "health": { "dice": "3d6" },
        "defense": 6,
        "initiativeModifier": 1,
        "speed": 16,
        "abilities": { "brawn": 1, "wits": 0, "heart": -1 },
        "tier": "pack",
        "actions": [
          {
            "id": "bite",
            "name": "Bite",
            "budget": "act",
            "toHit": 2,
            "damage": { "dice": "1d6", "flat": 1, "type": "cut" },
            "reach": 2
          },
          {
            "id": "worry",
            "name": "Worry",
            "budget": "act",
            "toHit": 2,
            "damage": { "dice": "1d4", "type": "cut" },
            "applies": [{ "condition": "shaken", "duration": { "rounds": 2 } }]
          },
          {
            "id": "snap_and_worry",
            "name": "Snap and worry",
            "budget": "act",
            "sequence": [
              { "action": "bite", "times": 1 },
              { "action": "worry", "times": 1 }
            ]
          }
        ]
      }
    }
  ]
}
```

Числа ниже – прямой способ записать существо. Записанное в собственных терминах набора правил, как `sheet`, берет `health`, `defense`, `initiativeModifier`, `speed`, `abilities`, `saves`, `checks`, `soak` и `hardness` из этого листа (см. "Существо в собственных терминах набора правил" ниже).

- `health`: число либо `{ "dice": "3d6", "flat": 2 }`, бросаемое один раз при создании боя. Прогноз читает среднее, поэтому меню никогда не обещает результат еще не брошенной кости.
- `defense`, `initiativeModifier`, `speed`: против чего бросается атака, прибавка к инициативе (или, если инициатива бросается пулом, сколько костей бросается) и дальность движения за ход в вашей единице расстояния.
- `abilities` и `saves`: ключами служат id характеристик и спасбросков листа. Неуказанный спасбросок равен нулю.
- `checks`: что существо прибавляет в состязании, с ключами по id `combat.checks`. Неуказанная проверка равна нулю. Capability API 1.43.
- `soak`: только в бою `dice-pool` – что существо поглощает: `all` для любого вреда, `byKind` для вида вашей шкалы здоровья. Capability API 1.47.
- `hardness`: если инициатива – число, которое сдвигают атаки, тратящий удар, чьих костей меньше этого значения, ничего не делает. Capability API 1.56.
- `resist`, `vulnerable`, `immune`: типы урона, сопоставляемые без регистра и проверяемые по `combat.damageTypes`, если вы их объявили. Запись `resist` или `immune` может также сообщать, что проходит сквозь нее, `{ "type": "tearing", "except": ["silver"] }`: удар оружием-предметом с одной из этих меток предметов принимается как есть (Capability API 1.55, см. [Оружие в бою](#weapons-in-a-fight)). `conditionImmunities` именует ваши состояния.
- `tier`: ступень `combat.threat`, к которой относится существо.
- `loot` (Capability API 1.63): id таблицы добычи, которую бросает за него выигранный бой (см. Добыча выше).
- `traits`: короткие пары имени и текста, показанные Game Master. Они никогда не разрешаются, поэтому все с числами должно находиться в действии.
- `signaturePoints`: очки, возвращаемые в начале собственного хода и расходуемые на действия `signature`.
- `riders`: до четырех, то же, что `rider` записи каталога, но записанное в блоке. Каждый имеет вид `{ "id": "pack", "name": "Pack", "on": "hit", "oncePer": "turn" | "round", "amount": { "dice": "1d6" } }` с необязательным `type` и необязательным `actions`, указывающим собственные действия блока, при которых он срабатывает. Дополнительный эффект блока не читает списки листа, поэтому у него нет двух ключей: `sources` и `requires`. Существо с листом получает дополнительные эффекты своих списков, как персонаж.
- `actions`: до двенадцати, каждое с собственным `id`. Действие содержит то же, что написанный вручную блок статистик (`toHit`, `autoHit`, `damage`, `save`, `applies`, `targetCount`, `reach`, `range`, `area`), плюс четыре свойства только для существ. `reach` – дальность удара, `range` – дальность броска или выстрела, `area` – форма области, все в вашей единице расстояния; `range` может быть числом или `{ "normal": 30, "long": 120 }`, если дальше можно достать со штрафом, а `area` имеет вид `{ "shape": "burst" | "cone" | "line", "size": n, "friendlyFire": false }` (см. Позиции):
  - `uses`: `{ "per": "encounter" | "day", "count": n }`. Когда использования заканчиваются, действие исчезает из меню.
  - `recharge`: `{ "dice": { "count": 1, "sides": 6 }, "from": 5 }`. В начале боя доступно, расходуется при использовании; в начале собственного хода существа бросает кости: `from` или выше возвращает его. Кости записываются в журнал при любом результате.
  - `sequence`: другие действия того же блока по порядку, каждое со своей целью. **Так записывается существо, бьющее дважды за одно действие.** Один бюджет оплачивает всю последовательность. У последовательности нет собственного эффекта, и она никогда не может именовать другую последовательность.
  - `signature`: `{ "cost": n }`, оплачивается собственными очками существа вместо бюджета и только во время чужого действия: бой предлагает его в окне между ходами (см. Окна).
  - `reaction`: тот же объект, что `mechanics.reaction` записи каталога (см. Окна): действие отсутствует в меню любого хода и вместо этого предлагается в названный им момент. Реакция не может одновременно быть особым действием, и последовательность не может быть реакцией.
  - `self: true`: действие приходится на само существо, а не на кого-то другого, и потому не принимает `targetCount` или `area`. Оба требуют Capability API 1.46. Parry – и то и другое, с состоянием `parrying`, которое добавляет 2 к защите:

    ```json
    {
      "id": "parry",
      "name": "Parry",
      "budget": "reaction",
      "self": true,
      "reaction": { "on": "hit" },
      "applies": [{ "condition": "parrying", "duration": { "rounds": 1 }, "endsAfter": "attacked" }]
    }
    ```
- Спасброску нужна сложность на самом действии: `save.difficulty` для спасброска, вызываемого действием, либо `saveDifficulty` для состояния, снимаемого спасброском, если у действия нет собственного. Действие блока записывается обычными числами даже у существа с листом, поэтому число хранится на действии. Собственный спасбросок составляющей может опустить `difficulty` и взять то же число.
- `damage.plus` – тот же список составляющих, что `plus` записи каталога, читаемый точно так же: `"damage": { "dice": "1d6", "flat": 2, "type": "piercing", "plus": [{ "dice": "1d4", "type": "fire" }] }` – укус с отдельной величиной жара, к которой отдельно применяется сопротивление и которая отдельно удваивается.

Собственный бестиарий черновика 5e – пять написанных вручную существ в `docs/development/ruleset-5e-2014.example.json`, покрывающих последовательность, перезарядку, спасбросок с состоянием, сопротивления и иммунитеты, ограниченные использования, особые очки и одно существо с листом.

#### Существо в собственных терминах набора правил

Существо не обязательно записывать обычными числами. Дайте ему `sheet` точно такой же формы, как лист персонажа, и бой построит его как участника отряда: здоровье, защита, спасброски, инициатива, скорость и все атаки и способности списков будут такими, какими их делают ваши формулы листа. Так набор правил сообщает, что у противников те же характеристики, навыки и списки, что у персонажей, какими бы они ни были. Toll Warden из Ember Roads:

```json
{
  "id": "toll-warden",
  "label": "Toll Warden",
  "creature": {
    "tier": "pack",
    "traits": [{ "name": "Knows the road", "text": "It will not follow anyone past the last milestone." }],
    "sheet": {
      "abilities": { "brawn": 2, "wits": 1, "heart": 1 },
      "skills": { "sway": "trained" },
      "fields": { "calling": "Hauler", "toughness": 3 },
      "lists": {
        "gear": [{ "name": "Toll hook", "swing": "brawn", "damage": "1d6", "harm": "cut" }],
        "knacks": [{ "name": "Hold the Line", "_catalog": "knacks/hold-the-line" }]
      }
    }
  }
}
```

- **Каждая часть необязательна**: `abilities`, `skills`, `saves`, `bonuses`, `fields` и `lists`, с ключами по id листа. Все пропущенное принимает собственное значение листа по умолчанию, как у пустого персонажа. Grit стража равен 9, поскольку `grit_max` складывает 4, его Toughness и Brawn; Guard равен 7 по аналогичной причине.
- **У каждого числа один источник.** Существо с листом не задает одновременно `health`, `defense`, `initiativeModifier`, `speed`, `abilities`, `saves` или `checks`; иначе Engine отклоняет файл. У него может не быть собственных `actions`, поскольку его действия задаются списками. Существо без листа по-прежнему задает первые три числа и хотя бы одно действие.
- **Оно проверяется как авторские данные.** Каждый id должен быть объявлен листом; навык или спасбросок получает одну из предлагаемых ему ступеней мастерства; поле, показатель, бонус или столбец содержит объявленное значение (целое число в диапазоне, один из вариантов и т. п.); список не превышает допустимое число строк. Части `live` нет, поскольку расходы существа хранит бой.
- **Строка может поступать из каталога.** `_catalog: "<catalog>/<entry>"` именует выбранную запись, как в листе персонажа; оттуда бой читает стоимость и действие строки. Каталог должен наполнять этот список. Встроенный каталог обязан содержать запись; у отдельного файла строка с отсутствующей в нем записью просто ничего не дает существу. Каталоги, на которые ссылаются листы бестиария, загружаются в бой вместе с бестиарием.
- **Данные записи рядом с листом все еще учитываются**: `tier`, `traits`, `actions`, `signaturePoints`, `riders`, `resist`, `vulnerable`, `immune` и `conditionImmunities`.
- **Оно платит из собственных запасов.** Они начинают полными, расходуются на действия из списков, и существу предлагаются более дорогие варианты оплаты (заклинание из более высокой ячейки), как участнику отряда, независимо от того, решает Engine или Game Master. Hold the Line стража стоит ему Luck.
- **При шкале ран его здоровье – сама шкала.** Удар отмечает собственную шкалу существа по вашему `damageKinds` после применения `resist`, `vulnerable` и `immune`, поэтому существо с иммунитетом к виду урона не получает от него отметку.
- **Оно остается противником.** При нуле выбывает, а не умирает, никогда не делает спасбросков от смерти; экран показывает обычные сведения противника и ничего из листа; потраченные ресурсы нигде не записываются обратно, даже если персонаж носит то же имя.
- **Лист, вообще не дающий здоровья**, исключается из боя с объяснением в начальном журнале, вместо появления существа, которому никто не может навредить.
- Слой, удаляющий значение одного из полей-перечислений, никогда не лишает вас использующего его существа: пока слой включен, поле принимает для существа значение по умолчанию, как для персонажа; существо из-за этого не отклоняется.
- Game Master тоже может придумать такое существо; оно ограничивается своей ступенью (см. Противники, которых никто не написал).
- Пакет с таким существом объявляет Capability API 1.34.

Toll Sergeant из черновика 5e – то же самое на листе d20: его Класс Доспеха, здоровье, спасброски и два удара за действие происходят из собственных полей и списка атак.

#### Противники, которых никто не написал

Когда Game Master придумывает противника, Engine приводит предложение к вашей шкале `threat` до бросков: здоровье – в диапазон ступени, защиту, бонус попадания и сложности спасбросков – не выше значений ступени плюс два, урон уменьшает, пока лучший раунд существа (самая тяжелая последовательность или отдельное действие против одной цели) не войдет в `damagePerRound` ступени. Сначала сокращается число костей, затем постоянная часть, затем удар последовательности, и лишь потом размер кости; ничто не уменьшается до нуля. Отсутствующие в наборе правил имена убираются: неизвестные типы урона, состояния и спасброски, а также все действия после первых шести. Необъявленная ступень заменяется нижней ступенью шкалы. Каждое изменение возвращается обычным предложением, чтобы журнал мог объяснить сделанное.

Придуманное существо тоже можно записать как `sheet`, как существо бестиария; так придуманный маг получает ячейки и заклинания. Game Master видит id листа и допустимое содержимое, читаемые боем списки и предлагаемые им каталогами имена, чтобы заклинание называлось, а не описывалось: строка, именующая запись каталога в любом регистре, становится этой записью, а собственные значения Game Master (например, подготовка заклинания) накладываются сверху. Лист читается терпимо, поскольку его написала модель: отсутствующее имя убирается, значение подгоняется к полю или столбцу, а числа рядом с листом не используются.

Придуманное существо, не являющееся боссом, ограничено тем, что открывает ему набор правил. Фильтр каталога с `startFrom` именует поле листа, по которому организованы записи (список заклинаний пакета 5e по `class`); существо сохраняет только записи, чей фильтр соответствует его значению этого поля, тем же способом, которым открывается окно выбора. Поэтому Чародей никогда не получает весь список заклинаний, а существо без класса – ничего из каталога по классам. Оставленные выборы затем заполняются без нового запроса к Game Master: для каждого списка, чьи строки действуют лишь после выбора (`onlyWhen` у источника боевых способностей), из доступных и оплачиваемых собственными запасами записей для каждого запаса добирается небольшое число записей (больше у более компетентного существа), как и для действий без ограничения использований. Выбор опирается на темперамент и компетентность, с которыми существо сражается: защитное или поддерживающее выбирает поддержку своей стороны, безрассудное – урон, методичное или терпеливое – сдерживание врага; чем выше компетентность, тем вероятнее реакция, контрмера или иной способ изменить ход. Выбор использует собственное зерно боя, поэтому один и тот же бой всегда заполняется одинаково. Строка такого списка, названная Game Master, считается выбранной.

Босса Game Master пишет целиком как возможное исключение: ничего не убирается и ничего не дополняется.

Затем оба варианта ограничиваются своей ступенью:

- Здоровье приводится к диапазону ступени через единственное поле, из которого читается: максимум запаса является этим полем либо `sum` с ровно одним полем (максимум здоровья в 5e, Toughness в Ember Roads). Формула здоровья без единственного поля остается как написано, и журнал это сообщает. Длина шкалы ран принадлежит вам и никогда не меняется.
- После построения существа защита, бонус попадания и сложности спасбросков ограничиваются значениями ступени плюс два; урон уменьшается, пока лучший раунд не войдет в `damagePerRound` ступени, с учетом самой большой доступной оплаты. Сначала убирается прибавка от более дорогой оплаты, затем кости, постоянная часть, удар и лишь потом размер кости.

Ваш собственный бестиарий никогда не ограничивается. Это написанные вами данные, и Engine принимает их как есть.

### Позиции: бой на поле

Бой остается театром воображения, пока блок не задаст цену одной клетки поля. Объявите `distance`, чтобы сражаться на сетке: тогда перемещение, досягаемость, дальность, области, линия видимости, укрытие и удары по уходящим обретают смысл. Каждое значение – ваше число; Engine дает только поле.

```json
"distance": { "label": "ft", "perCell": 5 },
"ranged": { "long": "disadvantage", "adjacentFoe": "disadvantage" },
"cover": { "bonus": 2 },
"opportunity": { "budget": "reaction" }
```

Ember Roads объявляет одну строку и больше ничего; в этом и смысл: остальное не обязательно.

```json
"distance": { "label": "paces", "perCell": 2 }
```

**Клетка.** `distance.perCell` задает, сколько ВАШИХ единиц стоит клетка, а `label` – название единицы. В ней выражены все расстояния мира блока: `economy.movement`, `speed` существа, `reach` и `range` оружия, `reach` и `range` действия существа. Каталог с собственным `units.distance` переводит собственные `mechanics.range` и `area.size` своим `perCell`; без него использует это объявление. Положительное расстояние округляется до ближайшей клетки, но никогда до нуля, поэтому все, чему вы дали число, достигает хотя бы одной. Ноль не означает короткое расстояние, а сохраняет собственный смысл: `mechanics.range` 0 – на себя или касанием (касание другого достигает соседней клетки); 0 в столбце оружия `reach` или `range` означает, что у строки нет такой дальности.

**Будет ли бой на поле.** Должны совпасть два условия: блок объявляет `distance`, а в игре выбран стиль боя Tactical. При стиле Classic или наборе правил без `distance` бой остается театром воображения, как прежде: любой может целиться в любого, и ничто ниже вообще не читается.

**Что видит игрок.** Поле рисуется с собственным рельефом тактического стиля. Каждая клетка – кнопка, доступная указателем или стрелками, сообщающая, что это, кто на ней и что для нее значит еще не законченный выбор. Перемещение подсвечивает предложенные меню клетки, каждую с ценой В ВАШЕЙ ЕДИНИЦЕ, рисует маршрут и выделяет янтарным клетки, чей путь вызовет чей-то удар, называя нападающих под полем. Вариант с целью одновременно подсвечивает допустимых участников на поле и в списке. Вариант с `area` направляется на клетку; клетка под указателем сообщает, кого заденет, включая друзей. Остаток движения показан рядом с бюджетами, снова в вашей единице. Экран ничего не измеряет: каждая клетка, цена, маршрут, цель и точка прицеливания поступают с сервера.

**Перемещение.** Запас хода – `economy.movement` участника отряда либо собственный `speed` существа, поделенный на `perCell` и округленный ВНИЗ; не меньше одной клетки, пока движение вообще возможно. Восполняется в начале собственного хода владельца и может расходоваться до, между и после действий: пройти, ударить, пройти снова. Вход на клетку стоит один или больше на трудной местности. Восемь направлений стоят одинаково, как на настольных сетках, для которых это сделано. Через друга можно пройти, но ни на ком нельзя остановиться; противник – стена; в твердую преграду входить нельзя, как и срезать угол между двумя твердыми клетками.

**Досягаемость и дальность.** Строка оружия получает их из `combat.attacks[].reach` и `.range`, каждое – столбец того же списка или одинаковое число для всех строк:

```json
"attacks": [
  {
    "list": "attacks",
    "budget": "action",
    "name": "name",
    "toHit": { "ability": { "column": "ability" } },
    "damage": { "dice": { "column": "damage" } },
    "reach": { "column": "reach" },
    "range": { "normal": { "column": "range" }, "long": { "column": "long_range" } }
  }
]
```

Ноль в столбце означает, что у строки нет такой дальности; так обычный меч находится в одном списке с метательным топором. Строка вообще без досягаемости достигает одной клетки. Действие существа использует собственный `reach` или `range`, способность каталога – `mechanics.range` (0 – на себя или касанием, то есть одна клетка при направлении на другого).

Строка с ОБОИМИ значениями – метательное оружие: в пределах досягаемости это взмах, дальше – выстрел. Поэтому правила выстрела ниже не касаются его в руке; им можно ударить проходящего мимо, в отличие от лука.

Действие существа также может содержать свой `area` в вашей единице: `{ "shape": "cone",
"size": 15 }`, с `"friendlyFire": false` для защиты своей стороны. Так дыхательное оружие становится настоящим конусом на поле, а не числом целей. У последовательности нет собственной формы; она есть у именуемых действий. Бой без поля игнорирует форму и использует `targetCount`, поэтому запись существа может указать оба варианта и быть корректной в обоих режимах.

**Как далеко можно послать область.** Это задает `range`: у шара, брошенного на сто футов, оно есть. Без дальности взрыв происходит там, где его поставили, на собственной клетке действующего, а конус или линию можно направить на любую клетку в пределах рисуемой длины: здесь клетка задает только направление. Это относится и к `mechanics.area` записи каталога, и к области существа.

`ranged` задает цену выстрела за пределами обычной дистанции `normal` либо при враге на соседней клетке. Каждый вариант – `"disadvantage"` или `"normal"`; без блока оба не имеют цены. Взмах никогда не является выстрелом, поэтому оба правила его не касаются, как и метательного оружия в пределах досягаемости.

**Области.** `mechanics.area` записи становится реальной формой на поле, направленной на клетку, а не участника; `targetCount` к ней не относится: число целей определяет форма. Задеты все стоящие в клетках, друзья и враги, если запись не задает `"friendlyFire": false`.

```
burst, size 2, aimed at X        cone, size 3, aimed right      line, size 3, aimed right
. . . . .                        . . . .                        . . . .
. # # # .                        . . # .                        A # # #
. # X # .                        A # # #                        . . . .
. # # # .                        . . # .
. . . . .                        . . . .
```

Взрыв покрывает все клетки в пределах своего размера от целевой клетки. Конус идет от действующего к ней, на каждом шаге имея ширину, равную расстоянию. Линия идет так же с шириной в одну клетку. Все три останавливаются на твердой преграде.

**Линия видимости и укрытие.** Прямая линия клеток между двумя участниками: твердая преграда блокирует выстрел и распространение области за нее, а цель просто отсутствует в меню. Местность, дающая укрытие, прибавляет `cover.bonus` к защите против атаки, и журнал это сообщает. Нет укрытия на три четверти, полного укрытия или высоты.

**Удары по уходящим.** Объявите `opportunity.budget`; когда боец выходит из досягаемости стоящего врага, который способен действовать, имеет этот бюджет и оружие ближнего боя, перемещение ОСТАНАВЛИВАЕТСЯ на месте, а врага спрашивают, ударить ли. Согласие тратит бюджет и разрешается как та же атака в его собственный ход; пропуск ничего не стоит. Затем перемещение продолжается с места задержки, оплачивая каждую действительно пройденную клетку; удар, поваливший движущегося, заканчивает путь там, где тот упал. У каждого одна возможность на весь путь независимо от того, сколько раз он выходит из той же досягаемости. `disengage` предотвращает это до конца хода; у набора правил без `opportunity` ничего из этого нет.

Запрос – это ОКНО, удерживающее весь бой: ничто не движется, пока все спрошенные не ответят. За участника отряда отвечает игрок, выбирая удар или соседнее Pass; за остальных – тот, кто ими играет, а за босса Game Master – собственное решение Game Master. См. Окна ниже.

**Как противник использует поле.** Противник, которым никто не играет, оценивает каждую достижимую клетку относительно всех вариантов оттуда, вычитает за каждый удар на пути и предпочитает не двигаться, если уже способен на лучший вариант с места. Когда ничто не в досягаемости, сокращает дистанцию, начиная с рывка, если в `standard` есть `dash`.

**Возможные отказы.** `out-of-reach` (дальше досягаемости), `no-line-of-sight` (твердая преграда), `unreachable` (клетка, которую нельзя оплатить движением или на которой нельзя закончить путь), `bad-cell` (область направлена в недопустимое место).

### Что бой делает с вашим блоком на сервере

Игра, чей набор правил объявляет `combat`, получает бой по этому блоку на том же сохраненном сражении, которое Engine использовал всегда:

- **Кто участвует.** Game Master говорит, кто сражается; Engine читает числа каждого участника отряда из его листа. Участник без листа вашего набора правил отклоняется по имени, а не получает числа, которых вы не писали.
- **Откуда числа противника**, по порядку: существо, названное Game Master в бестиарии; существо с подписью, совпадающей с именем противника; предложенный Game Master для боя блок статистик, ограниченный вашей шкалой угрозы; наконец, простое существо из чисел ступени. Каждый запасной вариант и каждое ограничение фиксируются обычными словами, чтобы бой мог объяснить сделанное. Набор правил без записи бестиария, предложения и шкалы угрозы отклоняет бой, а не выдумывает его.
- **Листы – источник записи.** Здоровье, запасы, состояния, концентрация и счетчики правила умирания записываются по собственным правилам листа после каждого принятого действия, поэтому перезагрузка посреди боя показывает ровно оставленное боем; итогового подсчета после сражения, который мог бы противоречить этому, нет.
- **Меню – единственный источник допустимости.** Каждый действующий, игрок или противник, выбирает id из одного и того же меню блока. Противник Engine выбирает по собственной тактике Engine; противнику Game Master предлагается выбрать один id из того же меню, с вашими числами, но без сведений о будущих результатах костей.
- **Ваши кости.** У боя собственные зерно и курсор, поэтому прочитанный с диска бой продолжается с теми же костями, которые бросил бы.

### На экране

Бой идет на экране сражения в ваших терминах. Меню содержит ваши атаки, способности, состязания и перечисленные стандартные действия; каждое показывает расход из ваших бюджетов и запасов. Видны порядок ходов, раунд, все названные состояния с оставшимися раундами, временные очки, концентрация и два счетчика правила умирания. Журнал выводит настоящую арифметику в ваших терминах: "Juno attacks Rust jackal with Road axe: 8 (5 + 3) + 3 = 11 against Guard 6, a hit." Каждое принятое действие сразу записывается в лист, поэтому перезагрузка посреди боя точна, а Game Master после этого сообщают не менять эти числа повторно.

Бой с позициями рисуется на поле вместо сцены портретов; действия игрока описаны в разделе Позиции. Любое расстояние на поле, в меню и журнале выражается в ВАШЕЙ единице: "Juno moves to 4, 6 for 6 paces and has 2 paces left."

### Состязания: захват, толчок, освобождение

Некоторые приемы – не атака против защиты, а состязание: бросают обе стороны, и кто справится лучше, добивается своего. Схватить кого-то, опрокинуть или оттолкнуть и вырваться – все это одна форма, поэтому набор правил описывает каждый прием данными:

```json
"checks": [
  { "id": "brawn", "label": "Brawn", "value": { "abilityMod": "brawn" } },
  { "id": "wits", "label": "Wits", "value": { "abilityMod": "wits" } }
],
"contests": [
  {
    "id": "grab",
    "label": "Grab",
    "budget": "act",
    "attacker": { "checks": ["brawn"] },
    "defender": { "checks": ["brawn", "wits"] },
    "onWin": { "applies": [{ "condition": "held" }] }
  },
  {
    "id": "break_free",
    "label": "Break free",
    "budget": "act",
    "attacker": { "checks": ["brawn", "wits"] },
    "defender": { "checks": ["brawn"] },
    "from": { "holding": "held" },
    "onWin": { "ends": [{ "condition": "held", "on": "actor" }] }
  },
  {
    "id": "shove",
    "label": "Shove back",
    "budget": "act",
    "attacker": { "checks": ["brawn"] },
    "defender": { "checks": ["brawn"] },
    "ties": "attacker",
    "onWin": { "push": 4 }
  }
]
```

- **`checks`** – числа, которые читает состязание, каждое – значение из листа, читаемое один раз в начале боя, как защита или спасбросок. Существо, записанное обычными числами, задает собственные (`"checks": { "brawn": 2 }`); существо с листом читает их из листа. До двенадцати.
- **Бросок.** Обе стороны бросают ваши `attackRoll.dice` и прибавляют лучшую из проверок, которые могут здесь использовать (`attacker.checks`, `defender.checks`). Побеждает больший итог; при равенстве побеждает защищающийся, если `ties` не говорит `"attacker"`. Журнал сообщает обе стороны: "Juno tries Grab on Ash-hound: 12 (6 + 6) + 3 = 15 with Brawn against 2 (1 + 1) + 2 = 4 with Brawn, and wins."
- **Победа** выполняет то, что говорит `onWin`, хотя бы одно действие:
  - `applies` накладывает состояния на проигравшего с победителем в качестве источника, поэтому состояние, отмеченное вами `endsWhenSourceDown`, заканчивается, когда удерживающий падает. `rounds` задает состоянию таймер; без него оно длится, пока что-то его не снимет.
  - `ends` снимает состояния с действующего или с цели.
  - `push` отталкивает проигравшего прямо от победителя на это расстояние в вашей единице, останавливаясь перед чем-либо твердым, кем-либо стоящим, краем поля и слишком тесным для протискивания углом. Это принудительное перемещение: оно не тратит движение проигравшего, и никто не наносит по нему удар. В бою без поля никто не перемещается.
    Поражение ничего не делает – это и есть неудавшийся захват.
- **`from: { "holding": "held" }`** направляет состязание только на того, кто наложил это состояние на действующего, и помещает его в меню, только пока состояние действует: так выражается освобождение.
- **`reach`** в вашей единице расстояния – насколько далеко достает состязание; если не указано – соседняя клетка. `reach` и `push` требуют `combat.distance`.
- **`strike: true`** позволяет состязанию заменить один удар, когда действие покупает несколько, как это делает атака: выбранное первым, оно тратит бюджет и оставляет остальные удары в запасе; выбранное при ударах в запасе, оно стоит одного из них. Эталонный набор 5e так проводит захваты и толчки.
- **В меню** у состязания своя группа, и оно показывает шанс победы. Противник под управлением Engine оценивает его, как и все остальное, но умеренно: захват или толчок что-то подготавливает, а освобождение ценнее всего, но только пока персонаж удерживается. Game Master, играющий противником, выбирает его из того же меню.
- Проверки противника, которого придумывает Game Master, ограничиваются его ступенью, как и его шанс попадания.

Состязания требуют Capability API 1.43 для набора в составе пакета.

### Окна: приостановка боя

Некоторые моменты принадлежат не действующему сейчас участнику, а другому. Engine оставляет бой открытым для его решения вместо решения за него; такая пауза – окно.

Его открывают шесть ситуаций; две уже следуют из ваших объявлений:

- **Кто-то отходит.** Перемещение, выходящее из досягаемости способного ударить врага, останавливается на этом шаге и спрашивает его. См. Удары по уходящим выше.
- **Между ходами.** После конца хода, до начала следующего, каждого противника с `signaturePoints`, которому доступна оплата собственного действия `signature`, спрашивают о покупке. Это единственный момент покупки: особого действия нет ни в чьем меню хода, включая собственное.
- **Кто-то что-то использует.** До разрешения спрашивают всех на ДРУГОЙ стороне, у кого есть запись, ожидающая этого момента, на кого бы ни было направлено действие, если эта запись достает до использующего. Стандартное действие и состязание такого момента не открывают.
- **На кого-то направлено действие.** До разрешения спрашивают всех на ДРУГОЙ стороне, на кого оно направлено и у кого есть запись, ожидающая такого момента. Лечащий друг не является угрозой, требующей ответа, поэтому действие друга не открывает окно.
- **Бросок атаки попадает в кого-то.** До урона спрашивают того, в кого он попал, если у него есть запись, ожидающая этого момента. То, что он выберет, учитывается для этой атаки: см. Момент после попадания ниже.
- **Кому-то причинили урон.** После разрешения спрашивают всех пострадавших с записью, ожидающей ЭТОГО момента, независимо от виновника. Полученный урон – факт о вас; запись, направленная обратно на виновника, все равно не может быть направлена на друга.

Последние четыре ситуации запись каталога или собственное действие существа запрашивает, называя ожидаемый момент. Когда одно действие открывает и `used`, и `aimed`, сначала спрашивают об использовании; если никто его не отменит, затем спрашивают тех, на кого оно направлено, и действие разрешается, когда ответят и те и другие. О попадании спрашивают по мере того, как попадает каждый бросок действия, а об уроне – когда все действие завершено.

Что делает окно независимо от причины открытия:

- **Пока оно открыто, ничто другое не движется.** Ни действующий участник, ни конец его хода, ни другое окно. Бой ждет.
- **Спрашивает по одному**, в порядке ходов, каждого один раз. Пропуск всегда допустим и бесплатен. Участник без доступных вариантов пропускается без вопроса.
- **Продолжается ровно с места задержки.** Перемещение проходит оставшиеся клетки, оплачивая каждую реально пройденную.
- **Отвечает тот, кто играет участником.** Окно вашего участника отряда принадлежит вам: вариант и соседнее Pass в меню; за противника отвечает управляющий им, а за босса Game Master – Game Master, с пропуском момента как одним из ответов.
- **Сохраняется вместе с боем.** Игра, закрытая посреди движения, возвращается с теми же ожидающими ответа участниками и оставшимися клетками.

Для первых двух ничего дополнительно не объявляется: набор правил с `opportunity.budget` получает первое, бестиарий с `signaturePoints` – второе, а набор без обоих никогда их не видит.

**Указать, какого момента ждет запись.** Запишите `mechanics.reaction` объектом вместо `true`:

```json
"reaction": { "on": "aimed", "at": "source", "cancels": true }
```

- `on` – `used`, `aimed`, `hit` или `harmed`; именно оно помещает запись в меню окна. Engine следит только за этими четырьмя моментами. Запись с прежним `"reaction": true` сообщает лишь, что не выполняется в ход; этого недостаточно для предложения где-либо, поэтому ее нет ни в одном меню.
- `at` – `source` (по умолчанию) или `chosen`. `source` направляет действие на вызвавшего момент и подставляет цель без запроса выбора; `chosen` сохраняет собственные цели записи и спрашивает.
- `cancels` полностью останавливает событие, которое удерживало окно. Задать его может только запись `used` или `aimed`: уже случившееся отменить нельзя, а попадание уже брошено.
- `against` сужает то, на что отвечает запись, до используемого из определенных каталогов: `"against": { "catalogs": ["spells"] }` отвечает на заклинание и ни на что другое. Действие без записи за ним (оружие в списке, собственное действие существа) не происходит ни из какого каталога, поэтому никогда не открывает момент для записи, называющей каталоги. Без `against` запись отвечает на что угодно.

Задайте также `budget`, иначе тратится бюджет списка по умолчанию. Реакция почти всегда расходует собственный бюджет, который не дает вместить несколько в один ход.

**Цена тратится до того, как кого-либо спросят.** Отмененное действие не происходит, но уже куплено: бюджет и запасы потрачены. Если ваша система возвращает их, выразить это пока нельзя.

Контрмера записывается так, и на поле она отвечает только тому, кто находится в пределах ее собственного `range`:

```json
"mechanics": {
  "kind": "utility",
  "range": 8,
  "free": true,
  "cost": [{ "pool": "luck", "amount": 1 }],
  "reaction": { "on": "used", "cancels": true, "against": { "catalogs": ["knacks"] } }
}
```

**Момент после попадания.** Запись на `hit` – способ выразить Shield, Parry и Uncanny Dodge. Атака удерживается после броска, и того, в кого она попала, спрашивают до нанесения урона. То, что он выберет, учитывается для этой атаки: ее бросок не делается заново, а проверяется заново против его защиты в ее нынешнем виде, поэтому состояние, прибавляющее к защите, может превратить попадание в промах, а натуральная грань, которая всегда попадает, по-прежнему попадает. Состояние, длящееся одну атаку (`endsAfter: "attacked"`), наложенное в ответ, покрывает эту атаку, включая ее урон, и расходуется ею – так выражается "уполовинить урон этой атаки": `resist-all` на одну атаку.

```json
"mechanics": {
  "kind": "buff",
  "targets": "self",
  "budget": "reaction",
  "reaction": { "on": "hit" },
  "applies": [{ "condition": "shielded", "duration": { "rounds": 1, "at": "turn-start" } }]
}
```

Атака продолжается ровно с места задержки: остальные ее цели и, для действия существа, составленного из других действий, остальные его части. Каждый бросок, попавший в того, у кого есть такой ответ, удерживается по очереди, а бой, сохраненный при открытом окне, возвращается в том же виде. Атака, совершенная внутри окна (удар по уходящему, особое действие, ответ), никогда не удерживается, потому что ничто открытое внутри окна не открывает другое. При открытии окна журнал показывает бросок и то, против чего он сделан, а если ответ изменил защиту – промахивается ли теперь атака. Противники под управлением Engine принимают защиту, только если она превращает попадание в промах.

Пакету, именующему момент, нужен Capability API 1.33, а пакету с `used` или `against` – 1.44. Пакету, ожидающему `hit`, нужен 1.46.

### Пока нет

Прямо, поскольку набор правил не должен обещать того, чего Engine не делает:

- **За пределами простого поля**: нет укрытия на три четверти или полного укрытия, высоты, полета над препятствиями, протискивания, верховой езды, скрытности или внезапности, и никого ничто не перемещает, кроме собственного хода и толчка в состязании. Никто не тащит удерживаемое существо.
- **Состязание простое.** У него нет ограничений по размеру, и оно не открывает окна (никто не может на него ответить).
- **Запись может ждать только четыре момента**, `used`, `aimed`, `hit` и `harmed` (см. Окна выше). Engine замечает их от имени записи; два остальных окна, отход и пауза между ходами, открывает сам бой, и запись не может их запросить. Нет момента броска спасброска, смерти, начала хода или падения чего-либо.
- **Контрмера полностью останавливает то, на что отвечает.** Она не может отличить одну запись каталога от другой, и нет проверки, которая остановила бы что-то сильнее ее самой.
- **Цепочек нет.** Бой хранит одно окно вместо стека, поэтому ничто внутри окна не открывает следующее: контрмеру нельзя контрить, урон реакции не вызывает новый момент, а атака, совершенная внутри окна, не удерживается при попадании.
- **Попадание – только бросок атаки.** То, что приходится без него (дротики, которые просто попадают, область, от которой все спасаются), не открывает момент `hit`, а ответ не может отличить взмах от выстрела, поэтому Parry, который правила ограничивают мечами, парирует и стрелы.
- **Урон меняется уполовиниванием, а не на величину.** Ответ может сделать вред одной атаки вдвое меньше (`resist-all` на эту атаку); он не может вычесть из него брошенное число.
- **Ничего не возвращается.** Цена отмененного действия остается потраченной.
- **То, что меняет состояние, – закрытый список.** Защита, броски атаки, спасброски, проверки состязаний и скорость (то же для уровня и действия предмета в бою), и ничего больше: нет бонуса к урону, наносимому владельцем, и нет уровня, который снижает максимум персонажа или выводит его из боя.
- **У существа, записанного обычными числами, нет шкалы ран.** В наборе правил со здоровьем-шкалой такое существо все еще теряет очки; дайте ему `sheet`, чтобы удары отмечали ячейки после применения его `resist`, `vulnerable` и `immune`.
- **Дополнительный эффект срабатывает сам.** У `on` одно значение, `hit`, поэтому его получает первое подходящее попадание периода; момента с вопросом, потратить ли его, нет.
- **Число, которое сдвигают атаки, простое.** Тратящий удар бросает это число и ничего больше, поэтому никакое оружие его не меняет, включая его `floor` (прочная цель поглощает забирающий удар, а ее твердость останавливает тратящий, но больше ничто не уменьшает ни тот, ни другой); срыв снимается после фиксированного числа ходов, насколько бы глубоким он ни был; а атака, совершенная в окне (удар по уходящему, реакция, особое действие), совершается в первом стиле.
- **Придуманный противник ничего не поглощает и не имеет твердости.** Существо, которое Game Master придумывает для одного боя, ограничено вашей шкалой угрозы, которая ничего не говорит о поглощении или твердости, поэтому у него нет ни того ни другого.

## Слои: варианты вашего набора правил

Слой – именованный вариант набора правил, который игрок включает при создании игры: мало магии, суровая зима, более жесткая сложность. Слои живут в файле набора правил в необязательном массиве `layers`, поэтому путешествуют с ним и никогда не пропадают из использовавшей их игры. Мастер настройки показывает их переключателями под набором правил; выбор закреплен на весь срок игры, как и сам набор.

```json
"layers": [
  {
    "id": "hard_winter",
    "label": "Hard winter",
    "summary": "Cold, hunger and short days. Everything is harder.",
    "conflicts": ["mud_season"],
    "gm": {
      "guidance": "Hard winter is on. Let a failed check cost warmth, food or daylight as well as progress.",
      "worldGuidance": "Hard winter is on. Build a world of closed roads, thin stores and rationed settlements."
    },
    "fields": [{ "id": "calling", "removeValues": ["Sailor"], "default": "Hauler" }],
    "difficultyLadder": [{ "label": "Easy", "dc": 7 }],
    "catalogs": [{ "id": "knacks", "hide": { "filter": "grit", "above": 0 } }]
  },
  {
    "id": "mud_season",
    "label": "Mud season",
    "summary": "Thaw, flooded roads and slow going."
  }
]
```

**Что может слой.** Список закрыт; каждый эффект что-то сужает либо добавляет текст:

- `gm.guidance` добавляется к `gm.checkGuidance` после вашего текста и текстов предыдущих слоев. `gm.worldGuidance` аналогично добавляется к `gm.worldGuidance`.
- `fields` убирает значения из поля **enum**. `removeValues` именует уже имеющиеся значения; хотя бы одно должно сохраниться, и если `default` поля удаляется, слой вместо него именует сохраняющийся `default`.
- `difficultyLadder` заменяет вашу шкалу другой в форме вашего вида разрешения: `{label, dc}` для `dice-sum`, `{label, successes, target?}` для `dice-pool`. Проходит ровно те же проверки, что ваша шкала. Если ее объявляют несколько активных слоев, побеждает последний.
- `catalogs` скрывает записи из окна выбора редактора листа. Каждое правило именует один из объявленных `filters` каталога и ровно одно сравнение: `above` или `below` для фильтра `number`, `equals` или `notIn` для `text` или `tags`. Запись, вообще не задающая этот фильтр, никогда не скрывается.
- `currencies` убирает монеты: `removeUnits` называет отдельные монеты, а `removeFamilies` – целые семейства. Самая мелкая монета семейства уходит только вместе с семейством, поэтому каждое оставшееся семейство по-прежнему может платить и давать сдачу. Пока слой включен, никто не зарабатывает, не платит, не выбирает и не получает в добыче убранную монету, а строка кошелька ее опускает. Цена, названная в ней, выражается в самой крупной оставшейся монете, которая покрывает ее ровно, при той же стоимости: долгая ночь в Gravewatch убирает crown, поэтому караульный пистолет за 3 crowns стоит 15 shillings. Предмет, чье семейство убрано целиком, не имеет цены.

**Чего слой не может.** Он не добавляет значение перечисления, поле, навык, запас или отдых, не меняет вид разрешения, текущее состояние или боевые числа, не добавляет вызов модели. Значение, _добавленное_ слоем, было бы неизвестно остальным читателям листа, поэтому значения могут только убираться. Все вне списка – изменение самого набора правил или второй набор.

**Конфликты.** `conflicts` именует слои, которые нельзя включать вместе. Достаточно указать одну сторону пары. Мастер настройки блокирует другой переключатель; если сохраненный выбор все же содержит оба, объявленный **позже** отбрасывается, поэтому те же два выбора всегда дают те же правила.

**Лист, уже хранящий удаленное значение, сохраняет его.** Ничто не переписывает персонажа. Редактор просто перестает предлагать значение; персонаж, уже имевший его, показывает его как есть. Выключите слой в новой игре – значение снова предлагается. То же со скрытой записью каталога: она отсутствует в окне выбора, но уже выбранная игроком строка остается в листе. Монеты, которые убирает слой и которые у кого-то уже есть, остаются в его сумке.

**Ограничения.** 12 слоев на набор правил и 4000 символов указаний на слой, считая обе строки вместе. Пакетный набор с `layers` или базовым `gm.worldGuidance` требует Capability API 1.25, а набор, чьи слои убирают монеты, – 1.64. Импортируемый набор проверяет читающий его Engine, поэтому ему ничего такого не нужно.

**Слои другого автора** (слой малой магии для чужого набора правил, поставляемый своим файлом) – будущее дополнение. Сегодня слой поставляется внутри набора, которому принадлежит.

## Как опробовать набор правил

Наборы правил сообщества используют тот же переключатель, что импортированные агенты. Откройте **Settings** (настройки) > **Advanced** (дополнительно) > **Danger Zone** (опасная зона) и убедитесь, что включено **Allow custom Agent imports** (разрешить импорт пользовательских агентов). Для импорта также нужен доступ через localhost или настроенный **Admin Access** (доступ администратора).

1. Откройте панель **Agents** и выберите **Import agents** (импортировать агентов; значок загрузки в ряду кнопок вверху панели).
2. Выберите **Game Mode ruleset** (набор правил Game Mode) и свой файл JSON.
3. Прочитайте обзор: имя, версия, лицензия, покрываемые возможности и текст Game Master. Выберите **Import** (импортировать).

Набор появится в разделе **Rules** (правила) панели и в выборе **Rules** мастера настройки новых игр. Импорт из файла получает имя `local/<your id>`, поэтому его нельзя спутать с официальным или чужим набором.

### Изменение уже импортированного набора правил

Импортированная версия никогда не переписывается. Если изменить файл и снова импортировать с тем же `version`, импорт отклоняется с просьбой поднять номер. Это намеренно: игра связана с точной версией создания, поэтому идущая кампания никогда не проснется с другой математикой.

Цикл разработки: отредактировать, поднять `version`, импортировать, начать новую игру. Старые версии остаются рядом с новой, пока вы не удалите набор из **Rules**. Удаление набора, который еще использует игра, заставляет ее сообщать об отсутствии правил до повторного импорта.

При изменении формы листа (добавлении, удалении или переименовании) поднимите также `sheet.version`. Существующие листы читаются терпимо: неизвестные новому листу значения сохраняются, отсутствующие получают значения по умолчанию.

## Как поделиться набором правил

**Файлом.** Отправьте JSON другу; он импортирует его так же, как вы.

**Из репозитория GitHub.** Если работа хранится в публичном репозитории GitHub, поместите каждый набор в папку `rulesets` в корне, по одному файлу на набор:

```text
your-repository/
  agents.json        (optional, only if you also share agents)
  rulesets/
    ember-roads.json
    another-system.json
```

Пользователь один раз добавляет репозиторий через список пользовательских репозиториев агентов, просматривает содержимое и позже синхронизирует новые версии. Этот список – расширенная возможность, которую оператор сервера включает через `ENABLE_CUSTOM_AGENT_REPOS=true`. Наборы из репозитория записываются под именем владельца, например `alice/ember-roads`, поэтому два автора могут публиковать набор `v20` без конфликта.

Есть два ограничения. В репозитории может быть не более 32 файлов JSON непосредственно в `rulesets`; репозиторий с большим числом отклоняется. Аккаунт `local` не может публиковать наборы, поскольку `local/` зарезервирован для импорта из файла.

**В официальном каталоге.** Широко используемую систему с ясной лицензией можно предложить всем через **Download Agents** (загрузить агентов). Для этого нужен pull request в репозиторий [Marinara-Agents](https://github.com/Pasta-Devs/Marinara-Agents). Пример структуры – пакет `ruleset-5e-2014` там.

## Лицензирование

Публикуйте только текст правил, которым вправе делиться. Многие системы выпускают справочный документ по открытой лицензии; копировать можно именно из него. Поместите id лицензии и требуемый ею текст атрибуции в `license`. Не копируйте текст из книг правил без открытой лицензии. Набору в основном нужны названия и числа, а текст Game Master следует писать своими словами.

## Устранение неполадок

- **Импорт сообщает, что имя не существует.** Что-то в файле ссылается на необъявленный id, например навык именует удаленную характеристику. Сообщение дает путь к строке.
- **Импорт сообщает, что версия уже установлена с другим содержимым.** Поднимите `version` и импортируйте снова.
- **Набора нет в мастере настройки.** Проверьте **Allow custom Agent imports**. Пока он выключен, импортированные наборы недоступны новым играм. Уже использующие их игры продолжают работать.
- **Игра сообщает об отсутствии набора.** Точная версия, на которой создана игра, не установлена. Импортируйте эту версию файла снова.
